# 临时数组索引

函数可以产生 Array 量，再对它索引。此时可以理解为先把整个 Array 放入匿名盒子，
然后沿普通数组规则找到元素。不会因此给所有普通量开放 `@`。

```xe-core
fn make() -> Array[i32,2] { [10,20] }

fn read(pointer: i32@) -> i32 { pointer# }

fn main() -> Unit {
    let first: i32 = make()⟦0⟧;
    let second: i32 = read(make()⟦1⟧@);
    println("{} {}", first, second);
}
```

输出 `10 20`。普通声明初始化或调用语句中，匿名来源存活到包含它的完整表达式结束。
第二次调用的数组在 read 执行期间仍然存在；完成 second 初始化后才结束其存活。
嵌套实参块里其他语句的分号不会提前清理外层匿名来源。

```xe-invalid
let pointer: i32@ = make()⟦0⟧@;
// 声明结束后匿名数组已经失效，pointer 盒子的存活不能延长其目标。
```

当前只支持普通声明和调用中的只读 Copy 索引，以及调用期间的只读元素地址。
临时数组可写访问、临时范围视图、条件或块尾等更宽寿命组合当前不可用。
需要清晰的来源存活范围时，先保存完整数组，再索引：

```xe-fragment
let values: Array[i32,2] = make();
let pointer: i32@ = values⟦0⟧@;
```

复制临时数组中保存的外部指针量，与取得临时元素盒子的地址是不同操作。
前者依赖实际外部目标，后者依赖该匿名数组；不能只因类型中都出现 @ 就合并两种寿命。
