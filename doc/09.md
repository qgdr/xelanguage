# 包、模块与导入

模块系统吸收 Rust 的静态可见性和 Python 的“一文件一模块”直觉，但避免重复声明文件名。

## 项目结构

最小可执行包：

```text
hello/
├── xe.toml
├── xe.lock          # 工具生成并提交版本控制
├── src/
│   ├── main.xe      # 可执行入口
│   ├── lexer.xe     # crate::lexer
│   ├── parser.xe    # crate::parser
│   └── parser/
│       └── expr.xe  # crate::parser::expr
└── tests/
    └── smoke.xe
```

`src/main.xe` 是默认可执行入口，`src/lib.xe` 是库入口。一个包可以同时提供库和程序；额外
程序放在 `src/bin/name.xe`。

模块路径由 `src/` 下的文件路径唯一推导，源码中不再写 `module ...;`，也不需要写
`mod child;`。编译器从入口和 `use` 依赖递归加载需要的文件。不能同时存在会映射到同一
模块路径的文件。

这种方案保留了 Python “文件就是模块”的简单性，同时采用 Rust 风格的静态模块树、私有
默认和明确路径。Rust 将 crate 作为编译单元并组织模块树；Python 也把包含定义的文件视为
模块。Xe 把两者简化成一条固定文件映射规则。

## 导入

```xe
use crate::lexer::Lexer;
use crate::diagnostic::{Diagnostic, Severity};
use crate::syntax::Token as SyntaxToken;
use json::Value; // 来自依赖包 json
```

路径规则：

- `crate::`：当前包的模块根；
- `self::`：当前模块；
- `super::`：父模块；
- 首段为依赖包名时，从 `xe.toml` 的依赖中解析；
- `as` 创建本地别名。

首版禁止 `use path::*`，因为它让读者和工具难以判断名称来源。同一包内允许模块互相引用：
编译器先加载所有可达文件并收集顶层声明，再解析函数体和实现，因此不会按文件顺序决定
名称是否可见。初始化仍然没有次序问题，因为模块顶层不能执行普通语句。

包之间的依赖图必须无环；两个包共享的定义应移动到第三个基础包。

## 可见性

声明默认只在当前模块及其子模块可见。`pub` 使名称成为包的公开接口：

```xe
pub struct Lexer[region r] {
    source: str[r],
    position: usize,
}

pub fn tokenize(source: str) -> Vec[Token] {
    // ...
}
```

公开函数、公开结构字段和公开常量必须显式写完整类型。模块顶层不允许执行普通语句，因此
导入模块不会产生隐藏副作用。

## 包配置

```toml
[package]
name = "hello"
version = "0.1.0"
edition = "2027"

[compiler]
check_borrows = true # 推荐项目及官方自举使用；未配置则默认关闭

[dependencies]
json = "1.2"
local_util = { path = "../local_util" }
```

`xe.toml` 是用户编辑的包说明，`xe.lock` 是工具生成的精确依赖锁。库构建必须遵循锁文件，
确保人类、CI 与 AI 工具得到相同依赖图。

第一版只需支持注册表版本和本地路径依赖；Git 依赖可以之后增加。
