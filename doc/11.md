# 可失败结果与错误传播

## 类型问号与值问号：构造和消解

两个 ? 是不同运算符，入口上下文决定含义：

- 类型位置 T? / T?[E]：由负载类型构造结果类型；
- 值位置 result ? ...：选择结果分支，把负载送给对应处理函数；
- 值位置 result?[return]：成功提取负载，失败提前返回。
- 值位置 result?[panic]：成功提取负载，失败报告并终止进程。

可以把类型 ? 和值 ? 理解成概念上的正变换与反变换：前者组织可能性，后者拆解可能性。
它们不是严格数学逆函数：分流可以返回任意分支结果类型，可能丢失标签或改变负载。
源代码统一保留 ASCII ?，不增加反向问号字符。编辑器可以分别给类型修饰符与值操作符
着色，辅助阅读，但颜色不参与语法或语义，无色终端中的代码也必须含义明确。

## 结果类型

T? 是 T?[None] 的简写；T?[E] 的 E 是具体错误类型。不引入 Option / Result 两套类型。
概念展开如下，用户无需声明两个同名枚举：

```xe
enum[T] Maybe {
    Yes[T],
    None,
}
enum[T, E] Maybe {
    Yes[T],
    No[E],
}
```

类型位置的 None 是无错误负载标记，不是 Unit。显式构造统一写 Maybe::Yes[value]、
Maybe::None、Maybe::No[error]，参数由预期类型推导。

## 返回位置的简写

函数声明返回 T? 或 T?[E] 时，直接 return 操作数和函数尾表达式具有预期结果类型；
其中的 if / 分支结果继续接受这一预期类型：

```xe
fn positive(value: i32) -> i32? {
    if value > 0 { value } else { None }
}

fn divide(left: i32, right: i32) -> i32?[str] {
    if right == 0 {
        Maybe::No["division by zero"]
    } else {
        left / right
    }
}
```

- 已经是完整目标结果类型的值直接返回，不再次包装。
- 类型恰好为成功负载 T 的值包装为 Maybe::Yes[value]，按值传递。
- None 只在预期为 T? / T?[None] 时表示 Maybe::None；不能为 T?[E] 制造假错误。
  None 是上下文保留标记，不能声明为局部名称。
- 错误值不自动包装，始终明确写 Maybe::No[error]。即使 T 和 E 相同，规则仍唯一。
- 只省略最外一层包装；嵌套结果的缺失层次须显式构造。有歧义时明确写 Yes / None。
- 简写不扩展到普通赋值、参数或枚举负载位置，不根据推导偷偷选择成功或失败。

所以 return value; 简写成功返回，错误写 return Maybe::No[error];。
资源成功返回移动 value。生成代码时构造 Yes，不修改 JSON 中的源码 AST，不需要运行时转换。

## 数字输出通道是分支管道

Maybe 的 ? 必须处理一个 1> 和一个 2>，顺序可交换。成功输入为 T，失败输入为 E；
T? 的失败分支没有参数。右侧只接可调用目标或管道参数绑定，不直接接结果表达式。

```xe
File::open("hello.txt")?
    1> opened
    2> failed;

let fallback: i32 = positive(-1)?
    1> value: i32 -> value
    2> _ -> 0;
```

1> opened 调用 opened(file)，不是返回函数；函数类型变量也可以作为调用目标。
返回函数本身明确写 1> _ -> opened。返回闭包时，正文内必须使用 fn 字面量，见第 15 章。
1> _、2> 0、1> foo(_) 和 2> -> 0 均非法；不存在通道匿名负载占位符。

参数绑定写 name: Type -> expression，类型可省略，_ -> expression 表示忽略输入。
T? 的无负载失败只能调用零参数函数、零参数 fn 字面量，或使用 _ -> expression；
不能声明 error -> ...。没有人为添加 Unit 参数。

```xe
let size: usize = File::open("hello.txt")?
    1> file: File -> file.size()
    2> error: io::Error -> {
        eprintln("{}", error@);
        0
    };
```

只有选中的处理函数被求值并执行，两个分支的调用结果必须类型兼容。
绑定正文延伸到本层下一个通道、外层分隔符或块结束；嵌套分流用块或括号。
推荐多行分流绑定先放入局部变量，再参与其他算术或管道；不能凭换行判断正文结束。

1> 和 2> 在语法上由整数及 > 组成，仅在期待通道头时识别，不是全局保留的词法单元。
普通比较 1>x 和 1 > x 含义相同；正文解析不能用字符串扫描提前截断合法比较。
常规格式化仍输出 1>、2>。一般整数模式写 1 :> handler，不与通道混用。

## 通道的借用与所有权

资源结果按值分流被消耗，负载移动给处理函数；Copy 结果复制。被忽略的资源自动 drop。
只读指针分流写 result ?[@] 1> handler 2> handler，普通负载 T/E 都以指针传入，
包括 Copy 标量和 str/Slice 视图描述符；读取值需写 value#。多负载规则与第 06 章相同。
可写匹配 ?[@[mut]] 必须来自可写存储。非拥有指针不能用按值分流移走所指结果。

## 使用 ?[return] 传播错误

```xe
fn read_text(path: str) -> String?[io::Error] {
    let file: File << File::open(path)?[return];
    let text: String << file.read_to_string()?[return];
    text
}
```

成功取得负载；失败从当前函数提前返回。它是编译器内置控制流操作，不调用一个会把
return 限制在自身函数内的闭包。展开如下：

```xe
fn read_text(path: str) -> String?[io::Error] {
    File::open(path)?
        1> file -> {
            file.read_to_string()?
                1> text -> text
                2> error -> { return Maybe::No[error]; }
        }
        2> error -> { return Maybe::No[error]; }
}
```

管道参数绑定不是独立函数作用域：其中 return / break / continue 仍作用于所在外层函数
或循环；fn 字面量则建立新函数作用域，其 return 只退出该匿名函数。
T? 的缺失分支返回 None。当前函数必须返回兼容结果；首版要求错误类型相同。
转换错误明确写 2> error -> { return Maybe::No[AppError::Io[error]]; }。
let file: File << File::open(path)?; 仍非法；?[return] 不与借用匹配组合，也无隐式 panic / ignore。

## 明确选择终止：?[panic]

```xe
let byte: u8 = u8::try_from(number)?[panic];
let text: String << File::open(path)?[panic].read_to_string()?[panic];
```

成功负载遵守相同复制/移动规则：u8 用 `=`，String 用 `<<`。
失败时输出错误并以非零状态退出；当前运行库直接终止进程，不承诺栈展开或执行 Drop。
它适合明确不可恢复的入口错误，普通业务错误优先通过 1>/2> 或 ?[return] 处理。
?[panic] 与 ?[return] 都是后置操作，不引入函数作用域，也不与借用匹配附件组合。

## 与具名分支管道的关系

```xe
File::open(path) ? {
    Maybe::Yes :> opened,
    Maybe::No :> failed,
};
```

Maybe::Yes / Maybe::No 选择变体并传递负载；Maybe::None 调用无参数处理函数。
数字通道仅是两个专用分支头，不能扩展 3>，且不能与 :> 形式在同一个匹配中混用。
