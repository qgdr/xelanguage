# 可失败结果与错误传播

## 结果类型

`T?[E]` 表示一次计算产生正常值 `T` 或错误 `E`：

```xe
fn open(path: str) -> File?[io::Error];
```

`T?` 是 `T?[None]` 的简写。两者都属于 `Maybe` 类型族，没有 `Option` / `Result` 两套类型。
概念上的展开如下；这是解释布局和分支的示意，用户无需声明这两个同名枚举：

```xe
// T? 或 T?[None]
enum Maybe[T] {
    Yes[T],
    None,
}

// T?[E]，其中 E 不是 None
enum Maybe[T, E] {
    Yes[T],
    No[E],
}
```

`None` 在类型位置是无错误负载标记，不是 `Unit` 类型或一个可传递的运行时值。两个形式的
第二分支都占用判别标签；`T?` 的 `None` 分支不携带值。构造时分别写
`Maybe::Yes[value]`、`Maybe::None` 和 `Maybe::No[error]`。`Maybe` 的类型参数从预期类型或
负载推导；无法推导时明确标注变量或函数返回类型。变体负载使用 `[]`，函数和方法调用
使用 `()`；分组和元组仍使用 `()`。`T?[E]` 的 `E` 必须是具体错误类型；无错误负载时
使用 `T?`。

## 显式输出通道

无修饰的后缀 `?` 必须紧跟两个输出通道：

- `1>`：成功或存在值，负载类型是 `T`；
- `2>`：`T?[E]` 的负载是 `E`；`T?` 的 `None` 分支没有负载。

```xe
fn opened(file: File) {
    // 使用文件
}

fn failed(error: io::Error) {
    eprintln("open failed: {}", error@);
}

File::open("hello.txt")?
    1> opened
    2> failed;
```

没有 `->` 的目标必须是能够接收该通道负载的函数。上例根据结果调用 `opened(file)` 或
`failed(error)`。

`T?` 的 `2>` 没有负载，分支直接从 `->` 开始，或者指向一个零参数函数：

```xe
let index: usize = find_index(name)?
    1> value -> value
    2> -> 0;
```

这里没有为了让两条通道外形相同而制造一个假的错误值。

需要在分支中继续计算时，写成 `binding -> expression`：

```xe
let size: usize = File::open("hello.txt")?
    1> file -> file.size()
    2> error -> {
        eprintln("{}", error@);
        0
    };
```

绑定类型通常可以推导，也可以显式写成 `file: File -> ...`。所有能够继续执行的分支必须
产生兼容类型；返回 `Never` 的 `panic` 可以与任何正常分支组合。

两个通道都必须恰好处理一次。不能省略错误通道，也不使用容易与 Shell 追加重定向混淆的
`1>>` / `2>>`。

## 使用 ?[return] 传播错误

很多函数无法在当前层修复错误，只能交给调用者。例如：

```xe
fn read_text(path: str) -> String?[io::Error] {
    let file: File << File::open(path)?[return];
    let text: String << file.read_to_string()?[return];

    Maybe::Yes[text]
}
```

`?[return]` 的准确展开是：

```xe
fn read_text(path: str) -> String?[io::Error] {
    File::open(path)?
        1> file -> {
            file.read_to_string()?
                1> text -> Maybe::Yes[text]
                2> error -> { return Maybe::No[error]; }
        }
        2> error -> { return Maybe::No[error]; }
}
```

因此：

```xe
let file: File << File::open(path)?;
```

仍然不合法，因为无修饰 `?` 没有说明错误去向。只有：

```xe
let file: File << File::open(path)?[return];
```

才明确要求失败时从当前函数返回。

对 `T?` 使用 `?[return]` 时，缺失分支从当前函数返回 `Maybe::None`；当前函数也必须返回
兼容的可选类型。

`?[return]` 只能出现在返回兼容 `Maybe` 类型的函数中。带错误负载时，首版要求错误类型
完全相同；需要转换错误时写出两个通道：

```xe
let text: String << fs::read(path)?
    1> value -> value
    2> error -> { return Maybe::No[AppError::Io[error]]; };
```

不提供 `?[panic]`、`?[ignore]` 等隐藏失败的快捷方式。需要崩溃时写 `.expect(message)`，需要
忽略时通过显式通道说明原因。

## 与 match 的关系

分流可以降低成普通穷尽匹配：

```xe
match File::open(path) {
    Maybe::Yes[file] -> opened(file),
    Maybe::No[error] -> failed(error),
};
```

数字通道只用于 `Maybe` 的两个分支。普通枚举继续使用具名变体，第一版不扩展 `3>` 等通道。
