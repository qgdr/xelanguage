# 第一版 C 后端：从源码到可执行程序

状态：已经可以生成并运行程序，覆盖具体函数、结构体、方法、管道和枚举匹配；
泛型按使用的具体类型实例化，不依赖运行时类型擦除。
它只依赖 Python 标准库和系统 C 编译器，不使用 LLVM；语法为 xe-bootstrap-0.9。
自举、完整标准库和全部冻结语法的运行支持仍未完成。

## 运行命令

在仓库根目录使用统一 uv 环境：

    make run
    make run SOURCE=tests/stage999/struct_methods.xe BACKEND_FLAGS=--check-safety
    make run SOURCE=tests/backend/enum_pipeline.xe BACKEND_FLAGS=--check-safety
    make run SOURCE=tests/backend/enum_resources.xe BACKEND_FLAGS=--check-safety
    make run SOURCE=tests/backend/generic_instances.xe
    make run SOURCE=tests/backend/tuples.xe
    make run SOURCE=tests/backend/type_aliases.xe
    make run SOURCE=tests/backend/readline.xe
    make build SOURCE=tests/stage999/struct_move.xe
    make emit-c SOURCE=tests/stage999/struct_move.xe
    make compiler-test
    make demo
    make audit

make run 的默认示例是 struct_move.xe，输出 1:hello。
make ast / check 的默认示例仍为 maybe_error.xe，该示例现在也能编译执行。
SOURCE 显式指定时所有命令使用同一个输入。

- emit-c 默认输出 target/c/<源文件名>.c。
- build/run 默认输出 target/debug/<源文件名去掉扩展名>。
- build/run 同时保留 <可执行文件路径>.c，方便查看生成代码。
- PROGRAM、C_OUTPUT 可以自定义；CC 可以指定 GCC/Clang 兼容的系统 C 编译器。
- 类型、所有权和写权限检查始终开启；指针风险给 warning，BACKEND_FLAGS=--check-safety 是兼容写法。

可直接运行 CLI：

    uv run --project . --frozen --offline python compiler/main.py tests/stage999/struct_methods.xe --run --check-safety
    uv run --project . --frozen --offline python compiler/main.py tests/stage999/struct_move.xe --emit-c -o -

构建成功退出 0，源码或后端能力诊断退出 1，I/O/系统编译器失败退出 2。
run 返回程序自己的退出状态；fn main() 返回 Unit 时正常退出 0，
fn main() -> i32 则把返回值交给系统。语义检查失败时不生成 C。
未支持的后端功能用 XE-BACKEND-0001 定位，不静默生成错误代码。

## 实现了什么

- 标量、str 视图、拥有 String、普通非拥有指针。
- tuple[...] 元组布局与资源清理、无损数值 as、str@ 视图描述符指针、用户类型显式 Copy。
- tuple 解包声明、已有目标赋值和通用 >>；右侧快照、资源替换/忽略与提前返回清理。
- 透明类型别名展开后的普通布局、构造、关联调用与函数值，不生成额外运行时包装。
- print/println 标准输出及 readline 标准输入；短名称与 std::io:: 路径同接口。
  输入区分行/空行/EOF/IO 错误，刷新提示、UTF-8 检查与含 NUL 的长度保存。
- 非泛型函数、递归和相互调用，参数和返回值。
- 非泛型结构体、空结构体、嵌套字段和按值返回；字段初始化按源码顺序求值。
- 关联函数，以及共享、可写、拥有 self 的普通方法；接收者按声明自动借用/解引用。
- 基本算术、布尔短路、比较链、块结果、if、while、右开整数范围 for。
- return/break/continue；作用域资源清理、条件移动、部分字段移动和延后初始化。
- Copy 标记和自定义 Drop；结构体先执行自己的 drop，再按字段声明顺序清理有效字段。
- println/print/eprintln 的 {}、{:p}；拥有参数确实转交，指针参数不释放所指资源。
- String::from、clone、len、as_str、push_str；str.len、data、byte_at。
- 非泛型枚举的无载荷/单载荷/多载荷构造，含嵌套枚举和资源载荷。
- 普通 |> 管道，具名非泛型函数目标及内联参数绑定；资源沿管道转交。
- 枚举、字面量及通配分支 :>；拥有、只读指针 ?[@] 和可写指针 ?[@[mut]] 匹配。
- Maybe 的 Yes/No/None 布局、成功返回简写、1>/2>、?[return]、?[panic]、expect。
- 整数 T::try_from 的有符号/无符号边界，失败返回 ConversionError，不截断。
- Array 布局、字面量、索引、自动 Drop、指针迭代；Slice/SliceMut 的右开范围切片、
  索引/迭代及 Copy 元素 copy_from。
- Range 值及整数右开/闭区间循环；最后端点后的 continue 不会导致整数溢出。
- File::open/read_to_string/size、自动 close、io::Error 格式化；读文本验证 UTF-8。
- 具名函数值、无捕获 fn、fn 类型参数/返回、分支选择与管道调用，降低为 C 函数指针。
- 泛型函数的显式/推导实例、泛型结构体与枚举布局、泛型 impl 方法和关联函数；
  同实例缓存复用，明确实例可作为函数值，资源字段/载荷仍自动清理。
- T@[mut] 降为 T@，不改变 C 指针表示，也不放宽只读指针写入检查。

整数加减乘及除零/有符号除法溢出会产生清晰的运行错误，避免直接继承 C 的有符号溢出
未定义行为。检查函数使用 GCC/Clang 的 checked arithmetic builtins。
这是 stage0 的保守运行策略，不表示全部数值转换/溢出契约已经冻结。
String 按 UTF-8 字节保存；str 长度和输出不依赖结尾零，包含 NUL 的字符串也能完整输出。
panic/运行错误终止进程，不进行栈展开，因而不承诺错误退出时析构。

## 维护时看哪些文件

- compiler/xe_ast/backend_c.py：类型侧表、C 类型、表达式降低、调用和资源清理。
- compiler/runtime/xe_runtime.h：字符串分配/释放、UTF-8 输出、格式化和数值检查。
- compiler/xe_ast/build.py：原子写 C、调用系统编译器、发布可执行文件。
- compiler/tests/test_backend.py：真正编译执行，验证输出、退出码和失败保护。
- compiler/tests/test_backend_branches.py：管道、载荷清理、指针匹配和分支退出路径。
- compiler/tests/test_backend_results.py：Maybe/转换/数组/切片/文件及异常边界。
- compiler/tests/test_backend_functions.py：函数值、匿名函数提升、嵌套签名和资源参数。
- compiler/tests/test_generic_backend.py / test_generic_integration.py：泛型实际编译执行、
  实例缓存、具体所有权检查、风险传播及清理边界。
- compiler/tests/test_tuple_backend.py / test_tuple_alias_integration.py：元组解包的求值顺序、
  资源清理与别名展开后的函数/构造/方法/泛型交互。
- stdlib/io/xe_io.h：stage0 标准 IO 的 C 实现；生成 C 内含必要代码，仍可独立构建。
- compiler/tests/test_stdlib_io.py：实际 stdin/stdout、EOF/错误/编码边界和内存清理。
- compiler/tests/test_calculator_project.py：真实解释器项目的输出与算术/递归边界。
- tests/backend/：控制流清理、部分移动与求值顺序的可读示例。

AnnotatedChecker 复用语义分析器，以节点身份记录类型；不向 AST JSON 偷加类型信息。
后端仍是类型侧表加结构化 C 降低，不是已经具备完整 HIR/MIR 的编译器。

Xe 的实参先从左到右求值，并及时保存快照，再调用 C 函数：
不能依赖 C 未规定的参数求值顺序。比较链每个操作数最多求值一次，
前面的比较为 false 时不再计算后面的操作数。

每个拥有存储位置有活跃标记。移动只清除标记，参数/块结果接收者获得自己的标记；
因此复制底层 C 结构体的位并不等于 Xe 允许复制资源。
部分字段移动只清对应字段标记。return/break/continue 显式执行退出作用域的清理。
资源表达式语句在语句结束时清理，而不是拖到块末尾。

声明顺序并不总等于初始化完成顺序。首版使用每作用域序号和每存储位置的初始化序号，
退出时优先清理最后完成初始化的值；字段内部仍按声明顺序清理。
这是一版简单、可验证的参考实现，清理选择是二次复杂度；
后续 MIR 可对普通静态情况生成直接清理序列，保留复杂路径所需标记。
调试信息目前指向生成 C，不宣称已提供完整 Xe 源码调试映射。

## 管道与枚举匹配如何运行

普通管道与分支管道共用 handle：具名函数目标调用该函数，内联参数绑定则建立局部作用域。
内联参数绑定中的 return 返回外层函数，break/continue 作用于外层循环，
退出时照常清理经过的作用域。无捕获 fn 提升为独立函数，return 只返回该函数；
有捕获闭包需要拥有环境布局，仍未接入后端。
_ -> expression 接收并清理被忽略的资源；不会因为忽略名称而跳过析构。

枚举的 C 表示包含标签和每种载荷的字段，只有当前标签对应的字段有效。
首版为便于阅读没有把载荷压进 union；后续优化布局不改变 Xe 所有权语义。
所有构造参数先从左到右求值，再组装枚举；后续参数提前返回时，先前参数仍会被清理。
清理枚举时先调用自定义 Drop（若有），再按声明顺序清理当前变体的载荷；
不读取或释放其他变体的字段。

拥有匹配只在选中分支转交活动载荷，借用匹配保存原对象地址，不复制对象到临时枚举。
所以分支拿到的 String@ / i64@ 指向原对象，不延长它的生命周期；可识别失效风险给 warning。
str 载荷本身是视图，借用匹配统一传递 str@ / str@[mut]，指向原对象的视图描述符。
匹配的公共结果先移到外层存储，随后才清理分支局部资源。
分支函数可接收多个载荷，无载荷变体对应零参数函数或 _ -> expression。

语义分析继续拒绝不穷尽的匹配、移动后使用、借用载荷的非法资源转送，
以及自定义 Drop 枚举的资源载荷抽取。组合/元组/过滤选择模式尚未实现。

## 失败保护

不使用 shell 拼接编译命令；C 编译器通过独立参数调用。
输出不能覆盖输入源码。生成失败保留旧 C 和旧可执行文件。
系统编译器失败时保留新 C 供检查，但不覆盖旧可执行文件；
成功后才原子替换可执行文件。目标名称冲突时请显式指定不同输出路径。

## 明确未实现

泛型 Copy/Drop 实现、编译期值参数、有捕获闭包、通用 Trait 分派、模块加载、
Vec/Map/Box、外部 ABI 与外部地址 unsafe 操作等还未接入这个后端。
切片当前要求右开范围表达式，不接受保存于变量的 Range 或闭区间；bytes/chars 尚未执行。
File::size 仅适用于可 seek 的普通文件，不能把所有输入流假装成有固定长度的文件。
File.read_to_string 从当前流位置读到结尾，会推进游标；共享接收者下的 IO 状态契约见第 20 章待讨论项。
as[checked]/as[wrap] 草案已撤回，不再作为待实现功能列出。
首版 const 只接受字面量及一元正负号，不能重复执行常量初始化函数来假装常量。
浮点余数暂不支持。

普通非泛型函数仍全部生成；泛型模板只为被使用的具体类型生成代码。
未用泛型模板仍需通过语法解析，不需要提前生成不能确定的 C 布局。
完整语言验收不能以“已有结构体示例能跑”代替。下一步是更通用的有类型 IR、
更完整的静态 Trait 能力，然后扩展模块、标准库和自举源码。完整审查和待讨论项见第 20 章。
