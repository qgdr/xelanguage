# 当前语法评审与实现验收

本章保留语法收敛时的评审与验收建议，不以语法评分代替测试。
其中阶段性实现描述不是候选版能力清单：当前范围见 [发布契约](../RELEASE.md) 与
[第 38 章](38.md)，资源/模式、静态 Trait、有限 C ABI 和位操作的后续补全见
[第 34](34.md)、[35](35.md)、[36](36.md)、[37](37.md) 章；
子集自举固定点已实现，完整语言自举仍未完成，见 [第 31 章](31.md)。

## 已收敛的含义

- : 在值声明中用于名称与类型，在 fn[T: Trait] 中用于类型参数能力约束；
  :: 是命名空间符号，:> 是完整的分支管道符号。
- [] 用于类型/负载/筛选/运算修饰/捕获附件，但每一种位置均有明确入口。
- () 用于函数调用、函数参数及值/类型分组；元组使用 tuple[...]，花括号不再承担元组含义。
- |> / 1> / 2> / :> 都调用处理函数；直接返回结果必须写参数绑定正文。
- x -> 正文只在管道处理位置合法，不产生函数值；fn 创建函数值并建立函数作用域。
- 匹配选择器不声明变量，参数类型注解不改变输入传递方式。
- 资源移动与非拥有指针访问分开；块退出确定性 drop，不依赖借用检查开关。
- 借用匹配的标量也传递指针，不根据 Copy 能力猜测参数表示。
- 1> / 2> 按语法位置识别，普通比较不因空格改变含义。
- 参数只表达输入类型和指针读写能力，不携带绑定可变性；局部可变存储使用 let[mut]。

这些规则足以构造编译器的 Token、AST、诊断、Arena/ID 数据结构、文件读写与控制流。
四种管道可降低到调用，匹配可降低到同一个穷尽分支节点，不要求自行实现复杂解析算法。
只读匹配、普通函数及直接参数绑定足以完成第一版自举，捕获闭包可以独立推进。

## 仍需承认的设计成本

1. 普通指针可以存在别名和悬垂风险，语言不宣称内存安全。编译器发现风险时 warning 并
   传播 unsafe；类型、写权限和资源所有权错误仍拒绝，unsafe 不增加权限或所有权。
2. -> 处理正文覆盖完整表达式，容易让后续 |> 看起来属于外层。命名函数、fn 块及括号
   必须用于明确连续步骤；格式化器不能仅靠换行营造不存在的边界。
3. str@ 现在合法，视图描述符与底层字节必须区分。借用匹配统一传递 T@ / T@[mut]，
   不再根据视图或 Copy 能力猜测负载传递方式。
4. 分支 :> 后可写参数绑定或可调用值，因此一个名字是否合法依赖名称解析与类型检查。
   这不是“调用或返回”的歧义：合法目标总被调用，非法目标报错，绝不返回原值。
5. 资源枚举按值匹配有析构复杂度。自定义 Drop 类型不能抽取资源负载；普通枚举的剩余
   资源及忽略参数必须恰好清理一次。
6. 有捕获闭包已支持具体环境和方法式调用：读/写环境保留自身，移出资源才消耗环境。
   不能把“签名相同”误写为“闭包类型相同”；动态共同类型仍暂缓，见第 15 章。
7. 模式选择和参数绑定分离，每次 ? 只处理一层；不支持递归变体选择器，需要显式内层匹配。
   这牺牲少量简写，换取负载来源和所有权明确。

当前结论：核心方向可实现，已有前端检查和部分 C 后端运行验收，但完整语言与自举尚未验证，
不能宣称达到 10 分或性能优于其他自举编译器。性能取决于后端、数据布局、分配和算法，
不是符号数量。

## 0.6 参数与符号边界审核

参数保持 name: Type，删除 name[mut] 后不再与 array[index] 产生视觉上的相似。
let[mut] 的附件紧跟声明关键字，不是索引；T@[mut] / value@[mut] 紧跟取地址符号，
只说明该指针的能力。参数的 T@[mut] 允许修改所指对象，不允许重绑参数。
需要局部修改时显式遮蔽参数：Copy 值用 let[mut] name = name;，资源用 <<，
因此不引入隐式复制或新的参数运算符。

仍需区分三类阅读成本：

- [] 在类型上下文是泛型/长度，在表达式上下文可能是枚举载荷或索引。
  前端保留 BracketApply，由名称解析和类型检查确定；未知名称必须报错，不能猜测大小写。
- `fn[T] name(...)` 是具名声明的泛型；`fn[captures](...)` 是匿名表达式的捕获。
  两者入口不同，不靠附件里的名称猜含义。参数的 [] 只出现在冒号后的类型或借用附件中。
- 当前只有一种检查策略，权限从 let[mut] / T@[mut] 明确读取。
  类型和值位置的 ? 是构造与消解，概念上对应正/反变换，不要求严格互为逆函数。

管道目标中的裸函数名始终表示调用；返回函数值必须放在参数绑定正文中。
处理参数绑定不是闭包，return/break/continue 属于外层；fn 则建立独立函数作用域。
这些边界可以清楚解析，不代表闭包、泛型、模块和全部保留模式已有完整后端支持。

## 验收顺序

1. 解析并格式化所有成功样例，检查格式化幂等性和 AST 不变。
2. 对比命名处理函数、直接参数绑定及 fn 的结果与副作用顺序。
3. 测试 1> / 2> 和 1>0、1 > 0、整数选择器同文件出现，确保无空格敏感性。
4. 同时测试拥有匹配、共享匹配、Copy 标量、嵌套指针及只读视图。
5. 检查未选分支不求值、穷尽性、不可达分支、多负载签名错误。
6. 检查块尾转移、return / break / continue / ?[return] 清理与自定义 Drop 限制。
7. 捕获闭包单独验收移动、未调用析构、调用后使用及借用逃逸。
8. 正确诊断旧写法；解析报错或崩溃不能当成所有权失败测试通过。
9. 完成自举固定点；独立验收 warning 传播，不把没有 warning 宣称为内存安全证明。
