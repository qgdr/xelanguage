# 绑定、复制与值传递

## let 与可变声明附件

`let` 创建不可重新赋值的绑定，`let[mut]` 明确允许重新赋值和取得可写指针。
当前始终验证这些规则：

```xe
let name: str = "Xe";

let[mut] count: usize = 0;
count = count + 1;
```

不可重新赋值不等于对象内部永远不可修改。是否能够修改对象内容由指针的读写权限决定，
与独占借用无关。

[mut] 在 let 上修饰绑定，在 @ 上修饰指针的可写能力；它不改变被绑定值的类型。
例如 let pointer: usize@[mut] = count@[mut]; 可以通过 pointer# 修改 count，
但不能给 pointer 本身重新赋值。移动资源不要求 let[mut]，仍由 << / >> 和参数规则决定。

类型、初始化、资源所有权和可变性始终检查；可识别的指针风险给 warning，旧检查旗标仅为兼容。

局部变量可以省略类型：

```xe
let answer = 42;
let[mut] index = 0;
```

同一作用域不能重复声明同名绑定。内层作用域允许暂时遮蔽外层名称，但 `xe lint` 默认提示，
因为大型程序中的意外遮蔽不利于阅读和自动修改。

模块级只读绑定也使用 `let`，公开时在前面加 `pub`，不另设常量声明关键字：

```xe
let LIMIT: usize = 100;
pub let VERSION: str = "0.1.0";
```

模块级绑定必须显式标注类型并用 `=` 初始化，不在导入模块时执行函数或创建资源。
当前实现只支持 Copy 字面量；Python 后端另支持字面量的一元正负号。
模块级 `let[mut]`、延后初始化、类型推导及资源存储暂未实现，不能把局部绑定能力
直接推广到模块顶层。可变状态和资源仍在函数内创建；模块值的可取址存储也尚未实现，
需要地址时先在函数内复制到局部变量，再使用 `@`。

旧版 `const NAME: Type = value;` 仅作为兼容拼写保留，文档和新代码统一使用 `let`。
AST 中沿用 `Constant` 节点名称表示编译期只读值，这是实现分类，不是新的源码关键字。

## 复制与传递

`=` 明确表示复制，只能用于实现了 `Copy` 的类型：

```xe
let first: i32 = 5;
let second: i32 = first;
// first 和 second 都可以继续使用。
```

`<<` 表示转移不可复制的值，不能用于 Copy 值；可以用 `=` 时必须用 `=`：

```xe
let number: i32 = first;                   // 复制：first 仍有效
let text: String << String::from("hello");
let other: String << text;                 // 移动类型：text 从此失效
```

`>>` 是独立的从左向右传递语句，保留同时支持两类值：Copy 值复制，其他值移动：

```xe
source >> target;
// source 可复制时相当于 target = source，否则相当于 target << source。
```

`=` / `<<` 分别是复制/移动声明、字段初始化和重新赋值的标准写法。`>>` 是语句层转送，
也允许在结构体字面量中使用 `source >> .field;`；不能写 `let source >> target` 或 `.field >> value`。
官方示例优先使用 `=` / `<<`；`>>` 适合管道结果落地。由于用户选择保留普通值的 `>>`，
它不是 `<<` 的严格反向等价，这个不对称例外必须显式记住。它们都不兼作整数移位运算符。

普通函数参数与返回值根据类型复制或移动，不需要选择赋值符号：

```xe
fn[T] identity(value: T) -> T { value }
```

无约束泛型的局部接收者可以先声明，再使用通用 `>>`：

```xe
fn[T] identity_via_local(value: T) -> T {
    let result: T;
    value >> result;
    result
}
```

泛型字段初始化使用 value >> .field;，不把未知 T 的 << 宣称为所有实例都合法。
基础泛型实例化后端已实现，上例会按实际 T 检查复制/移动规则并生成具体函数。
一般 Trait 能力仍有边界，完整范围见第 22 章。

## 元组解包

元组可以通过 `let tuple[a, b] = value;` 创建逐位置绑定，成员也可以独立标注类型。
`let[mut] tuple[a, b] ...` 照常允许后续修改；资源元组使用 `<<`。
没有 let 的 `tuple[a, b] = value;` 写入已有变量，`value >> tuple[a, b];` 是通用转送。
`_` 表示忽略成员，拥有资源仍自动析构。完整例子与边界见 [第 23 章](23.md)。

## 延后初始化

变量可以先声明后初始化，但控制流必须保证它在读取前恰好完成一次初始化：

```xe
let value: i32;

if ready {
    value = 1;
} else {
    value = 2;
}

println("{}", value);
```

如果存在一条能够到达读取位置、但没有初始化变量的路径，编译器必须报告“变量可能尚未
初始化”。延后初始化的 `let` 初始化后仍不可重新赋值。

## 重新赋值

初始化完成后只有 `let[mut]` 绑定可以直接重新赋值：

```xe
let[mut] current: String << String::from("first");
current << String::from("second");
```

对已经初始化的接收者执行 `<<` 时，先析构旧值，再接收新值。把变量传递给自身是编译错误。

## 声明形式

```text
let 名称: 类型 = 可复制表达式;
let 名称 = 可复制表达式;
let 名称: 类型 << 表达式;
let 名称 << 表达式;
let 名称: 类型;

let[mut] 名称: 类型 = 可复制表达式;
let[mut] 名称: 类型 << 表达式;
let[mut] 名称: 类型;
```

兼容说明：旧 var 是 let[mut] 的隐藏语法糖，仍可解析，但不作为公开示例或推荐写法。
二者生成相同的 mutable: true AST；写权限检查和运行行为完全相同。
声明附件目前只允许 [mut]，空附件、未知或重复修饰均报错。
