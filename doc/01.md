# 绑定、复制与值传递

## let 与 var

`let` 创建不可重新赋值的绑定，`var` 创建允许重新赋值的绑定：

```xe
let name: str = "Xe";

var count: usize = 0;
count = count + 1;
```

不可重新赋值不等于对象内部永远不可修改。是否能够修改对象内容由取得的是共享借用还是
可写借用决定。

这项区分由 --check-borrows 模式验证。默认模式的无修饰指针不检查可写能力；
let 只是绑定不能直接重新赋值，不是通过指针无法修改对象的承诺。

局部变量可以省略类型：

```xe
let answer = 42;
var index = 0;
```

同一作用域不能重复声明同名绑定。内层作用域允许暂时遮蔽外层名称，但 `xe lint` 默认提示，
因为大型程序中的意外遮蔽不利于阅读和自动修改。

公开常量使用 `const`，必须显式标注类型并能在编译期求值：

```xe
pub const VERSION: str = "0.1.0";
```

## 复制与传递

`=` 明确表示复制，只能用于实现了 `Copy` 的类型：

```xe
let first: i32 = 5;
let second: i32 = first;
// first 和 second 都可以继续使用。
```

`<<` 表示值从右向左传递，对所有类型都合法：

```xe
let number: i32 << first;                  // Copy 类型：first 仍有效
let text: String << String::from("hello");
let other: String << text;                 // 移动类型：text 从此失效
```

`>>` 是相同操作的反向写法：

```xe
source >> target;
// 等价于 target << source;
```

`<<` 是声明、字段初始化和重新赋值的标准写法。`>>` 只允许作为独立的源到目标传递语句，
适合代码确实按数据流从左向右排列的场景；不能写 `let source >> target` 或 `.field >> value`。
官方文档默认使用 `<<`，同一段代码不应混用两种方向。两者解析后降低成同一个值传递节点，
也不兼作整数移位运算符。

将 `<<` 定义为通用值传递非常重要：泛型代码不知道 `T` 是否实现 `Copy`，但始终可以写：

```xe
fn[T] box_value(value: T) -> Box[T] {
    Box[T] {
        .value << value;
    }
}
```

## 延后初始化

变量可以先声明后初始化，但控制流必须保证它在读取前恰好完成一次初始化：

```xe
let value: i32;

if ready {
    value << 1;
} else {
    value << 2;
}

println("{}", value);
```

如果存在一条能够到达读取位置、但没有初始化变量的路径，编译器必须报告“变量可能尚未
初始化”。延后初始化的 `let` 初始化后仍不可重新赋值。

## 重新赋值

只有 `var` 可以重新赋值：

```xe
var current: String << String::from("first");
current << String::from("second");
```

对已经初始化的接收者执行 `<<` 时，先析构旧值，再接收新值。把变量传递给自身是编译错误。

## 声明形式

```text
let 名称: 类型 = 可复制表达式;
let 名称 = 可复制表达式;
let 名称: 类型 << 表达式;
let 名称 << 表达式;
let 名称: 类型;

var 名称: 类型 = 可复制表达式;
var 名称: 类型 << 表达式;
```
