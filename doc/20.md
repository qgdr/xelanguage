# 0.9 语法审核、实现边界与自举验收

语法能明确解析、语义完整检查、程序真的生成并运行，是三件不同的事。
任何一层通过都不自动证明另外两层通过。当前编译器是 Python stage0，不是 Xe 自举编译器。
本章保留核心约定与待讨论项；覆盖最新容器、模块、并发功能的整体验收快照见 [第 30 章](30.md)。

## 核心约定的自洽性

| 约定 | 对应关系 | 必须明确的边界 |
| --- | --- | --- |
| 地址与指针 | a: T 则 a@: T@；p: T@ 则 p#: T | # 提供访问能力，不提供资源所有权 |
| 运算附件 | @[mut]/@[unsafe]、?[return]/?[panic] | 符号只接受自己定义的附件 |
| 结果与分流 | T? 组织可能性，value ? 分解可能性 | 两个上下文明确的运算，不是严格数学逆函数 |
| 负载与调用 | Variant[value] 构造，function(value) 调用 | [] 还用于索引/泛型，由语法位置和名称解析决定 |
| 管道 | value \|> f、1> f、Variant :> f 都调用 f | 返回函数要显式绑定后返回 fn/函数值 |
| 块与元组 | {x} 是块，tuple[x] 是单元素元组 | tuple 前缀明确区分类型、值与解包上下文 |
| 复制与移动 | Copy 用 =，不可复制值用 << | >> 同时适用两类值，是用户选择的非对称例外 |

核心入口具有确定解析规则，可以作为稳定内核，不需要再增加一套 match 或特殊 println。
T: Trait 与 value: Type 分处具名泛型附件和值声明，语法上下文可区分。
方法 . 按 self 类型自动取地址是明确的便利规则，不推广到普通函数的全部参数。

“像数学一样可推导”是设计准则，不是消除所有约定的证明：复制、资源、生命周期和控制流
仍需要解释。可读性需要初学者阅读实验验证，不能通过主观打分宣布已经 10 分。

## 类型是否会在读者不知情时变化

一个已声明变量不会仅因传参、访问或捕获就变成另一种声明类型。表达式的结果类型可以
不同于其输入类型，但变化规则必须能由写法或明确的上下文推得。地址捕获
`fn[x@]` 的隐藏环境字段为 `T@`，正文中的 `x` 仍是原始 `T` 的非拥有别名；
若 `p` 原本是 `T@`，`fn[p]` 的正文中 `p` 仍是 `T@`，详见第 15 章。

下表区分已经确定的上下文规则。它们不会修改原有变量的声明类型；`for` 创建新的
循环变量，字段/索引投影访问指针所指对象，但都不取得被指资源的所有权：

| 入口 | 确定的规则 | 边界 |
| --- | --- | --- |
| `for item in array` / `slice` | 新循环绑定是 `T@` / `T@[mut]`，不是元素 `T` | 遍历现存容器元素时绑定指针，可写 `for item: T@ in ...` 明示。 |
| `for item in iterator` | 调用 `next(): Step[T]`，遇 `Step::Stop` 停止，绑定 `Step::Item` 的 `T` | 生成值时获得值；若 `T` 本身是指针就获得指针，不额外取地址或解引用。 |
| `p.field`、`p[index]`，其中 `p: T@` | 投影自动越过最外层指针 | 只限字段/索引投影，不转移所指资源所有权；普通 `p#` 仍显式取值。 |
| `object.method()` | 值可按 `self: Self@` / `Self@[mut]` 自动取地址；指针可直接调用相容的指针接收者方法 | `self: Self` 若真正要消耗非 Copy 对象，指针调用报错；Copy 值的调用只复制，不转移所指资源。 |
| `T@[mut]` 用于 `T@` 位置 | 仅最外层指针写权限单向降为只读；原变量类型不变 | 已约定的权限收窄，不递归放宽二级指针。 |
| `fn f() -> T? { value }` | 仅返回位置将 `T` 包装成成功结果；普通赋值与参数位置不这样做 | 返回签名中已写 `?`，失败值仍须显式构造。 |
| 整数字面量与泛型实参 | 尚无固定类型的字面量按上下文定型；已定型数值变量不隐式转换 | 超出目标范围或不能精确表示必须报错，不得截断。 |

闭包 `f()` 的只读、可写、一次性调用能力由正文对环境的操作决定，影响是否消耗环境，
不改变捕获名的类型。指针上的 `unsafe` 是风险注记，不是新的业务类型；它可能因发现
悬垂风险而附加 warning。`x@`、`p#`、`value?[return]`、`as` 和 `?[@]` 本身已写出操作符，
不属于“隐藏变化”。

## 本轮已实现并有运行回归的功能

- Maybe 的 Yes/No/None、成功返回简写、1>/2>、共享/可写匹配、?[return]、?[panic]。
- 无损 as、整数 T::try_from、Copy<< 拒绝和普通/资源 >> 区分。
- Array/Slice/SliceMut 基础布局、范围切片、索引、迭代、析构和部分初始化清理。
- Range 与右开/闭区间整数循环；闭区间最大端点不靠溢出结束循环。
- File 打开/读取/关闭、UTF-8 验证、io::Error 输出。
- 具名函数值、无捕获 fn、函数值参数/返回、分支选择与管道调用。
- 指针模型允许别名/重复调用，资源盗取仍拒绝；局部资源视图逃逸以风险 warning 表达。
- 返回上下文推导、嵌套 Maybe 包装、None 上下文限制、负数选择器和无限按值布局诊断。
- 可写指针向只读指针的浅层单向转换，以及泛型函数/结构体/枚举的具体实例化后端。
- tuple[...] 元组、浅层解包/赋值和 _ 资源清理，以及透明类型别名与既有类型的组合。

测试编译并执行，不只检查 C 文本；资源错误路径另有 ASan/UBSan 验收。
真正项目见 [Xe Calculator](../examples/calculator/README.md)：扫描、优先级、错误恢复和文件输入。

## 仍需商量，不暗中发明规则

1. **泛型实现能力。** 已确定 struct[T] Holder / fn[T] wrap 声明、Holder[i32] / wrap[i32]
   应用和通用 value >> .field 初始化，解释见第 21 章。基础具体实例化后端已接入，
   但一般 Trait 分派、泛型 Copy/Drop 与编译期值参数仍需扩展；详见第 22 章。
2. **指针风险分析精度。** T@ 是普通指针，不需要 Rust 式独占区域证明；风险跟着 unsafe
   注记传播，能识别时给 warning，不能保证检测所有失效、外部释放和间接别名风险。
3. **unsafe 与 FFI。** 普通指针不拥有所指资源；free(pointer) 仍需要明确外部契约。
   [unsafe] 是风险注记，不是声明所有权或语句块门禁；ABI、分配/释放接口仍需独立实现。
4. **切片错误接口。** 当前数组切片越界终止，字符串切片失败返回 str?；这是运行库现状，
   不是理想的统一终局。File::size 也只接受可 seek 文件，失败终止；可恢复接口仍需明确。
   File.read_to_string 当前推进内部流位置，即使接收者是共享 File@；是否要求可写借用，
   或将外部 IO 状态与对象存储的可变性分开说明，仍需要讨论，不能称为纯读取函数。
5. **分支筛选能力。** 基础变体/字面量/_ 已运行；组合、元组、负载过滤尚未完整实现。
   必须明确将整个值还是所选负载送入处理函数，不能靠一个成功样例掩盖边界。
6. **递归数据布局。** 直接按值递归具有无限大小，应报错；AST 可以使用普通指针或 arena
   下标，但指针不自动提供资源所有权。Vec 和 Box 已实现；Map/Set 仍需实现。

尚未实现：注册表依赖/锁文件、一般静态 Trait 分派、泛型 Copy/Drop、编译期值参数、动态闭包/公共 Call Trait、yield 状态机、
Map/Set 等更多动态容器、extern ABI、完整标准库/调试映射。异步仍为 DEFERRED。
基础 Shared/Weak、互斥锁和 Thread 已实现，见第 29 章；完整线程安全 Trait/竞争分析仍未实现。
用户结构体和枚举 Copy 必须显式 impl，不再自动推导纯基本值结构体 Copy。

## 能否不比 Rust/OCaml 差

目前不能诚实地下这个结论。[OCaml 的类型定义与变体](https://ocaml.org/releases/4.13/ocaml-4.13-refman.pdf)
有丰富的结构表达，[Rust 的分阶段自举说明](https://rustc-dev-guide.rust-lang.org/building/bootstrapping/what-bootstrapping-does.html)
展示真正的构建链；不是仅凭一张语法表达到成熟度。

Xe 的可验证方向是：用较少约定写清类型化 AST、诊断、资源和标准库，再比较代码量、
修改涉及的模块数、诊断质量、构建时间、性能与初学者理解率。
目前演示支持“规则能组合成可读程序”，不支持“已经整体优于两门成熟语言”。

## 自举验收顺序

1. 固定覆盖编译器所需的子集，完成容器、模块与静态泛型能力。
2. 保持 Python stage0 为参考，用 Xe 编写同输入/同 AST/同诊断契约的前端。
3. stage0 编译 Xe 编译器得到 stage1，stage1 编译同份源码得到 stage2。
4. 比较归一化产物/行为，运行相同成功、失败和资源测试；路径/时间戳不能制造假差异。
5. 发布可重复构建步骤。没执行这条链时，不使用“已经自举”作为项目状态。

## 重复审核

```sh
make compiler-test
make demo
make audit
```

audit 逐例记录 AST、语义、C、系统编译、运行与原始诊断，源码哈希写入 target/audit/stage999.json。
有 XE-PTR 风险 warning 的程序仍生成 C 并尝试系统编译，但默认不执行，记录 warning_not_run。
只有人工审查并接受风险时才使用 --run-warnings，不能为了让审核全绿运行悬垂示例。
它不是安全沙箱，不要运行不可信源码。生成 C 不等于编译成功，退出 0 不等于输出正确，
样例全过不等于整个规范实现；精确输出由项目测试验收，扩展能力都应增加正反例。
