# 普通指针与显式 Copy：已批准迁移

本章记录用户确认的设计，不把过去的“安全借用”模型继续作为现行规范。
当前实现范围仍由第 18、19 章及实际测试说明；目标设计不等于每个功能已实现。

## 固定的基本关系

- T@ 是只读普通指针，T@[mut] 是可写普通指针；两者都 Copy，允许别名和重复传参。
- unsafe 跟着指针传播，而不是停在某个 unsafe 语句块中。可检测的悬垂等风险给 warning，
  推导类型附带 unsafe，仍可编译；不承诺检测所有风险，不宣称内存安全。
- 类型、写权限、资源所有权错误仍报错。指针不拥有所指资源，不能移动 p# 中的资源。
- 用户结构体和枚举 Copy 必须显式 impl；基础类型的复制能力不需要用户声明。
- = 只复制；<< 只移动不可复制值；>> 通用转送。字段初始化也允许 value >> .field;。
- 每个 ? 只消解一层枚举。需要处理内层枚举时，再明确写一次 ?。
- 有捕获闭包暂缓，不继续扩充其调用和生命周期规则。

## 泛型：前面声明，后面代入

```xe
struct[T] Holder {
    value: T,
}

fn[T] wrap(value: T) -> Holder[T] {
    Holder[T] {
        value >> .value;
    }
}

fn main() {
    let holder: Holder[i32] << wrap[i32](10);
    println("{}", holder.value);
}
```

这里不是把同一个操作搬了位置，而是区分两种操作：

| 写法 | 读法 |
| --- | --- |
| struct[T] Holder | 声明以 T 为未知量的类型族 Holder |
| Holder[i32] | 代入 T = i32，选出一个具体类型 |
| fn[T] wrap | 声明以 T 为未知量的函数族 wrap |
| wrap[i32] (10) | 先代入类型，再传入普通调用参数 |

[] 始终附带信息：声明时列出未知量，使用时给出未知量的取值。
从左向右读 wrap[i32](10) 就是“选择 wrap 的 i32 版本，然后调用并传入 10”。
这也允许自然组合 namespace::Holder[i32]、Holder[i32]::new(10) 和 object.map[u8](convert)。
具名 struct、enum、trait、fn 的泛型声明统一附在关键字后；impl 的泛型也附在 impl 后。
旧的“类型名后附泛型参数”声明迁移为 struct[T] Holder 等关键字附件。
[] 在这些位置是类型参数，不因 T@ 而误读成对运行时变量取地址。

未知 T 可能 Copy，也可能是资源，因此不能统一使用 = 或 << 初始化字段。
value >> .field; 沿用现有通用转送规则，没有为 = 偷偷增加移动含义。
Holder 未声明 Copy，即使 Holder[i32] 所有字段可复制，也仍是不可复制用户类型。

## 一层匹配

```xe
outer ? {
    Outer::Wrapped :> inner -> inner ? {
        Inner::Number :> number -> number,
        Inner::Empty :> _ -> 0,
    },
    Outer::Empty :> _ -> 0,
}
```

一次 ? 只选择当前枚举，并按声明顺序把这一层的完整负载传给处理函数。
不支持 Outer::Wrapped[Inner::Number[_]] 这种递归变体选择器；不自动展平深层字段。
字面量筛选、通配符和显式内层匹配与递归展开不同，不因此增加隐藏的参数绑定规则。

## 迁移时不要运行悬垂示例

tests/warnings 保存应该“warning 但编译成功”的风险程序，不能统一执行。
tests/fails 只保留语法、类型、写权限和所有权等必须失败的程序；指针别名不是失败用例。
AST 是原始语法树，语义推导和风险传播信息必须另外报告，避免伪装成用户写过的注记。
