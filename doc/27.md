# 自举基础库与模块加载：已实现边界

这一阶段补齐了写一个 Xe 前端最直接需要的能力：遍历源码、保存数量未知的节点、
写出生成文件，以及把实现拆成多个文件。它不是“完整标准库”或“已完成自举”的声明。

## 字节与字符

`str` / `String` 的 `bytes()` 产生 `Bytes`，`chars()` 产生 `Chars`。
前者逐次返回 UTF-8 字节 `u8`，后者返回 Unicode 标量 `char`，不是用户眼中的字形。
两者保存原文的非拥有视图，不复制文字；必须让原文在遍历过程中保持有效。

```xe
let text: str = "A中😀";
for byte: u8 in text.bytes() { println("{}", byte); }
for scalar: char in text.chars() { println("{}", scalar); }
```

`next()` 返回 `Step[u8]` / `Step[char]`，结束为 `Step::Stop`，不是 `None`。
直接调用 `next()` 需要可写迭代状态；`for` 自己管理内部可写状态。
已结束的文本迭代器再次调用仍返回 Stop。

`String::new()` 创建空的拥有字符串，`push_str(str)` 追加文字，`push_char(char)`
追加一个标量。容量按增长策略预留，避免每个字符都重新分配。修改可能让之前的
`as_str()` / 字节指针失效；已有指针风险规则照常给 warning，不承诺内存安全。

## 可增长数组 Vec[T]

`Array[T, N]` 固定元素数量；`Vec[T]` 拥有可增长缓冲区；`Slice[T]` 只是观察视图。
Vec 自己不可 Copy；复制能力属于元素，不意味着整个拥有容器可以复制。

```xe
let[mut] values << Vec[i32]::new();
values.push(10);
values.push(20);
for value: i32@ in values { println("{}", value#); }
let last: i32 = values.pop()?[panic];
```

| 接口 | 含义 |
| --- | --- |
| `Vec[T]::new()` / `with_capacity(n)` | 创建拥有容器；后者预留 n 个元素的空间 |
| `len()` / `capacity()` / `is_empty()` | 查看元素数量、容量和是否为空 |
| `push(value: T)` | 普通参数规则：Copy 元素复制，否则移动进容器 |
| `pop() -> T?` | 取出最后一个元素的所有权；空容器返回 None |
| `reserve(additional: usize)` | 确保能再放 additional 个元素，不改变长度 |
| `clear()` | 逆序 drop 当前元素，保留缓冲区供重用 |
| `as_slice()` / `as_slice_mut()` | 创建只读/可写元素视图，不取得元素所有权 |

修改元素/容器需要 `let[mut]` 或 `Vec[T]@[mut]`；只读指针不提供可写能力。
`values[index]` 访问元素本身，类型是 T；只有 `values[index]@` 才是 T@。
下标不提供资源移出权限；资源可用 `pop()` 取出。这是容器的所有权规则，不是借用类型转换。
`for` 绑定 `T@`，不转移容器或元素。容器退出作用域时逆序析构剩余元素并释放缓冲区，
已 pop 的元素不重复析构。`Vec[Node]` 支持递归 AST 容器；节点中不能直接按值放一个 Node。
递归使用相同具体类型可以复用清理函数；不断把 T 变成 Node[T] 的递归泛型会触发
实例化数量/深度限制并报告 XE-GENERIC-0002，不能无限生成清理代码。

扩容、clear、pop 等修改可能使之前的元素地址或切片失效。编译器会保守地传播风险
warning；程序仍需要维护地址有效性。内存分配失败和容量溢出当前终止程序，
不是已经提供了可恢复的分配器接口。

## 写入文件

```xe
let[mut] file << File::create("output.txt")?[panic];
file.write_all("hello\n")?[panic];
file.flush()?[panic];
```

`File::create(path)` 返回 `File?[io::Error]`，创建文件或截断已有文件。
`write_all(text: str)` / `flush()` 返回 `Unit?[io::Error]`，要求可写接收者。
写入按字节长度处理，保留内嵌 NUL；错误可以用分支或 `?[return]` 处理。
`flush()` 检查缓冲写入错误，不承诺断电持久性（不是 fsync）。
自动 drop 会关闭文件，但 drop 本身不能返回关闭错误；需要观察写入失败时显式 flush。

## 一文件一模块

有 `xe.toml` 时，入口放在 `src/` 内；`src/main.xe` 是程序根，`src/lib.xe` 是库根。
独立文件没有包配置时，以入口所在目录为源码根。使用文件路径推导模块名，
不需要写 `mod` 或 `module` 声明。

```xe
use crate::scan::{Word, words};
use crate::report::render as make_report;
use std::io::{println, eprintln};
```

支持 `crate`、`self`、`super`、分组导入、别名、模块别名、公开再导出和完整限定引用。
模块别名指向对应 .xe 文件；仅有目录不产生运行时模块或隐含模块文件。
导入及完整限定引用递归加载可达文件；未使用的导入也检查有效性。
同包模块可以相互引用：先收集所有声明，再检查正文。
默认声明/字段/方法仅当前模块及子模块可见；跨其他模块调用接口要写 `pub`。
同名私有声明互不干扰，局部变量可以遮蔽导入名。不同包的依赖图不允许环。

当前支持本地依赖：

```toml
[dependencies]
util = { path = "../util" }
```

依赖目录需要 `xe.toml` 和 `src/lib.xe`，调用写 `use util::function;`。
注册表下载、版本选择、Git 依赖、xe.lock 生成/验证及模块级增量编译尚未实现；
统一工具已有整程序 C 编译缓存，但仍每次重新检查 Xe 源码，见第 32 章。
不静默忽略这些依赖；真正引用不支持的依赖时明确报错。
没有模块顶层执行语句，因此导入不会运行隐藏初始化代码。

`std::io` / `std::env` / `std::iter` / `std::collections` 支持导入已登记接口。
标准库目前仍由 C 运行库及编译器生成代码支撑，尚不是 Xe 源码包。

## 构建和维护

```sh
make check SOURCE=examples/source_scan/src/main.xe
make source-scan
make source-scan INPUT=tests/language/iterator_step.xe REPORT=target/debug/words.txt
```

构建把可达模块合成一个 C 翻译单元，再交给系统 C 编译器；暂不要求用户理解
对象文件及链接顺序。错误和风险 warning 保留各自文件的行列位置，不能覆盖任何已加载源码。
`make ast` 仍输出入口文件原始语法树；模块限定名与类型侧表属于编译内部处理，
不污染用户 AST JSON。`--check --diagnostic-format json` 的推导类型带来源文件。

实现入口：`compiler/xe_ast/modules.py` 管理加载和名称解析，
`backend_containers.py` 生成 Vec、Box 和文本迭代代码，运行库处理字节操作与分配。
模块边界、库边界与工具执行分别由 `test_modules.py`、`test_bootstrap_library.py`、
`test_source_scan_project.py` 验证，包含 ASan/UBSan 和资源恰好析构一次检查。

Xe 子集前端与固定点后来已经实现，源码和边界见 [第 31 章](31.md)。
完整语言前端仍未移植；后续按真实阻塞补库/静态类型能力，不以 IR 重构替代自举结果。

拥有单个堆对象的 Box、可失败分配及普通指针接口见 [第 28 章](28.md)。
