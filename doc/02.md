# 类型、函数与运算符

## 基本类型

整数：`i8`、`i16`、`i32`、`i64`、`isize`、`u8`、`u16`、`u32`、`u64`、`usize`。

其他核心类型：

- `f32`、`f64`：浮点数；
- `bool`：`true` 或 `false`；
- `char`：一个 Unicode 标量值；
- `str`：不可变 UTF-8 视图，包含数据地址和字节长度；
- `Unit`：没有内容的单值类型，它唯一的值写作 `unit`；
- `Never`：永远不会产生值，用于 `panic`、`exit` 等函数。

`String`、`Vec[T]`、`Map[K, V]`、`Slice[T]` 等由标准库提供。`Any`、运行时反射和动态类型
不属于第一版自举核心。

## 字面量

```xe
let decimal: i32 = 255;
let hex: i32 = 0xff;
let octal: i32 = 0o377;
let binary: i32 = 0b1111_1111;
let ratio: f64 = 1.5;
let byte: u8 = b'A';
let cat: char = '😻';
let text: str = "hello";
let empty: Unit = unit;
```

数字中的下划线只改善可读性。

## 函数

```xe
fn add(left: i32, right: i32) -> i32 {
    left + right
}
```

参数必须声明类型。返回类型省略时为 `Unit`，函数正常执行到结尾时返回 `unit`：

```xe
fn greet(name: str) {
    println("hello, {}", name);
}
```

参数绑定默认不可重新赋值。函数确实需要修改自己的局部参数绑定时使用 `var`：

```xe
fn advance(var index: usize) -> usize {
    index = index + 1;
    index
}
```

按值参数是隐含的值传递位置：

- `Copy` 参数复制，调用后实参仍可使用；
- 移动类型参数取得所有权，调用后实参失效；
- `T@` 和 `T@[mut]` 参数只借用对象。

T@[mut] 属于 --check-borrows 模式。默认模式的 T@ 是非拥有、不检查借用的指针；
无论模式如何，不能将资源参数 p: T@ 的 p# 再按值传入其他函数。

这个规则对所有函数一致，包括 `print`、`println` 和 `format`。任何函数都不能在调用点
把移动参数偷偷改成借用；需要保留移动类型时，调用者必须显式传入 `value@`。

返回移动类型时，块尾表达式或 `return` 将其所有权移给调用者。

同一模块不按参数类型重载同名函数。需要多种类型时使用泛型、Trait 或不同名称，避免调用
含义依赖隐藏的重载候选。第一次自举只为内置类型实现运算符，用户运算符重载以后再设计。

## 显式转换

普通 `as` 只允许不会丢失信息的转换：

```xe
let wide: i64 = small as i64;
```

可能失败或截断的转换必须说明策略：

```xe
let byte: u8? = number as[checked] u8;
let wrapped: u8 = number as[wrap] u8;
```

`as[checked]` 返回可选值，`as[wrap]` 使用模运算。浮点到整数、整数到枚举等转换必须另行
定义清楚，不能静默发生。指针地址使用 `.addr()`，不使用 `as Ptr`。

## 运算符优先级与结合规则

下表从高到低。括号可覆盖优先级；求值顺序与结合方向是不同问题。

| 层级 | 符号或结构 | 结合规则 |
| --- | --- | --- |
| 名称结构 | :: | 组成路径，不是运行时二元运算 |
| 1 | 调用 ()、索引/变体负载 []、字段 .、@ / @[...]、#、?[return] | 后置链从左到右 |
| 2 | not、一元 +、一元 - | 从右到左嵌套 |
| 3 | as、as[checked]、as[wrap] | 从左到右 |
| 4 | *、/、% | 从左到右 |
| 5 | +、- | 从左到右 |
| 6 | <、<=、>、>=、==、!= | 比较链，不按普通二元结合 |
| 7 | and | 从左到右，短路 |
| 8 | or | 从左到右，短路 |
| 9 | ..、..= | 不可连写 |
| 10 | \|> | 从左到右调用；参数绑定正文另有边界 |
| 11 | ? 分流、?[@] / ?[@[mut]] 匹配 | 消耗左侧完整管道表达式；连续匹配用括号 |
| 语句层 | =、<<、>> | 不属于表达式，不允许链式赋值 |

普通 ? 与 ?[return] 故意不同：前者带分支结构，优先级低于普通管道；
后者仅提取/传播，是后置操作。类型位置的 T?、T@ 是类型修饰，不参与表达式优先级。

```xe
a + b * c;              // a + (b * c)
ready or valid and ok;  // ready or (valid and ok)
source |> parse ? 1> good 2> bad; // 对 parse(source) 的结果分流
source?[return] |> process;      // 先取得成功值，再调用 process
```

:>、1>、2> 是分支头，不是任意二元表达式运算符，不单列算术优先级。
-> 分隔处理参数与正文，或参数列表与返回类型；fn 创建匿名函数。
: 是名称/类型分隔符，[] 运算修饰是对应结构的附件；逗号、分号、花括号都不具有算术优先级。

比较链 a == b == c 依次检查 a == b、b == c；每个操作数至多求值一次，从左到右短路。
a != b != c 仅比较相邻两对，不保证 a != c。资源比较是读取而非消耗对象；
首版只支持已定义的内置比较，禁止借比较移动资源。

处理绑定 x -> expression 的正文包括完整表达式：value |> x -> f(x) |> g 中 g 属于正文。
若要让后续管道或算术作用于整个分支结果，必须用括号或先绑定局部结果；换行不改变含义。
