# 类型、函数与运算符

## 基本类型

整数：`i8`、`i16`、`i32`、`i64`、`isize`、`u8`、`u16`、`u32`、`u64`、`usize`。

其他核心类型：

- `f32`、`f64`：浮点数；
- `bool`：`true` 或 `false`；
- `char`：一个 Unicode 标量值；
- `str`：不可变 UTF-8 视图，包含数据地址和字节长度；
- `Unit`：没有内容的单值类型，它唯一的值写作 `unit`；
- `Never`：永远不会产生值，用于 `panic`、`exit` 等函数。

`String`、`Vec[T]`、`Slice[T]` 等已有 stage0 库支持；`Map[K, V]` 是尚未实现的标准库目标。
`Any`、运行时反射和动态类型不属于第一版自举核心。

## 透明类型别名

顶层 `type Name = Type;` 可以为现有类型建立透明别名，例如
`type handler = fn(i32) -> i32;`。别名展开后仍使用原来的类型、Copy 和资源规则；
支持前向引用和别名链，拒绝循环，不增加泛型别名语法。详见 [第 23 章](23.md)。

## 字面量

```xe
let decimal: i32 = 255;
let hex: i32 = 0xff;
let octal: i32 = 0o377;
let binary: i32 = 0b1111_1111;
let ratio: f64 = 1.5;
let byte: u8 = b'A';
let cat: char = '😻';
let text: str = "hello";
let empty: Unit = unit;
```

数字中的下划线只改善可读性。

## 函数

```xe
fn add(left: i32, right: i32) -> i32 {
    left + right
}
```

参数必须声明类型。返回类型省略时为 `Unit`，函数正常执行到结尾时返回 `unit`：

```xe
fn greet(name: str) {
    println("hello, {}", name);
}
```

所有函数参数统一写 name: Type，签名不声明参数绑定的可变性。
参数绑定只读，需要局部修改时在函数体建立可变绑定：

```xe
fn advance(index: usize) -> usize {
    let[mut] index = index;
    index = index + 1;
    index
}
```

右侧 index 是参数，左侧是新的局部绑定；这是显式遮蔽，而不是重新赋值参数。
Copy 值用 =；资源类型必须用 let[mut] text << text; 转交所有权，不能隐式复制。
旧 let[mut] index: Type、var index: Type 和 index[mut]: Type 均不属于参数语法。
匿名函数和管道处理参数也遵守同一规则。
修改调用者对象时仍须显式声明并传入 T@[mut]；指针参数绑定本身只读不妨碍写所指对象：

```xe
fn advance_in_place(index: usize@[mut]) {
    index# = index# + 1;
}
```

按值参数是隐含的值传递位置：

- `Copy` 参数复制，调用后实参仍可使用；
- 移动类型参数取得所有权，调用后实参失效；
- `T@` 和 `T@[mut]` 参数复制地址，允许重复调用和地址别名，不获得对象所有权。

T@[mut] 的可写限制始终验证。不能将资源参数 p: T@ 的 p# 再按值传入其他函数。

这个规则对所有函数一致，包括 `print`、`println` 和 `format`。任何函数都不能在调用点
把移动参数偷偷改成借用；需要保留移动类型时，调用者必须显式传入 `value@`。

返回移动类型时，块尾表达式或 `return` 将其所有权移给调用者。

同一模块不按参数类型重载同名函数。需要多种类型时使用泛型、Trait 或不同名称，避免调用
含义依赖隐藏的重载候选。第一次自举只为内置类型实现运算符，用户运算符重载以后再设计。

## 显式转换

不隐式转换已有数值变量的类型。字面量按预期类型推导，包括元组各元素。
整数字面量须符合目标范围；指定浮点目标时须能精确表示该整数，不能默默舍弃精度。
浮点字面量可按 f32/f64 的表示精度舍入，但不得溢出成无穷大。
普通 `as` 只允许对整个来源类型范围都不会丢失信息的转换：

```xe
let wide: i64 = small as i64;
```

可能失败的整数转换使用普通关联函数，返回明确错误类型：

```xe
let byte: u8?[ConversionError] = u8::try_from(number);
let required: u8 = u8::try_from(number)?[panic];
```

同符号整数可扩宽；无符号到更宽有符号可扩宽；f32 可扩宽到 f64。
整数到浮点只有整个来源范围都能精确表示时允许。f64 到 f32 不属于无损转换。
`try_from` 检查目标整数范围，失败为 Maybe::No[ConversionError]；不会截断或取模。
ConversionError 是不可自行构造的内置 Copy 错误类型，当前支持格式化输出。
普通错误可用 1>/2> 恢复，?[return] 传播，或显式 ?[panic] 终止。
浮点到整数、整数到枚举等另行设计，不能静默发生。
as 的 checked/wrap 附件草案撤回，解析器给出迁移诊断；前端和 C 后端实现上述整数规则。
输出指针地址已支持 `{:p}`。地址整数化的 `.addr()` 是预留 API，当前语义检查器和后端
均未提供；不使用 `as Ptr`。它不是现阶段可执行的转换示例。

类型允许括号分组：fn(i32) -> i32? 是返回可选整数的函数；
(fn(i32) -> i32)? 是可选函数。类型后置修饰作用于分组后的完整类型。

## 运算符优先级与结合规则

下表从高到低。括号可覆盖优先级；求值顺序与结合方向是不同问题。

| 层级 | 符号或结构 | 结合规则 |
| --- | --- | --- |
| 名称结构 | :: | 组成路径，不是运行时二元运算 |
| 1 | 调用 ()、索引/变体负载 []、字段 .、@ / @[...]、#、?[return] / ?[panic] | 后置链从左到右 |
| 2 | not、一元 +、一元 - | 从右到左嵌套 |
| 3 | as | 从左到右 |
| 4 | *、/、% | 从左到右 |
| 5 | +、- | 从左到右 |
| 6 | <、<=、>、>=、==、!= | 比较链，不按普通二元结合 |
| 7 | and | 从左到右，短路 |
| 8 | or | 从左到右，短路 |
| 9 | ..、..= | 不可连写 |
| 10 | \|> | 从左到右调用；参数绑定正文另有边界 |
| 11 | ? 分流、?[@] / ?[@[mut]] 匹配 | 消耗左侧完整管道表达式；连续匹配用括号 |
| 语句层 | =、<<、>> | 不属于表达式，不允许链式赋值 |

普通 ? 与 ?[return] 故意不同：前者带分支结构，优先级低于普通管道；
后者仅提取/传播，是后置操作。类型位置的 T?、T@ 是类型修饰，不参与表达式优先级。

```xe
a + b * c;              // a + (b * c)
ready or valid and ok;  // ready or (valid and ok)
source |> parse ? 1> good 2> bad; // 对 parse(source) 的结果分流
source?[return] |> process;      // 先取得成功值，再调用 process
```

:>、1>、2> 是分支头，不是任意二元表达式运算符，不单列算术优先级。
-> 分隔处理参数与正文，或参数列表与返回类型；fn 创建匿名函数。
: 是名称/类型分隔符，[] 运算修饰是对应结构的附件；逗号、分号、花括号都不具有算术优先级。

比较链 a == b == c 依次检查 a == b、b == c；每个操作数至多求值一次，从左到右短路。
a != b != c 仅比较相邻两对，不保证 a != c。资源比较是读取而非消耗对象；
首版只支持已定义的内置比较，禁止借比较移动资源。

处理绑定 x -> expression 的正文包括完整表达式：value |> x -> f(x) |> g 中 g 属于正文。
若要让后续管道或算术作用于整个分支结果，必须用括号或先绑定局部结果；换行不改变含义。
