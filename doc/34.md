# 资源替换与一层模式：执行规则闭环

本轮实现不新增符号。沿用已经约定的 `=` / `<<` / `>>`、`?`、`:>`、
`tuple[...]`、选择器 `|` 和普通指针 `@`。

## 资源替换

替换不是覆盖几段内存，而是把一个新的拥有值放入已有位置：

```xe
struct Item { number: i32, text: String, }
impl Drop for Item {
    fn drop(self: Self@[mut]) { println("drop {}", self.number); }
}

fn replace(pointer: Item@[mut], replacement: Item) {
    pointer# << replacement;
}

fn main() {
    let[mut] items << Vec[Item]::new();
    items.push(Item { .number = 1; .text << String::from("old"); });
    items[0] << Item { .number = 2; .text << String::from("new"); };
}
```

执行顺序固定为：

1. 求值并保存目标的基位置和索引，只执行一次下标及指针表达式。
2. 求右侧的新值，将其保存到独立拥有临时值。
3. 对含索引的目标，按已保存索引逐层重新验界并解析当前元素地址，再清理活跃旧值：
   先执行自定义 Drop，再清理其资源字段。
4. 把新值移入目标，目标再次负责将来的清理。

这套规则覆盖局部变量、按值字段、Array/Vec/可写切片元素以及可写指针所指对象；
String、用户资源、Vec、Box、Shared 等不再各自使用不同的替换语义。
右侧提前 `return` 时尚未替换，旧值仍正常清理；成功移动出去的字段可以重新初始化，
但不能访问已移动父对象下的字段。重新初始化不会再次 Drop 已经移动走的旧字段。

不能把 Vec 元素的旧地址跨右侧运算保存：右侧可能扩容、清空或更换容器。
例如 `values[0] << { values.push(new_item()); replacement() };` 在右侧完成后
写入当前存储的第 0 个元素，而不会使用 realloc 已释放的地址。若右侧清空数组/向量
导致下标不再有效，执行通常的越界 panic，不对旧地址重复析构。
目标基表达式和索引不会因此重新执行；嵌套下标按由外到内重新解析。
右侧若移走目标的父拥有者且未重建，编译报已移动/未初始化；
整个根变量重新初始化、或精确字段移动后重建仍遵守既有规则。
这些是编译器管理容器/拥有者的替换规则，不是对普通指针增加互斥借用证明。

普通指针仍和 C 一样：它不取得所指资源的所有权，也不证明地址有效。
原位替换要求指针指向有效的、已初始化的可写对象；不能借此从 `pointer#` 移走资源。
指针别名、失效地址等风险仍可能产生 warning，不声称完全内存安全。

## 选择器只筛选，`:>` 后才绑定参数

```xe
enum Token { Number[i32], Identifier[str], End, }

fn describe(token: Token) -> str {
    token ? {
        Token::Number[0 | 1] :> number: i32 -> "small number",
        Token::Number :> number: i32 -> "other number",
        Token::Identifier["if"] :> text: str -> "keyword",
        Token::Identifier :> text: str -> "identifier",
        Token::End :> _ -> "end",
    }
}
```

负载过滤的位置只能是直接字面量、`_` 或这些选择器的 `|` 组合。
它不声明变量，不省略参数，不改变载荷类型；例如 `[0, _]` 仍把两个载荷都送给处理器。
不允许递归写 `Outer::Value[Inner::Value[_]]`：把内层交给参数后再显式写一次 `?`。

同一分支的组合选择器必须提供相同数量和类型的载荷：

```xe
enum Source { Left[i32], Right[i32], Empty, End, }
fn identity(value: i32) -> i32 { value }

fn read(source: Source) -> i32 {
    source ? {
        Source::Left | Source::Right :> identity,
        Source::Empty | Source::End :> _ -> 0,
    }
}
```

如果两个变体分别附带 `i32` 和 `str`，不能组合成一个处理器；分别写分支即可。
后端只访问选中变体的载荷，不提前复制或移动其他变体的资源。

## 元组选择与指针匹配

```xe
fn choose(pair: tuple[bool, bool]) -> i32 {
    pair ? {
        tuple[true, _] :> whole: tuple[bool, bool] -> 1,
        tuple[false, true] :> whole: tuple[bool, bool] -> 2,
        tuple[false, false] :> whole: tuple[bool, bool] -> 3,
    }
}

fn change(pair: tuple[i32, i32]@[mut]) {
    pair ?[@[mut]] {
        tuple[_, _] :> whole: tuple[i32, i32]@[mut] -> {
            whole.0 = whole.1;
        },
    };
}
```

沿用第 06、14 章已经冻结的规则：元组选择器只按位置筛选，处理器收到**整个元组**，
不自动展开为多个参数；顶层 `_` 同样接收整个对象。需要成员时显式解包：

```xe
let total = pair ? {
    tuple[_, _] :> whole -> { let tuple[first, second] = whole; first + second },
};
```

资源元组在处理器中使用 `let tuple[...] << whole;`。`?[@]` / `?[@[mut]]` 的元组
处理器接收 `tuple[...]@` / `tuple[...]@[mut]`，访问成员仍可用 `.0`、`.1` 或显式取址。
按值枚举匹配才按变体声明传完整的各个载荷，指针匹配则传各载荷的指针；
这些显式规则不因类型注解或 `_` 自动改变。

## 覆盖、不可达和析构

- 枚举必须覆盖所有变体。`Number[0]` 只覆盖该变体的一部分，不能替代整个 `Number`。
- bool 及 bool 元组的直接过滤会联合检查：`true` 和 `false` 可完整覆盖，
  不需要形式上的 `_`；`unit` 本身也覆盖全部 Unit 值。
- 普通整数、字符串等通常使用 `_` 或不带过滤的变体作为兜底；若实际列出完整
  有限整数域，例如 u8 的 256 个不同值，也能证明穷尽，不要求多写一个不可达兜底。
- 重复选择、已经被之前分支完整覆盖的选择以及兜底后的分支是编译错误。
  `|` 内的冗余选择同样报错，交换左右顺序不改变诊断，例如 `_ | true` 与
  `true | _` 都应直接简化为 `_`。
- 资源只由选中的分支接收一次；忽略的资源仍清理，提前 return/break/continue
  使用正常作用域清理，不漏 Drop、不重复 Drop。
- 有自定义 Drop 的枚举不能移出资源载荷，但可以通过 `_` 转交整个枚举，
  或显式指针匹配查看载荷。

这些行为通过实际 C 编译与执行测试验证，包括 ASan、UBSan 和默认泄漏检查；
对应测试是 `test_resource_replacement.py` 与 `test_one_layer_patterns.py`。
