# Trait、Copy 与析构

实现状态：非泛型用户类型的 Copy/Drop 及泛型 Copy 约束已经可运行。
下面的一般 Trait、默认方法与 Display/Formatter 展示目标设计，通用检查/分派尚未实现；
不能因为解析器接受 trait 声明就把该例当作当前完整标准库接口。

Trait 描述类型能够提供的静态行为：

```xe
trait Display {
    fn display(self: Self@, output: Formatter@[mut]);
}

impl Display for Position {
    fn display(self: Self@, output: Formatter@[mut]) {
        output.write("{}:{}", self.line, self.column);
    }
}
```

没有函数体的方法必须由实现类型提供；有函数体的方法是默认实现。第一次自举只需要静态
分派，不要求 Trait 对象和运行时虚表。

## Copy

`Copy` 是编译器识别的标记 Trait：

```xe
impl Copy for Position;
```

用户结构体和枚举必须显式声明 Copy；即使字段全部是整数，或结构体为空，也不会自动实现。
`=` 初始化/赋值没有实现 Copy 的用户类型时，编译器报错，不偷偷改成移动。

禁止实现 Copy 的条件：

- 类型实现了 Drop：浅复制会导致同一资源被重复释放。
- 任意字段或枚举负载不是 Copy：不能靠声明绕过字段自己的所有权规则。
- 类型是拥有资源的内置类型，例如 String、File：它们的复制必须使用明确的 clone API。
- 泛型实现没有证明相关字段的复制能力：需要 T: Copy 等约束，不猜测未来实参。

Copy 是无正文的标记实现，不允许借它定义复制函数。Clone 是显式普通调用，两者不混淆。
当前只支持非泛型用户结构体/枚举的 Copy 实现；重复实现报错。条件泛型实现尚未接入，
不会把某个具体实例的 Copy 承诺错误地推广到所有实例。
整数、浮点、bool、char、Unit、函数值和指针由语言提供复制能力；标准视图的复制只复制
地址和长度，不克隆底层资源。数组、元组等内置组合必须逐元素满足 Copy。

T@ 与 T@[mut] 都 Copy，unsafe 注记不改变这个事实。可写指针复制后允许别名；
复制任何指针都不会取得所指资源的所有权，也不会延长对象生命周期。

泛型可以要求复制能力：

```xe
fn[T: Copy] duplicate(value: T) -> tuple[T, T]
{
    tuple[value, value]
}
```

`Clone` 与 `Copy` 不同：`Clone` 是可能分配资源的显式普通方法，移动类型可以实现它。

## Drop

`Drop` 在值离开作用域时释放资源。下面使用已实现的输出接口展示自定义清理钩子；
文件关闭等平台释放应由对应资源的实现负责，当前没有公开 os::close FFI 接口：

```xe
struct Tracked {
    handle: usize,
}

impl Drop for Tracked {
    fn drop(self: Self@[mut]) {
        println("drop {}", self.handle);
    }
}
```

析构顺序：

1. 同一作用域中的局部变量按完成初始化的逆序析构；
2. 结构体先执行自己的 `drop`；
3. 再按字段声明顺序析构仍有效的字段；
4. 已经移动出去的值或字段不会再次析构。

编译器自动生成字段析构代码。用户的 `drop` 不应手动重复析构字段。`Copy` 与 `Drop` 互斥。

## 块结束时自动释放

每个 block 都建立局部作用域。离开该作用域时，内部定义的绑定全部失效；已经初始化且
仍由当前作用域拥有的资源自动 drop，不需要手写释放。这是确定性的作用域析构，不是
追踪式垃圾回收，也不保证释放指针所指的外部对象。

- 普通标量和 Copy 值结束其局部生命周期，不调用资源析构。
- 非拥有指针及视图结束自身生命周期，不 drop 所指对象。
- 未初始化的绑定不析构；已移动出去的值不析构；仍拥有的资源恰好析构一次。
- 内层块先清理自身，外层对象不会仅因内层块退出就被析构。
- 正常到达右花括号时，先求值并转交块尾结果，再按初始化逆序清理其他局部资源。
- return 先求值并转交返回结果，再由内到外清理退出的作用域；函数按值参数也属于函数
  作用域，未转交的资源参数在函数退出时析构，晚于参数初始化的函数局部资源先析构。
- break 清理直到所退出循环的当前迭代作用域；continue 清理本次迭代的局部资源。
  循环外仍有效的资源不因此释放。?[return] 的失败路径按提前 return 清理。
- 资源表达式作为带分号语句使用、又未转交或存入绑定时，其临时拥有值在语句结束时 drop。

```xe
fn main() {
    let kept: String << {
        let scratch: String << String::from("temporary");
        let result: String << String::from("kept");
        result
    }; // result 已移出，不 drop；scratch 在这里自动 drop

    println("{}", kept@);
} // kept 自动 drop
```

指针不延长资源生命周期。地址或视图可能逃逸到所有者 drop 之后；能够发现时编译器标注
unsafe 并给 warning，不取消正常析构，也不阻止编译。后续解引用的正确性由程序员负责。

首版 panic 采用终止进程而非栈展开；panic、直接 exit、系统强制终止和永不结束的循环不
保证运行作用域析构。drop 必须正常返回，不能借错误传播离开析构过程。

编译器在每条正常退出边上插入同一套清理逻辑，记录初始化和移动状态。C / LLVM 后端只需
执行这些显式清理操作，不依赖后端自动理解 Xe 所有权，也不需要为此实现垃圾回收器。
