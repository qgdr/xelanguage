# Box：拥有堆对象与普通指针

状态：本章接口和语义已经用户确认，并已实现类型检查、C 生成及运行测试。
沿用现有泛型、方法、指针及结果语法，不增加运算符，不改变 AST 版本。

## 一个拥有者，多个普通指针

`Box[T]` 拥有堆上的一个 T。Box 描述符保存数据地址，退出作用域时先 drop T，
再释放这块堆内存。它不能 Copy，即使 T 是 i32；移动 Box 转交同一块内存的所有权，
不复制或搬动堆上的 T。

```xe
fn main() {
    let[mut] owner << Box[i32]::new(10)?[panic];
    let read: i32@ = owner.ptr();
    let write: i32@[mut] = owner.ptr_mut();
    write# = 20;
    println("{}", read#); // 20；允许指针别名。

    let handle: Box[i32]@ = owner@;
    println("{}", handle.ptr()#);

    let value: i32 = owner.into_value();
    println("{}", value); // 20
    // owner 已消耗；read/write 已悬垂，不能再解引用。
}
```

`owner@ : Box[T]@` 指向 Box 描述符；`owner.ptr() : T@` 指向其中的堆对象。
二者不同，编译器不能偷偷把一个变成另一个。Box 不是 @ 指针，不支持 `owner#`，
也不把 `owner.field` 或 `owner[index]` 隐式解释为内部 T 的操作。
取出普通指针后，仍保留既有 `p.field` 访问规则，例如 `p: Node@` 可以写 `p.name`。

## 接口

```xe
// 以下展示方法签名，不是额外的用户声明。
Box[T]::new(value: T) -> Box[T]?[AllocError]
ptr(self: Self@) -> T@
ptr_mut(self: Self@[mut]) -> T@[mut]
into_value(self: Self) -> T
```

`ptr_mut()` 要求可写 Box 绑定或可写 Box 指针；ptr() 不要求可写。
可写 T@[mut] 可以降为只读 T@，反向不行。取得指针不转交 T 的资源所有权。

`into_value()` 消耗 Box、取出 T，只释放堆外壳，不 drop 已转出的 T。
T 为 Copy 时用 `=` 接收，否则用 `<<`；未知泛型仍可按既有规则用 `>>`。
通过 Box@ 不能调用 into_value()，因为普通指针没有 Box 所有权；Box 本身始终不可 Copy。

Box、AllocError 当前作为简短内建标准名称使用；不新增未审核的标准库模块路径。
透明别名如 `type Heap = Box[i32];` 也可用 `Heap::new(10)`，不改变所有权或布局。

## 分配失败也必须清理

new 的实参和普通函数实参一样：Copy 值复制，不可复制值移动。
实参只求值一次；取得实参后才尝试分配。分配失败返回 No[AllocError]，
已经转入的资源在进入调用者的失败处理分支前恰好 drop 一次，不能留在原变量中继续使用。

AllocError 是无附带数据的分配失败标记，输出显示 `heap allocation failed`。
它不是要求所有 T?[E] 的 E 都为错误类型，也没有新增预定义 Error Trait。
失败处理仍使用既有 `1>` / `2>`、`?[return]` 或 `?[panic]`：

```xe
fn heap(value: i32) -> Box[i32]?[AllocError] {
    Box[i32]::new(value)
}

fn main() {
    heap(42)?
        1> owner: Box[i32] -> println("{}", owner.ptr()#)
        2> error: AllocError -> println("cannot allocate: {}", error);
}
```

只有本章 Box::new 提供这个可恢复的分配结果；当前 Vec/String 的分配失败仍终止，
不能把 Box 的契约推断成所有标准库分配接口的契约。
`?[panic]` 终止时依然不承诺执行全局资源清理。

## 指针不延长生命，warning 不阻止运行

ptr / ptr_mut 返回普通指针，不是具有生命保证的智能句柄。
Box 析构或 into_value 后，指向其 T 的指针失效；程序负责不再访问。
如果 T 自身保存外部 str 或指针，将它放入 Box 也不会让外部数据自动活得更久。
编译器能识别的风险给 warning 并传播 unsafe，类型、写权限和资源所有权错误仍是 error。

Box 移动不会改变堆对象地址，只要新拥有者仍存活，原先取得的 T@ 在运行时仍然有效。
当前风险分析按绑定来源保守追踪，尚未完整追踪跨移动的堆对象身份，因此这里可能误报
失效 warning。实际地址稳定行为已有运行及 ASan/UBSan 测试；不将保守警告说成语言禁令。

正常 `make build` / `make run` 遇到 warning 仍编译/运行，只有 error 阻止编译。
`make audit` 默认不自动执行包含指针风险的样例，这是审核工具避免统一运行悬垂程序的策略，
不是语言拒绝 warning 程序。人工审查后可选择 `--run-warnings`。
