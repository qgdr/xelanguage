# Xelanguage 语言规范总览

本文是规范入口。除非章节明确标注“未来扩展”，文档中的规则都是目标语言的一部分；现有
Python 编译器尚未全部实现这些规则。

冻结范围由 [Bootstrap Syntax 0.2](17.md) 明确列出。FROZEN 是前端实现契约；
RESERVED / PROVISIONAL / DEFERRED 不得被误认为已经实现或已经稳定的语义。

## 设计目标

Xelanguage 按以下顺序取舍：

1. 含义明确，读者可以局部判断代码在做什么；
2. 明确区分不检查指针的默认模式与检查模式，不作虚假的安全承诺；
3. 错误信息能够说明原因、源码位置和修改方法；
4. 语法结构稳定，便于格式化器、语言服务器和 AI 工具修改；
5. 编译器实现简单可靠，可以逐步自举；
6. 性能可预测，但不为了极少数场景破坏日常可读性。

## 面向人类与工具的约定

- 公开 API 显式标注参数和返回类型，局部变量允许类型推导。
- 不根据缩进改变语义；换行用于排版，`;` 结束语句。
- 不允许整数充当布尔值，不进行有损隐式转换。
- 导入必须指明名称，首版禁止 `*` 通配符导入。
- 模块加载没有隐式执行的顶层副作用。
- 每种语法糖都有唯一、可记录在诊断中的基础语义。
- 官方格式化器产生唯一的常规排版，避免无意义的风格争论。

## 名称与类型

`:` 在变量、参数和字段声明中表示“左侧名称具有右侧类型”；
在具名函数的泛型附件中，`T: Trait` 表示类型参数的能力约束：

```xe
let count: usize = 0;

fn contains(text: str, byte: u8) -> bool {
    // ...
}

struct Position {
    line: usize,
    column: usize,
}
```

`::` 是一个完整的命名空间运算符，不是两个独立的类型冒号：

```xe
let text: String << String::from("hello");
let token << syntax::Token::End;
```

## 方括号与圆括号

枚举变体使用 `[]` 声明、构造和筛选负载，例如 `Token::Integer[i64]` 和
`Token::Integer[42]`。无负载变体直接写 `Token::End`。函数和方法调用使用 `()`；
分组与元组也使用 `()`。类型参数、运算符修饰和索引继续使用 `[]`，由左侧名称及其
所在语法位置决定具体作用；写成 `Token::Integer(42)` 时编译器应提示改用 `[]`。

## 运算符修饰

部分运算符允许紧随其后的 `[...]` 修改该次运算。修饰符属于对应运算符的语法，不是普通
数组索引：

```xe
let write: i32@[mut] << value@[mut];
let file: File << File::open(path)?[return];
```

首版规则：

- `@[mut]`：建立独占可写借用；
- `@[r]`、`@[mut, r]`：为公开 API 标注借用区域；
- `?[return]`：成功时取得值，失败时从当前函数提前返回；
- `?[@]`、`?[@[mut]]`：只读及可写借用匹配；
- `as[checked]`、`as[wrap]`：受控数值转换。

每个运算符只接受规范列出的修饰符。未知、重复或互相冲突的修饰符是编译错误。修饰符在
编译期解释，不允许用户代码改变其基础语义。未来可以增加新修饰符，但不能悄悄改变无修饰
运算符的含义。

## 语句与块表达式

带 `;` 的表达式作为语句使用。块末尾不带 `;` 的表达式是块的值：

```xe
fn plus_one(value: i32) -> i32 {
    value + 1
}

let answer = if ready {
    42
} else {
    0
};
```

`return value;` 用于提前返回。省略函数返回类型时返回 `Unit`。

每个块建立局部作用域。退出块时，内部绑定失效，仍拥有的资源自动 drop；块尾表达式或
return 已转移出去的资源不重复析构。普通退出及 return / break / continue / ?[return]
均遵守此规则，不依赖是否开启借用检查。完整顺序与边界见第 08 章。

## 一致性底线

- 所有普通参数位置使用同一套规则：`Copy` 值复制，移动值转移，`value@` 才是共享借用；
- 不存在隐式克隆、隐式有损转换、隐式错误丢弃或仅对某个标准库函数生效的所有权例外；
- 方法接收者可以根据声明中的 `self: Self@` 或 `self: Self@[mut]` 建立调用期短借用，这是
  对所有方法统一的接收者规则；普通参数仍必须显式借用；
- 类型和生命周期可以推导，但推导不能改变运行时行为；
- 标准库便利接口必须能够解释为这些基础规则的组合。

## 自举核心

第一版自举只要求：

- 基本类型、数组、字符串、切片、结构体和枚举；
- 函数、块、条件、循环和穷尽模式匹配；
- 模块、公开接口、简单泛型和静态 Trait 分派；
- `Copy`、移动、析构、安全借用和 Arena/ID 风格的数据结构；
- 可失败结果、文件、路径、进程参数和标准输入输出；
- LLVM IR 文本或 C 后端，以及一个很小的系统运行库。

异步、线程、异常、反射、动态 Trait 对象、继承和复杂宏不属于第一次自举。多线程加入前，
不会承诺线程安全 Trait；开启 `--check-borrows` 后借用规则在单线程中防止悬垂指针和
别名写入。默认模式没有这些保证，官方库与自举验收必须使用检查模式。

## 管道与匿名函数的统一约定

|>、1>、2>、:> 后只能接可调用目标或处理参数绑定。裸函数名意味着调用，不是返回函数值。
参数绑定 x: T -> expression 立即执行，return 作用于外层所在函数；fn(...) { ... } 才是
匿名函数表达式，建立自己的函数作用域，捕获项用 fn[...] 显式列出。
共享匹配 ?[@] 将普通负载统一作为指针传入；str / Copy 只读视图保留有明确边界的例外。
模式只选择，变量只在处理参数位置声明，避免一个名字同时被解释为模式变量及相等比较。
完整优先级见第 02 章，解析摘要见第 14 章，[15：处理函数与闭包](15.md)。
