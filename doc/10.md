# 普通管道与处理函数

|> 将左侧结果作为参数送给右侧处理函数：

```xe
let result << input |> trim |> parse_i32;
```

命名函数和保存函数的变量均可作为目标，含义是调用，不是返回该函数。
需要额外参数时显式绑定，不使用匿名负载占位符：

```xe
let result = value
    |> number: i32 -> multiply(number, 2);
```

参数绑定正文覆盖后续表达式，因此连续变换优先用命名函数或带 fn 的匿名函数：

```xe
let result = value
    |> fn(number: i32) -> i32 { multiply(number, 2) }
    |> fn(number: i32) -> i32 { add(10, number) };
```

value |> x -> f(x) |> g 等价于 value |> (处理函数 x -> (f(x) |> g))，
不会把 g 当成外层的下一个处理函数；需要外层链时用上面的 fn 或括号明确目标范围。

```xe
let output: i32;
3 |> twice |> twice >> output;
```

>> 是独立的值传递语句，目标必须是存储位置；不是返回值管道，不能链式赋值。
管道与分支管道共用处理函数规则，详见第 15 章：

- path（包括函数变量）：调用目标；
- 参数 -> 正文：立即执行的参数绑定；
- fn(...) { ... }：创建匿名函数后立即作为目标调用；
- (函数值表达式)：显式求值目标后调用。

禁止 |> 42、|> _、|> f(_) 和 |> f(1) 等旧式值或调用表达式目标。
若函数 make_handler() 返回可调用对象，可显式写 value |> (make_handler())；
内层调用用于取得处理函数，外层管道调用它。不是禁止函数变量，而是禁止不可调用目标。

资源值经过管道一定转移所有权，Copy 值仍复制，不隐式克隆或借用。
value@ |> inspect 传递非拥有指针；pointer# |> consume 对资源类型始终非法。
闭包捕获及调用规则见第 15 章。即刻管道处理不要求堆分配。
