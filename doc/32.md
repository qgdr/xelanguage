# 原版 stage0 的统一工具链

本章记录已经实现的工具，不增加 Xe 语言规则。日常编译继续使用 Python stage0 和
现有 C 后端；`bootstrap/` 作为独立自举实验项目保留，不切换默认编译器。

## 启动与最短路径

首次准备根目录环境仍然运行 `uv sync --frozen`。仓库根的可执行脚本 `./xe` 优先使用
该 `.venv`，不会修改 shell 配置、创建第二套环境或改变工作目录。没有根环境时需要
Python 3.13+；从其他目录用绝对路径启动也能定位原版编译器。

```sh
./xe --help
./xe doctor
./xe check examples/feature_check/main.xe
./xe run examples/feature_check/main.xe -- check
./xe run examples/args/main.xe -- "two words" "你好 Xe" "" --help
./xe run --manifest-path examples/toolchain --bin smoke
```

也可在仓库根使用 `uv run --project . --frozen --offline python -m compiler ...` 或
`make xe XE_ARGS='build --manifest-path examples/toolchain'`。不需要安装 Python 包。
若想在任意目录直接输入 `xe`，可以自行把仓库目录加入 PATH；工具不会自动改 `.zshrc`。

## 命令范围

| 命令 | 当前行为 |
| --- | --- |
| ast | 解析单文件，输出 AST JSON；不做语义检查 |
| check | 加载可达模块，检查类型/写权限/资源，报告指针风险 |
| emit-c | 使用相同前端检查，输出可读 C |
| build | 生成 C，调用系统编译器，原子发布可执行程序 |
| run | 构建后运行，stdin/终端与当前工作目录保持不变 |
| test | 编译运行显式指定的 Xe 程序；`--compiler` 运行现有 Python 回归 |
| fmt | 整理已有行的缩进/安全尾空白；`--check` 不写源码 |
| lint | 语义检查，并提示隐藏 var 别名可以采用公开 let[mut] 风格 |
| doc | 从公开声明与 ///、//! 注释生成 Markdown/JSON API 清单 |
| clean | 只删除已登记、未手动修改且位于本项目 target 下的产物 |
| doctor | 显示解释器、项目、C 编译器路径与版本；不是全平台 ABI 验证 |

原 `compiler/main.py`、`python -m compiler.xe_ast`、Makefile 的 ast/check/build/run 等
命令仍然兼容；其默认输出路径未改变。新统一入口有独立的项目产物定位和缓存。

## 项目、入口与运行参数

沿用第 09 章已有目录约定，不新增清单字段：

```text
project/
├── xe.toml
├── src/
│   ├── main.xe       # build/run 的默认入口
│   ├── lib.xe        # doc 优先选择；只有库时 check 也可用
│   └── bin/smoke.xe  # --bin smoke
└── target/
    ├── debug/        # 默认 -O0 + 调试信息
    ├── release/      # --release，C 编译采用 -O2
    ├── ast/          # ast 的 JSON
    ├── c/            # emit-c 输出
    ├── doc/          # API 清单
    ├── tests/        # 显式 Xe 测试程序
    └── .xe-tools/    # 可核查的构建和产物收据
```

从当前目录向上寻找最近的 xe.toml；也可显式 `--manifest-path xe.toml` 或项目目录。
清单项目的模块与本地 path 依赖仍由原加载器解析。未配置清单的显式 .xe 文件，以所在
目录作为独立项目，生成物放在旁边的 target，而非都覆盖仓库的 target/debug/main。
`-o` 仍可选择输出路径；build/run 不能输出到 `-`。ast/emit-c 的 `-o -` 只输出相应文本。

`run` 的 `--` 前是编译器选项，之后原样传给程序：空参数、空格、UTF-8、`--help` 和
第二个 `--` 都保留。不拼接 shell，也不再次解释 `$()` 等内容。相对的运行时文件路径
继续相对调用者工作目录，而不是被偷偷改成源码目录。run 不往程序 stdout 混入构建提示。

默认 C 编译器为 CC 环境变量或 cc；`--cc` 接受单个可执行文件，不把 `"ccache gcc"`
当作 shell 命令。`--cflag=-Wall` 每次添加一个参数。`--build-timeout` 控制系统 C 编译，
run 的 `--timeout` 控制目标程序；都只接受有限正数秒。
`--sanitize` 启用 ASan/UBSan，Linux 加 no-pie，保留默认泄漏检测，仍不证明程序安全。
线程接口继续自动添加 pthread 链接参数。

## 缓存与失败保护

每次 build 仍进行模块加载、语义检查与 C 发射；缓存只省略最后的系统 C 编译。
缓存键包括实际生成 C、可达源码和清单、编译器源码、语法版本、C 工具路径/内容/版本、
配置参数、相关环境变量和平台信息。运行库嵌入生成 C，修改运行库也使缓存失效。
还核对现有程序内容哈希和可执行权限；缓存损坏或产物被修改时自动重新构建。
warning 每次重新报告，不能因缓存命中被隐藏。

可读 C 不作为人工编辑入口。真正编译的是本次生成文本的私有快照，不是后来可能被
改写的公共 .c 文件。收据中的程序哈希在发布前取自私有编译结果，避免另一个发布者的
程序被错误认作本次缓存结果。`--rebuild` 强制系统编译；自定义 C 选项可能引用未登记的
include/响应文件，因此目前保守禁用缓存。系统头文件/外部 SDK 更新后也应 --rebuild；
当前不承诺完整工具链环境的逐文件重现或机器码字节可复现。

源码检查失败不会覆盖旧程序；C 编译失败保留旧程序，留下新 C 方便定位，并登记失败 C。
不会允许程序/C/收据覆盖可达 Xe 源码或包清单，包含同路径、符号链接和硬链接别名。
编译器不是安全沙箱，只构建/运行自己信任的源码与 C 工具；不要并行 clean 和构建/运行，
也不要让不同任务共享同一个自定义输出路径。

收据是实现数据，不是依赖锁：注册表下载、Git 依赖、xe.lock 生成/强制校验、模块 .o/
.xmi 缓存、增量语义分析、LLVM 和交叉编译仍未实现。

## 测试：先不发明语言语法

```sh
./xe test examples/toolchain/src/bin/smoke.xe
./xe test examples/toolchain/src/bin/smoke.xe --sanitize
./xe test --compiler
./xe test --compiler --pattern=test_toolchain.py
```

第一种测试是普通带 main 的程序：成功退出 0，失败退出非零。多个显式文件各自编译/
执行；一个编译或运行失败不会掩盖其他案例。默认 stdin 为 EOF，每个 Xe 程序运行
超时 5 秒；可用 --timeout 修改。输出写临时文件，报告只保留末尾 16 KB及截断标记。
程序自行验证结果，可写 `main() -> i32` 或在失败时明确 panic；不增加 assert 关键字。

没有自动扫描 tests/fails、tests/warnings 或全部示例来执行。显式传入文件就表示要求
执行可信程序；指针 warning 不阻止编译/运行，audit 原有的“风险样例默认不运行”策略
仍独立保留。当前包加载器仍要求入口位于 src，因此包测试可先放 src/bin/smoke.xe；
独立 tests/smoke.xe 的包归属、单元测试函数发现与文档测试执行尚待商议，不偷偷绕过。

--compiler 专门运行已有 unittest 套件，可用 --pattern 选择文件。其默认总时间不限，
--timeout 可设整体上限；不接受 Xe 构建参数，原回归自行指定编译器与 sanitizer。
无文件且没有 --compiler 时显示用法错误，不臆测应该执行哪个工程。

## 格式、lint 与 API 文档

fmt 使用默认四空格缩进，不改变现有换行结构，不把一行多语句展开成新的官方风格。
字面量、注释内容、附件和运算符原样保留；写入前重新解析并比较忽略位置的 AST 及注释。
所有选择文件先验证，一个非法文件不导致先改其余文件；保留文件权限，不跟随源文件
符号链接。尚不是全功能 pretty printer，这个输出设置也不增加语言规范规则。

无路径 fmt 只扫描清单项目 src；明确目录会递归选取其中 Xe 文件，但跳过 target、
.git、.venv 和目录符号链接。不自动整理依赖包或自举项目。可以先 --check 查看状态。
lint 当前只提供隐藏 var 写法的迁移提醒，不是假装完成了未使用变量、复杂度和完整静态分析。

doc 默认只列本包可达的公开声明和公开成员，保留真实源文件位置，隐藏私有字段及类型；
--include-private 可以查看内部接口，--format=json 供工具读取。默认输出 target/doc/index.md。
不执行文档内的示例，不新增注解语法，暂不提供 HTML 站点、自动文档测试或 LSP。

## 机器可读接口与退出码

```sh
./xe check examples/toolchain/src/main.xe --message-format=json
./xe build --manifest-path examples/toolchain --message-format=json
./xe test examples/toolchain/src/bin/smoke.xe --message-format=json
./xe doc --manifest-path examples/toolchain --format=json -o -
```

--message-format / 兼容别名 --diagnostic-format 控制诊断。带诊断的 check JSON 在 stderr，
无诊断的检查结果在 stdout；其余错误/warning 在 stderr。build/文件输出状态/test/fmt/
clean/doctor 的 JSON 结果在 stdout；连续诊断消息可按 JSON 行读取。ast/emit-c/doc 的
`-o -` 输出本身，不混入状态。run 的目标程序输出不被改造成 JSON。

源码错误、测试失败和 fmt --check 发现差异退出 1；环境、配置、输入输出与工具错误
退出 2；warning 本身不导致失败。run 保留程序退出码，信号退出采用 128 + 信号编号，
中断返回 130。JSON 诊断带 code/severity/message，语言诊断继续保留原源码范围和建议。

## 清理与维护

先 `xe clean --dry-run` 看列表。真正 clean 只删除收据登记且哈希未变的本项目 target
文件；已修改、未知、外部输出、符号链接和损坏收据保留。旧 Makefile/旧 CLI 产物没有
登记时也保留；不会删根目录或递归清空 target，更不会删 target/bootstrap。
生成物删除后可重新 build/doc/ast 恢复。显式清理路径不存在时拒绝执行，不猜其父目录。

实现按职责分开：project 定位入口；driver 管理构建；artifacts 管理收据与清理；
formatting 验证格式变换；documentation 读取公开 API；toolchain 做 CLI 分发。
所有语言语义仍在 xe_ast 原有前端/后端。验收运行 `make toolchain-test`，完整回归仍是
`make compiler-test`。可运行项目见 [examples/toolchain](../examples/toolchain/README.md)。
