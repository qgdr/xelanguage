# 闭包状态、迭代器与拉取式生成器

状态：自定义 next 协议、拥有/指针 for、`std::iter::from_fn` 已接入 C 后端并有实际执行测试。
不增加运算符，不实现 `yield` 暂停恢复、异步生成器或通用 Iterator Trait/关联类型。

## 先区分三个概念

- 闭包：函数代码可以访问创建时保存的捕获环境。
- 迭代器：保存进度，每次 next() 产生一个值或报告结束。
- 生成器：产生一串新值的写法；目前可以用有状态闭包经 `from_fn` 实现，
  `yield` 暂停恢复状态机尚未实现。

它们不是依次必需的前提。Rust 的 Iterator 核心接口在 `next` 的返回值中表示元素或结束；
Xe 用专门的 `Step[T]` 明确区分这两个迭代事件，不把普通 `None` 当作停止信号。
参考：[Rust Iterator](https://doc.rust-lang.org/std/iter/trait.Iterator.html)。

`Step[T]` 是当前编译器预置的迭代协议类型，概念上等价于：

```xe
enum[T] Step {
    Item[T],
    Stop,
}
```

`Step::Item[value]` 表示本次产生一个 `T`；`Step::Stop` 表示迭代结束。
这两个构造依照预期的 `Step[T]` 推导类型参数；不能只返回裸 `value` 或 `None`。
`T?[Stop]` 也能表达“两种情况”，但那是通用 `Yes` / `No` 分支；
这里专用的 `Item` / `Stop` 名称更直接，让 `for` 协议与普通结果分流分开。
`T?[E]` 的 `E` 本可为任意类型，不因写在 `No` 分支就自动成为错误。
`None` 简写目前仅用于返回 `T?` 的位置；在普通枚举负载中必须明确写 `Maybe::None`。
当前没有通用的模块加载，不需也不能假设已存在可导入的 Xe 版 `Step` 标准库源码。

## 最简单的迭代器不需要闭包

```xe
struct Counter { current: i32, end: i32, }
impl Counter {
    fn next(self: Self@[mut]) -> Step[i32] {
        if self.current >= self.end { Step::Stop } else {
            let value = self.current;
            self.current = self.current + 1;
            Step::Item[value]
        }
    }
}
fn main() {
    let counter << Counter { .current = 0; .end = 3; };
    for value in counter { println("{}", value); } // 0、1、2
}
```

for 协议要求一个无额外参数的 `fn next(self: Self@[mut]) -> Step[T]` 方法。
`Step::Item[value]` 让本轮绑定 `value: T`；`Step::Stop` 在进入循环体前结束循环。
元素若可能缺失，返回 `Step[T?]`：`Step::Item[Maybe::None]` 仍是一个元素，绝不结束迭代。
元素若有另一种结果，返回 `Step[T?[E]]`：本轮取得 `T?[E]`，由循环体决定如何处理；
即使 `No[E]` 表示错误或其他情况，也不会被当成结束。
`Step::Stop` 只负责结束，与元素本身的 `None` / `No[E]` 互不混淆。
[iterator_step.xe](../tests/stage999/iterator_step.xe) 可运行地验证第一轮 `Item[Maybe::None]`、
第二轮 `Item[Maybe::Yes[7]]`，之后才 `Stop`。

遍历已有数组/切片元素时，for 绑定元素指针；范围与 `from_fn` 生成新值时，
for 绑定生成的值。自定义迭代器 `next(): Step[T]` 的 `Item` 负载是什么 `T`，
for 的新变量就是什么 `T`：资源元素获得所有权，指针元素仍只是指针，
不自动取地址或展开。这里的“生成”不表示已经支持 `yield`。
泛型 next 在具体实例上检查和生成代码，不要求已经支持通用 Trait 分派。

## for 拥有什么，什么时候清理

```xe
for value in iterator { /* ... */ }         // 源按类型复制或移动一次
for value in iterator@[mut] { /* ... */ }   // 只复制指针，保留外部拥有者和当前进度
```

第一种在进入循环前把值交给隐藏的循环局部存储，next 使用这个存储的可写地址。
因此原绑定可以不是 let[mut]；非 Copy 源即使零次迭代也已移动，不能再使用。
第二种要求可写指针，循环不拥有或释放外部迭代器；break 后可以继续 next 或再次迭代。
只读 `T@` 不能访问修改进度的 next。

每轮接收的新鲜资源元素，由本轮拥有；移交给其他函数后由接收者拥有。
忽略元素、continue、break 和 return 都清理仍拥有的本轮资源。
循环拥有的环境在正常结束、break 或提前 return 时清理；指针循环不清理外部环境。
如果元素是依赖迭代器内部存储的视图，将它保存到循环外可能得到悬垂风险 warning。
普通指针不会自动延长环境生命，也不会因为该 warning 而拒绝编译。

## 用有状态闭包生成值

Rust 提供 from_fn，把一个可重复调用并返回可选值的闭包包装成迭代器。
Xe 使用相同的轻量方向，但回调用 `Step[T]` 表示产出或结束，保留显式捕获和普通指针规则。
参考：[Rust from_fn](https://doc.rust-lang.org/std/iter/fn.from_fn.html)。

```xe
fn main() {
    let current = 0;
    let numbers << std::iter::from_fn(fn[current]() -> Step[i32] {
        if current >= 3 { Step::Stop } else {
            let value = current;
            current = current + 1;
            Step::Item[value]
        }
    });
    for number in numbers { println("{}", number); }
}
```

current 复制进闭包环境，环境由 numbers 拥有，不依赖外部 current 后续值。
每次 next **从闭包正文开头重新执行**；字段 current 留在环境里，保存进度。
闭包正文普通局部变量不跨调用保留。此实现不是 yield，也不会自动记住执行到了哪一行。

from_fn 接收一个无参数、返回 `Step[T]` 的可重复调用目标：无捕获函数、读/写环境闭包，
或可调用普通指针。写环境闭包由适配器通过内部可写地址调用，无需用户给每次调用加 @。
会移出捕获资源的一次性闭包不能作为持续回调；要产生资源元素，可以每轮新建或显式 clone。

适配器具体类型是 `FromFn[F]`，F 是具体回调类型，不是元素类型。
FromFn 是预先登记的标准类型，不能重新定义同名结构体、枚举、Trait 或别名。
捕获闭包的 F 通常由推导得到；泛型工厂可写：

```xe
fn[F] make(callback: F) -> FromFn[F] {
    std::iter::from_fn(callback)
}
```

存储只有 callback 和 done：无虚表、无强制堆分配。from_fn 按普通参数规则取得回调；
传 callback@[mut] 则只保存指针，不拥有外部闭包。指针所指对象必须仍存在。
这些是标准库登记接口，目前无需也不能假定普通 `use` 模块加载已实现。

## 结束不等于偷偷销毁对象

Xe 的 FromFn 首次收到 `Step::Stop` 后记住 done，后续 next 都返回 `Step::Stop`，不再调用回调。
这是明确的终止约定；Rust 的普通 from_fn 不自动保证这一点，Xe 有意选更容易观察的规则。
自定义迭代器 for 同样在第一次 `Step::Stop` 结束，但手动调用该对象的 next 是否还能产生值，
由其方法正文决定；当前没有通用 Fused Trait。

`Step::Stop` 只说明“没有下一个元素”，不是每个闭包通用的销毁信号。
FromFn 内的捕获资源在拥有迭代器的 block 结束时释放，而不是 next 偷偷销毁仍存在的对象。
for 若拥有它，结束循环即结束这个隐藏 block；for 若只持指针，环境属于外部拥有者。
这样既能及时清理，也不改变普通指针与 block 自动 drop 的既有含义。
