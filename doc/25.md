# 命令行参数与最小工具

命令行参数来自启动进程时的参数列表，不是 stdin 的一行文本。
读取参数只增加标准库接口，不增加语言符号，不改变 `fn main()`：

`std::env::args() -> Slice[str]?[io::Error]`

成功时得到只读切片，`args.len()` 返回参数个数，`args[index]` 读取一项。
第 0 项是程序名，第 1 项起是用户参数。`?` 处理读取/UTF-8 验证或分配失败；
成功负载是 Copy 视图，使用 `=`，不需要也不应对它使用 `<<`。
若接收尚未分流的整个错误结果，则写 `let result << std::env::args();`。

## 最简单的 Xe 命令行工具

[examples/args/main.xe](../examples/args/main.xe) 的唯一作用是读取参数并逐项打印：

```xe
// 最小命令行工具：只读取参数并打印，不读取 stdin。
// 参数包含程序名；空参数会打印为空行，参数内的空格不会再次拆分。
fn main() -> i32 {
    let args = std::env::args()?
        1> values -> values
        2> error -> {
            eprintln("无法读取参数：{}", error);
            return 1;
        };
    for arg: str@ in args {
        println("{}", arg#);
    }
    0
}
```

`1>` 将成功切片交给 values；`2>` 打印错误并退出。
数组和切片的循环产生元素指针，因此 arg 是 `str@`，`arg#` 读取它指向的字符串视图。
所有字符串都依赖进程参数存储，在 main 执行期间有效，用户无需手动释放。

构建并运行：

```sh
make build SOURCE=examples/args/main.xe PROGRAM=target/debug/xe-args
./target/debug/xe-args hello "two words" "你好 Xe" ""
```

输出（最后一行是空行）：

```text
./target/debug/xe-args
hello
two words
你好 Xe

```

shell 会先处理引号：`"two words"` 是一个参数，不是两个，外围引号不是内容。
`""` 是空参数，仍占一个位置。库不对参数文本再次按空格拆分。
没有用户参数时，示例只打印程序名；发生错误返回 `1`，正常返回 `0`。

## 通过编译器运行

```sh
make run SOURCE=examples/args/main.xe ARGS='hello "two words" "你好 Xe" ""'
uv run --project . --frozen --offline python compiler/main.py examples/args/main.xe --run -- hello "two words"
```

编译器选项在 `--` 前，目标程序参数在 `--` 后，二者不混淆。
运行器会把参数边界原样传递，包括空参数及 `--help` 等以连字符开头的内容，
不会将目标程序的 `--help` 当作编译器帮助。使用运行器时，程序名是可执行文件绝对路径。
Makefile 的 ARGS 按通常的 shell 引号规则展开；不要填入需要当作数据的未经引用的 shell 命令。

## 库边界与较完整的工具

参数必须是 UTF-8；非法字节返回 IO 错误，而不是替换字符。视图只读，改变局部绑定
不能改变字符串或参数表。实现、缓存和进程生命周期说明见 [stdlib/env](../stdlib/env/README.md)。
接口仍由 stage0 的 C 库支撑，普通源码模块加载和多线程没有因此完成。

[Feature Check](../examples/feature_check/README.md) 是另一个、较完整的 Xe 工具：

```sh
make feature-tool
./target/debug/xe-feature-check check
./target/debug/xe-feature-check echo "你好 Xe"
./target/debug/xe-feature-check --help
```

没有参数时仍进入原来的交互模式；有参数时执行对应命令后退出，不读取 stdin。
在终端交互时会显示 `xe> `，等待 echo 文本时显示 `text> `；未知指令只提醒并继续。
管道输入或重定向输出时不显示提示。支持颜色的终端会显示带颜色的检查结果，
重定向的输出仍为纯文本；可用非空 `NO_COLOR` 或 `TERM=dumb` 禁止颜色。
stdout 和 stderr 的颜色能力独立判断，echo 文本不会染色，详见 [第 24 章](24.md)。

Feature Check 正常或全部检查通过返回 0；检查失败返回 1，并在后续交互中保留；
参数模式的未知命令、多余参数返回 2；参数或输入读取失败返回 3。
交互中输错命令不会把正常退出变成失败，这和一次命令的参数模式有所区别。
`make feature-check` 自动运行 check；`make stdlib-test` 验证真实参数、UTF-8 错误、
只读权限、独立 C 构建、资源清理和运行器参数转发。
