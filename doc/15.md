# 处理函数、匿名函数与闭包

状态：匿名函数、显式捕获环境、方法式调用、资源清理和具体泛型回调已接入 Python/C 编译器。
捕获闭包的公共动态类型、独立泛型闭包和 `yield` 暂不支持。拉取迭代器见 [第 26 章](26.md)。

## 闭包是什么，变量存在哪里

普通函数只收到调用参数。闭包还保存创建时指定的变量，可以理解为：

**闭包对象 = 捕获环境（一个隐藏结构体）；调用闭包 = 运行函数代码，并访问这个环境。**

```xe
let base = 40;
let add << fn[base](value: i32) -> i32 { base + value };
println("{} {}", add(2), add(3)); // 42 43
```

编译器为这个表达式生成一个含 `base: i32` 字段的结构体，创建 `add` 时复制 40 到字段。
函数代码只保存一份，不把整个函数复制到每个对象里。调用时给隐藏函数传入环境地址和
`value`，函数从环境字段读取 base。因此外部 base 和捕获字段是两个存储位置。

环境就在闭包对象里：局部闭包通常是局部存储，传参移动对象，放入容器则随容器存储。
不会强制堆分配，也不会为了保留变量而自动延长原函数的栈生命。指针捕获只保存地址，
能够识别悬垂风险时 warning 并传播 unsafe；仍不宣称内存安全。

Rust 也把闭包描述成包含捕获字段的匿名类型，但它可以根据正文自动选择捕获方式。
Xe 明确要求列出捕获项，避免读者猜测哪些外部变量被保存。
参考：[Rust 闭包类型](https://doc.rust-lang.org/reference/types/closure.html)。

## 两种不同的结构

管道参数绑定只存在于 `|>`、`1>`、`2>`、`:>` 后，例如 `1> value: i32 -> value + 1`。
它立即处理本次输入，不创建可返回的闭包。真正的匿名函数必须以 `fn` 开头：

```xe
let increment = fn(value: i32) -> i32 { value + 1 };
let result = increment(41);
```

匿名函数复用普通函数的参数列表、返回类型和块正文。`->` 是结构分隔符，不是任意二元
运算符。参数可以依靠明确的预期函数签名推导，否则必须标注。省略返回类型表示 Unit。
具名声明 `fn[T] name(...)` 的附件声明泛型；匿名表达式 `fn[captures](...)` 的附件表示捕获。
匿名函数可以使用外层已知类型参数，但不能声明自己的独立类型泛型。

## 显式捕获：捕获什么，如何捕获

| 写法 | 闭包环境中的实际字段 | 正文里 `value` 的类型 | 创建闭包时发生什么 |
| --- | --- | --- | --- |
| `fn[value]` | `T` | `T`（独立的拥有值） | Copy 值复制；资源所有权移入环境 |
| `fn[value@]` | `T@` | `T`（只读别名） | 保存原变量的地址，不拥有所指对象 |
| `fn[value@[mut]]` | `T@[mut]` | `T`（可写别名） | 保存原变量的可写地址；来源必须可写，但允许别名 |

捕获列表中的 `@` 作用于原变量，决定**怎样保存它**；它不会悄悄改变正文中
同名变量的类型。编译器通过隐藏字段里的地址访问原变量。因此外部
`value: T` 被 `fn[value@]` 捕获后，正文里的 `value` 仍是 `T`；
`value@` 仍产生 `T@`，`value#` 则只有在 `T` 本身就是指针时才合法。
这与普通表达式 `value@: T@` 的类型规则一致，也避免为了修改外部整数写
`value# = value# + 1`。

区分“借用一个已有指针变量”和“按值捕获指针”很重要：若 `p: T@`，
`fn[p]` 的环境字段和正文里的 `p` 都是 `T@`，正文依旧用 `p#` 访问目标；
`fn[p@]` 的环境字段是 `T@@`，正文里的 `p` 仍是 `T@`。
按值捕获一个已有指针只复制指针，不获得其所指资源的所有权。
通过地址捕获的别名不拥有原变量，不能把非 Copy 资源从中移走，
也不会延长原变量的生命期；可能悬垂时按普通指针规则警告。

捕获列表只接受已有局部名字和地址附件，按列表顺序各求值一次。同名重复捕获、捕获名
与参数重名都报错。正文不能隐式使用未捕获的外部局部变量；模块函数及模块级绑定不需捕获。
要保留原资源，先显式 clone，再捕获副本，不隐藏复制：

```xe
let original << String::from("hello");
let copied << original.clone();
let callback << fn[copied]() { println("{}", copied@); };
callback();
callback();
println("{}", original@);
```

## 调用统一写 f(...)，不要求手动借用闭包

调用闭包与对象调用方法一样：接收者是闭包自身，括号里才是显式参数。
`f(x)` **不等于**把 f 当成一个按值参数传走。调用方式由正文实际对环境的操作决定：

| 正文对捕获环境的操作 | f(...) 的接收方式 | 调用之后 |
| --- | --- | --- |
| 只读取字段 | 只读访问环境 | 环境保留，可以重复调用 |
| 修改字段或其拥有资源 | 可写访问环境 | 环境保留；f 存储需可写，可以重复调用 |
| 移出非 Copy 捕获资源 | 接收环境所有权 | 环境被消耗，只能调用一次 |

这一点参考 Rust 的 Fn / FnMut / FnOnce 区分，但当前 Xe 没有加入三个公共 Trait。
捕获方式与调用能力不是同一件事：拥有 String 的闭包若只读取它，仍能重复调用。
参考：[Rust 调用能力](https://doc.rust-lang.org/reference/types/closure.html#call-traits-and-coercions)。

```xe
let current = 0;
let[mut] advance << fn[current]() -> i32 {
    current = current + 1;
    current
};
println("{} {}", advance(), advance()); // 1 2
println("{}", current);                // 外部副本仍为 0
```

环境字段是闭包内部状态，允许修改；外部闭包存储的 `let[mut]` 表示允许这种可写调用。
闭包作为函数参数仍遵守普通参数规则：参数绑定只读，需要可写调用时传 `F@[mut]`，
或者把收到的环境移动到新的 `let[mut]` 局部存储。临时闭包有自己的可写临时环境。

```xe
fn[F] twice(callback: F@[mut]) -> i32 {
    callback() + callback()
}
```

通过可写地址捕获修改**外部变量**，不等于修改闭包自己的隐藏指针字段：

```xe
let[mut] current = 0;
let advance << fn[current@[mut]]() -> i32 {
    current = current + 1;
    current
};
advance();
advance();
println("{}", current); // 2；advance 本身不需要可写绑定
```

反之，若先定义 `let p: i32@[mut] = current@[mut];`，再以 `fn[p]`
按值捕获指针，闭包正文的 `p` 仍是 `i32@[mut]`；此时应写 `p# = p# + 1`。

显式 `(f@)(x)` 和 `(f@[mut])(x)` 仍可用作普通指针调用，但不是日常调用要求。
只读指针不能调用会写环境的闭包；任何非拥有指针都不能调用会移出环境资源的闭包。
这里不引入独占借用规则，多个可写指针仍遵循 Xe 的普通指针约定。

按值函数参数、捕获、`<<` / `>>` 和管道**输入**依旧按类型转移或复制。管道的函数目标
则使用上述接收者规则：`value |> f` 转交 value，并不无条件转交 f。
新鲜闭包不实现 Copy，即使所有捕获字段都是 Copy；声明和转交整体使用 `<<` / `>>`。

## 资源清理与一次性调用

```xe
let owned << String::from("hello");
let take << fn[owned]() -> String { owned };
let text << take();     // 正文把拥有资源交出，因此消耗 take
println("{}", text);   // text 成为新拥有者
// take();             // 错误：环境已被消耗
```

未调用的闭包、可重复调用的闭包，在所属 block 结束时清理捕获资源。
一次性调用中未移出的资源在调用结束时清理；被移出的资源由接收者清理。
提前 return、break、continue 也遵守恰好一次析构。指针捕获不会释放所指对象。
普通闭包没有通用的“产生下一个元素”概念，不能依据其返回数值来决定销毁它。
返回 `Step::Stop` 结束迭代的约定仅属于迭代器协议，详见第 26 章。

## 在分支中返回闭包与类型边界

```xe
fn main() {
    let callback << positive(40)?
        1> base: i32 -> { fn[base](x: i32) -> i32 { base + x } }
        2> _ -> { return; };
    println("{}", callback(2));
}
```

分支处理参数立即执行，返回的闭包之后才执行。返回已有函数写 `1> _ -> foo`；
`1> foo` 则调用 foo。以上片段的 positive 定义与完整示例见 closure_capture.xe。

命名函数和无捕获匿名函数是 Copy 函数值，类型可写 `fn(i32) -> i32`。
每个捕获闭包表达式有独立匿名具体类型；同签名的两个捕获表达式也不能隐式合并。
局部通过类型推导使用它，泛型 `fn[F]` 可以接收具体闭包并生成静态调用。
外层泛型的不同具体实例拥有各自正确的环境布局，不共享错误的捕获字段类型。
当前未实现公共 Call Trait、动态装箱/类型擦除、任意闭包签名类型或自动堆分配；
不能用 `fn(...) -> T` 类型冒充带环境的闭包，也不宣称完整 Rust 闭包 API 已实现。

## 维护实现

`ClosureInfo` 保存字段类型、调用能力与返回地址来源；用户 AST 不被改写。
C 后端为具体环境生成结构体和隐藏调用函数，复用结构体字段的移动/部分移动及清理标记。
函数代码、环境布局、接收者调用方式、资源清理是四件独立的事，分开测试更容易排查。
真实执行测试覆盖重复调用、状态更新、资源转交、嵌套闭包、泛型及提前退出；
普通指针风险示例只检查 warning 并编译，不运行已知悬垂地址。
闭包调用有有限的捕获失效摘要：捕获 String 的追加/替换可使调用者旧视图标 unsafe，
新视图对应调用后的存储；数值计数器更新不会无故让其字段地址失效。
这不是完整副作用系统，经过任意具名函数包装或复杂间接别名仍可能漏掉风险提示。
