# 处理函数、匿名函数与闭包

状态：普通处理参数和无捕获函数值已实现；**有捕获闭包暂缓（DEFERRED）**。
以下捕获、具体类型和单次调用是历史草案，不构成当前新增实现承诺；重新启动闭包设计时
必须按普通指针模型审核，不能重新引入独占借用作为默认指针语义。

## 两种不同的结构

管道参数绑定只存在于 |>、1>、2>、:> 后：

```xe
1> value: i32 -> value + 1
```

它为这次调用的输入建立局部名称并立即计算正文，不产生可返回的闭包对象。
所有真正的匿名函数表达式都必须以 fn 开头：

```xe
let increment = fn(value: i32) -> i32 { value + 1 };
let result = increment(41);
```

匿名函数复用普通函数的 () 参数列表、-> 返回类型和块正文。-> 是结构分隔符，
不是可任意出现在表达式中的二元运算符。无捕获匿名函数可以推导参数类型，但缺少预期
签名时必须标注；省略返回类型统一表示 Unit，不推导一个不同的返回类型。

## 显式捕获附件

捕获外部局部变量时，在 fn 后使用 [] 列出，禁止隐式捕获：

具名声明 `fn[T: Trait] name(...)` 的附件是泛型；
匿名表达式 `fn[captures](...)` 的附件只表示捕获。
首版不支持匿名函数声明独立的类型泛型。匿名函数可以引用外层函数的类型参数，
但每个实例的参数类型仍固定。这不影响普通闭包、回调及泛型函数接收回调的后续设计。

```xe
let base: i32 = 40;
let add_base << fn[base](value: i32) -> i32 { base + value };
let answer = add_base(2);
```

每个捕获项使用已经声明的变量名及可选运算修饰：

- fn[value]：捕获拥有值，Copy 复制，资源移动进入闭包；
- fn[value@]：表达式意义的取地址，捕获共享指针；
- fn[value@[mut]]：捕获可写普通指针，必须具有可写来源，但不要求独占；
- 非拥有指针按值捕获仍是非拥有指针，不获得所指资源所有权。

[] 是函数捕获附件，不是函数调用参数或模式绑定。捕获只能引用已有局部存储位置，
按列表顺序求值且各项恰好一次；同名重复捕获报错。闭包正文中同名捕获表示捕获后的值，
不会隐式重新取外层变量。模块函数和常量不需要捕获。

## 在分支中返回函数或闭包

```xe
let callback << operation()?
    1> value: i32 -> {
        fn[value](x: i32) -> i32 { value + x }
    }
    2> error -> {
        eprintln("{}", error@);
        return;
    };
```

上述代码位于返回 Unit 的函数内：失败提前返回，成功得到一个闭包。
分支处理函数被调用一次，返回的闭包还没有被调用；之后 callback(2) 才执行闭包正文。
返回已有函数写 1> _ -> foo；写 1> foo 则是执行 foo。

## 首版调用与类型边界

命名函数和无捕获匿名函数是可复制的函数值，函数指针类型写 fn(i32) -> i32。
有捕获闭包各自拥有一个编译器生成的具体类型，局部用类型推导；泛型接收者通过编译器
提供的 CallOnce[参数元组, 返回类型] 静态调用约束使用它，不需要运行时反射或虚表。

有捕获闭包一律是非 Copy 类型，即使捕获项全部可复制；声明和传递使用 <<，不能用 =。
捕获环境按实际字段保存，编译器可以使用栈或返回值存储，不要求统一堆分配。

为保持第一版简单，有捕获闭包调用时按值消耗闭包，允许将捕获资源转交给其他函数；
未转交的资源在调用结束时析构。闭包未调用就离开作用域，也自动析构捕获资源。
无捕获函数值可重复调用。多次调用同一个拥有捕获的闭包以及借用式调用协议属于后续扩展，
不暗中推导复杂调用能力。

指针捕获不会延长所指资源生命；能够识别逃逸风险时 warning 并传播 unsafe。
类型、写权限与资源所有权仍检查，不要求独占区域证明。

不同捕获闭包即使签名相同，也不是同一具体类型；首版不隐式装箱统一分支类型。
可先让分支产生一个同类型数据，再在分支外构造一个闭包，或只让其中一个分支继续执行。
动态闭包容器、多个闭包的公共运行时表示和反复调用协议不属于首次自举要求。
立即执行的参数绑定可以直接降低为局部绑定和正文，不存在这些闭包存储问题。

## 捕获与普通参数传递一致

按值捕获取得该值：资源转移所有权，Copy 基本值复制。没有隐式 clone。
需要两个独立资源时先显式克隆，再捕获新资源：

```xe
let original: String << String::from("hello");
let copied: String << original.clone();
let callback << fn[copied]() { println("{}", copied); };
println("{}", original@); // original 未被捕获
callback();              // 消耗闭包及其中的 copied
```

fn[...] 当前只接受已有名字及借用附件，不直接接受 a.clone() 这种调用表达式。
用局部名字保存克隆结果使捕获内容及所有权更容易观察。

## 实现闭包难在哪里

闭包可以理解为“生成的函数 + 保存捕获值的结构体”，通常无需堆分配。
普通函数只有调用参数；闭包函数还需要收到自己的捕获环境。
主要工作是环境布局、按值/借用捕获初始化、调用环境的传递，以及未调用/调用完成/
提前退出时环境资源的恰好一次析构。借用环境还必须检查逃逸。
这是可以按普通结构体和函数逐步实现的工程工作，不要求复杂的编译器理论。

当前语义检查已按每个捕获闭包表达式标记独立具体类型、检查捕获移动与单次调用。
C 后端已运行普通函数值和无捕获 fn，但尚未生成捕获环境；有捕获闭包构建程序会得到
明确能力诊断，不能称为已运行支持。
