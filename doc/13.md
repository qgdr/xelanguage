# 标准库边界与工具链

## 标准库分层

标准库分成四层，避免所有功能互相依赖：

```text
core      不需要分配和操作系统：基本 Trait、范围、Maybe
alloc     需要分配器：Box、String、Vec、Map、Arena
std       文件、路径、环境变量、进程、时间、标准输入输出
platform  对各操作系统 ABI 的小型封装
```

`core` 和大部分 `alloc` 最终使用 Xe 编写。`platform` 可以调用少量稳定 C ABI。不同平台只
替换最底层封装，语言和上层标准库保持一致。

编译器自举至少需要：

- `String`、`str`、`Vec[T]`、`Slice[T]`、`Map[K, V]`、`Set[T]`；
- `Arena[T]` 和稳定的整数 ID；
- UTF-8 解码、文件、路径、命令行参数和缓冲输入输出；
- 排序、哈希、结果处理和基础格式化；
- 用于调用系统 C ABI 的外部接口。

## Prelude

每个模块只自动导入一个很小的 `core::prelude`，包括基本 Trait 和常用范围。
`Maybe::Yes`、`Maybe::No`、`Maybe::None` 使用完整名称访问。文件、网络、进程等能力
必须显式 `use`，让依赖在源码中可见。

## 格式化

`println`、`print` 和 `format` 的格式字符串必须是编译期字符串字面量。编译器会检查
占位符数量和参数类型，避免把格式错误留到运行时：

```xe
var text: String << String::from("hello");
println("text = {}", text@);
println("buffer = {:p}", text.as_str().data());
```

- `{}` 使用 `Display`，面向普通用户；
- `{:?}` 使用 `Debug`，面向调试；
- `{:p}` 只接受安全借用或裸指针，并输出地址。

格式化参数与普通函数参数遵守完全相同的所有权规则：`Copy` 值被复制，移动类型按值传入
时被移动，显式写 `value@` 才建立共享借用。因此上例第一条输出不会移动 `text`；如果写成
`println("text = {}", text);`，`text` 会被移动并在调用结束时析构。

编译器只对格式字符串的占位符做静态检查，不改写参数的所有权。标准库为 `T@` 提供条件
实现：当 `T` 实现 `Display` 或 `Debug` 时，相应的借用也能格式化。需要运行时格式字符串
时，显式使用返回错误的 `std::fmt::write_dynamic`，使动态解析成本和失败路径保持可见。

## 外部接口

```xe
extern "C" {
    fn malloc(size: usize) -> RawPtr[u8];
    fn free(pointer: RawPtr[u8]);
}
```

外部函数只能使用具有稳定布局的类型。裸指针调用和平台约束必须封装在标准库内部；普通
业务代码不直接依赖这些接口。

## 统一命令

```text
xe check   只分析，不生成程序
xe build   构建包
xe run     构建并运行默认程序
xe test    运行单元、集成和文档测试
xe fmt     使用官方格式化规则改写源码
xe lint    检查可维护性问题
xe doc     生成 API 文档
xe clean   删除 target/ 中的生成物
```

## 面向人类和 AI 的工程接口

AI 不需要专用语言语法；它更需要稳定、可验证的工具接口：

- `xe check --message-format=json` 输出错误代码、源码范围、关联位置和可选修复编辑；
- 错误代码稳定，例如 `XE-TYPE-0003`，文档可以链接到详细解释；
- `xe fmt` 产生确定格式，减少无意义差异；
- `xe doc` 读取 `///` 项目注释和 `//!` 模块注释，并执行其中的 Xe 示例；
- 编译器提供语言服务器所需的名称、类型、引用和重命名查询；
- 构建结果记录编译器、edition、目标平台和锁文件版本；
- 生成代码放入清楚标记的目录，不与人工源文件混写。

## 注释与可维护性

```xe
//! 词法分析模块：把 UTF-8 源码转换为带位置的 Token。

/// 返回下一个 Token。
///
/// 遇到非法 UTF-8 或无法识别的字符时返回诊断；不会跳过错误位置。
pub fn next(self: Lexer@[mut]) -> Token?[Diagnostic] {
    // 这里记录 token_start，因为后面的循环会推进当前位置。
    let token_start = self.position;
    // ...
}
```

注释应解释“不变量、原因、所有权和错误恢复策略”，而不是逐字复述代码。编译器各层必须有
简短架构说明，复杂数据结构旁必须记录它保持的条件。这样既方便没有系统训练的维护者，也
能让 AI 在修改前获得正确上下文。
