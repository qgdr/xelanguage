# 标准库边界与工具链

## 标准库分层

标准库分成四层，避免所有功能互相依赖：

```text
core      不需要分配和操作系统：基本 Trait、范围、Maybe
alloc     需要分配器：Box、String、Vec、Map、Arena
std       文件、路径、环境变量、进程、时间、标准输入输出
platform  对各操作系统 ABI 的小型封装
```

`core` 和大部分 `alloc` 最终使用 Xe 编写。`platform` 可以调用少量稳定 C ABI。不同平台只
替换最底层封装，语言和上层标准库保持一致。

编译器自举至少需要：

- `String`、`str`、`Vec[T]`、`Slice[T]`、`Map[K, V]`、`Set[T]`；
- `Arena[T]` 和稳定的整数 ID；
- UTF-8 解码、文件、路径、命令行参数和缓冲输入输出；
- 排序、哈希、结果处理和基础格式化；
- 用于调用系统 C ABI 的外部接口。

## Prelude

目标模块系统只自动导入一个很小的 `core::prelude`，包括基本 Trait 和常用范围。
`Maybe::Yes`、`Maybe::No`、`Maybe::None` 使用完整名称访问；结果返回位置另支持成功值和
无负载 `None` 简写，由预期类型解释，不是通配符导入。文件、网络、进程等能力
在目标模块系统中显式 `use`，让依赖在源码中可见。

当前单文件 stage0 预先声明 `print`、`println` 和 `readline`，也登记相同的 `std::io::` 路径。
这是已经声明的标准 IO 接口，不是 `use` 模块加载已经实现；当前无需写导入语句。
实现位于 [stdlib/io/xe_io.h](../stdlib/io/xe_io.h)，暂由 C 支撑，仍未完成 Xe 版完整标准库。
具体合同、EOF/错误区分及命令行例子见 [第 24 章](24.md)。

`std::env::args()` 已提供进程参数读取，返回 `Slice[str]?[io::Error]`，包含程序名。
成功参数视图只读且可复制，在整个 Xe main（含 Drop）执行期间有效。
UTF-8 验证及分配失败返回错误，不重新解释 shell 已经拆分的参数。
这同样是 stage0 预先登记的接口，不表示模块加载已实现；
最小参数打印工具和运行方法见 [第 25 章](25.md)。

`std::iter::from_fn` 已登记为保存回调的拉取迭代器：回调返回 `Step[T]`，
`Step::Item[value]` 产生元素，首次 `Step::Stop` 后不再调用回调。
`Step[T]` 是预置类型，不是当前可导入的独立 Xe 标准库源码。
它复用显式捕获环境，不要求堆分配，也没有新增 yield 语法。
自定义 next 协议、拥有/指针 for 以及资源清理见 [第 26 章](26.md)。

## 标准输入

`readline()` 返回 `String??[io::Error]`：外层区分读成功与 IO 失败，成功时内层再区分
拥有的一行 String 与正常 EOF。空行是 `Yes[String]` 中长度为零的 String，不是 EOF。
每次 `?` 只处理一层，程序明确决定失败恢复或退出。

读取前刷新 stdout；去掉 LF/CRLF 行结束符，保留 EOF 前没有换行的最后一行。
输入验证 UTF-8，并按长度保存 NUL。String 所有权由读调用交给程序，按正常规则析构。

## 格式化

`println`、`print` 和 `format` 的格式字符串必须是编译期字符串字面量。编译器会检查
占位符数量和参数类型，避免把格式错误留到运行时：

```xe
let[mut] text: String << String::from("hello");
println("text = {}", text@);
println("buffer = {:p}", text.as_str().data());
```

- `{}` 使用 `Display`，面向普通用户；
- `{:?}` 使用 `Debug`，面向调试；
- `{:p}` 只接受普通指针，并输出地址；[unsafe] 注记不改变其运行时布局。

格式化参数与普通函数参数遵守完全相同的所有权规则：`Copy` 值被复制，移动类型按值传入
时被移动，显式写 `value@` 才传递只读指针。因此上例第一条输出不会移动 `text`；如果写成
`println("text = {}", text);`，`text` 会被移动并在调用结束时析构。

编译器只对格式字符串的占位符做静态检查，不改写参数的所有权。标准库为 `T@` 提供条件
实现：当 `T` 实现 `Display` 或 `Debug` 时，相应的只读指针也能格式化。需要运行时格式字符串
时，显式使用返回错误的 `std::fmt::write_dynamic`，使动态解析成本和失败路径保持可见。

## 外部接口

```xe
extern "C" {
    fn malloc(size: usize) -> u8@[mut, unsafe]?;
    fn free(pointer: u8@[mut, unsafe]);
}
```

外部函数只能使用具有稳定布局的类型。上述为目标包装接口：分配失败用可选指针表达，
平台层负责将 C 的空指针转换为 None，不能假定当前已有该 ABI 映射。
unsafe 是可传播的指针风险注记，不改变 ABI、不增加权限或所有权。free 的调用者必须保证
地址来自对应分配器、尚未释放、不是栈地址；参数是地址不等于拥有值，重复释放无法靠
这个签名自动阻止。推荐平台层封装契约；外部 ABI 尚未接入当前后端。

## 统一命令

```text
xe check   只分析，不生成程序
xe build   构建包
xe run     构建并运行默认程序
xe test    运行单元、集成和文档测试
xe fmt     使用官方格式化规则改写源码
xe lint    检查可维护性问题
xe doc     生成 API 文档
xe clean   删除 target/ 中的生成物
```

## 面向人类和 AI 的工程接口

AI 不需要专用语言语法；它更需要稳定、可验证的工具接口：

- `xe check --message-format=json` 输出错误代码、源码范围、关联位置和可选修复编辑；
- 错误代码稳定，例如 `XE-TYPE-0003`，文档可以链接到详细解释；
- `xe fmt` 产生确定格式，减少无意义差异；
- `xe doc` 读取 `///` 项目注释和 `//!` 模块注释，并执行其中的 Xe 示例；
- 编译器提供语言服务器所需的名称、类型、引用和重命名查询；
- 构建结果记录编译器、edition、目标平台和锁文件版本；
- 生成代码放入清楚标记的目录，不与人工源文件混写。

## 注释与可维护性

```xe
//! 词法分析模块：把 UTF-8 源码转换为带位置的 Token。

/// 返回下一个 Token。
///
/// 遇到非法 UTF-8 或无法识别的字符时返回诊断；不会跳过错误位置。
pub fn next(self: Lexer@[mut]) -> Token?[Diagnostic] {
    // 这里记录 token_start，因为后面的循环会推进当前位置。
    let token_start = self.position;
    // ...
}
```

注释应解释“不变量、原因、所有权和错误恢复策略”，而不是逐字复述代码。编译器各层必须有
简短架构说明，复杂数据结构旁必须记录它保持的条件。这样既方便没有系统训练的维护者，也
能让 AI 在修改前获得正确上下文。
