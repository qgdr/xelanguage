# tuple 元组、解包与透明类型别名

0.9 使用 `tuple[...]` 表示元组，使用 `type Name = Type;` 为已有类型取一个短名字。
这些语法沿用已有的 Copy、移动、写权限和自动析构规则。冻结契约见第 17 章，
实际通过解析、语义和运行验收的范围由测试确认。

## 先区分类型与值

元组按位置保存多个成员，成员可以有不同类型：

```xe
fn coordinates() -> tuple[i32, i32] {
    tuple[10, 20]
}

fn main() {
    let point: tuple[i32, i32] = coordinates();
    println("{} {}", point.0, point.1);
}
```

`tuple[i32, i32]` 出现在类型位置，列出成员类型；`tuple[10, 20]` 出现在值位置，
列出成员表达式。成员从左到右求值，`.0`、`.1` 等位置索引继续可用。
单元素类型写 `tuple[i32]`，单元素值写 `tuple[42]`，不需要逗号帮助区分代码块。
尾随逗号可用于排版，但不改变成员个数。

本轮不增加空元组：`tuple[]` 拒绝。无内容的值仍写 `unit`，类型是 `Unit`。
花括号继续用于代码块、结构体字面量、声明和分支正文，不再表示元组。

## 用 let 解包为新变量

```xe
let tuple[x, y] = coordinates();
let tuple[left: i32, right: i32] = coordinates();
```

`let` 表明目标是新的变量，元组的第一个成员交给第一个名字，第二个成员交给第二个名字。
成员数量必须一致，不允许静默截断或自动补成员。每个名字可以独立标注类型，
未标注的成员从对应源类型推导。

`let[mut]` 照常允许之后重新赋值：

```xe
let[mut] tuple[x, y] = coordinates();
x = x + 1;
```

附件修饰新绑定的可变性，不会使成员获得 Copy 能力，也不会把只读指针变成可写指针。
本轮只增加逐位置浅层解包；成员自身是元组时，可以先取得该成员，再写下一次解包。
元组解包不属于枚举选择器，不会给 `?` 增加递归模式展开。

## 写入已有变量

没有 `let` 时，目标必须已经存在，遵守普通初始化和重新赋值规则：

```xe
let[mut] x = 0;
let[mut] y = 0;
tuple[x, y] = coordinates();
tuple[30, 40] >> tuple[x, y];
```

已经初始化的不可变绑定不能重新赋值。目标数量和类型也要逐成员检查。
右侧只求值一次，先取得源元组，再按位置交给各目标；不会为每个名字重新调用一次函数。
目标中的名字表示已有存储，也可以写 `tuple[x: i32, y: i32] = coordinates();` 校验成员类型；
这不会创建新变量或改变已有存储的类型。

解包后逐个转交成员，因此成员上的 `i32@[mut]` 可以降为目标的 `i32@`。
例如源类型是 `tuple[i32@[mut], i32]`，`let tuple[p: i32@, number] = source;` 合法；
经 `p#` 不能写入所指对象。现成整个元组不能直接赋给 `tuple[i32@, i32]`，
组合类型参数仍保持不变；解包是取出成员分别转换，不是让元组整体协变。

## Copy、资源与忽略成员

元组只有所有成员都 Copy 时才 Copy。`=` 复制这样的源，原元组仍可使用；
任何成员拥有不可复制资源时，整个元组都需要移动，使用 `<<`。
`>>` 继续按源的 Copy 资格选择复制或移动，没有另加隐式克隆规则。

```xe
fn messages() -> tuple[String, String] {
    tuple[String::from("hello"), String::from("world")]
}

fn main() {
    let tuple[first: String, second: String] << messages();
    println("{} {}", first@, second@);

    let tuple[kept, _] << messages();
    println("{}", kept@);
}
```

`_` 不创建变量，也不能读取；它仅说明不接收对应成员。被忽略的拥有资源仍按普通规则
自动 drop，不能为了省略名字而泄漏。移动到新变量的资源由新变量在作用域退出时清理，
源元组不能再重复释放。写入已有资源变量时，其旧值同样按正常替换规则清理。

不可复制资源不能用 `=` 解包，也不能通过非拥有指针的解引用取得所有权。
类型别名、`unsafe` 注记和可写地址都不会绕过这些检查。

## 用 type 为类型取名

```xe
type Number = i32;
type Point = tuple[Number, Number];
type handler = fn(i32) -> i32;
type Text = String;

fn next(value: Number) -> Number { value + 1 }

fn main() {
    let callback: handler = next;
    let point: Point = tuple[10, 20];
    let text: Text << String::from("hello");
    println("{} {} {}", point.0, callback(41), text@);
}
```

`type Number = i32;` 创建透明别名：`Number` 与 `i32` 是同一种类型，可以在参数、返回值、
字段和局部类型标注中互换。别名不需要包装或拆包，不增加运行时对象和新的名义类型身份。
`handler` 可以使用小写名称；类型位置决定它的作用，不靠首字母大小写猜测。

别名可以指向基础类型、指针、函数、元组、结果类型或已经具体代入的用户类型。
用户类型的透明别名也可作为构造与关联调用中的类型限定名，如 `PointAlias { ... }`、
`PointAlias::new(...)`；方法仍来自原类型，不生成一套新实现。
`Text` 与 `String` 同样不可复制；`type Writable = i32@[mut];` 也不会为只读来源授予 mut。
给未实现 Copy 的用户结构体取别名，不会替它实现 Copy。

当前别名只允许在模块顶层声明，没有局部别名或泛型别名语法。
例如不接受 `type[T] Pair = tuple[T, T];`；需要泛型类型族时仍使用具名 struct/enum 声明。

## 前向引用、链与错误

```xe
type Coordinate = Number;
type Number = i32;
```

别名允许先引用后声明的类型，别名链最终展开到实际类型。
直接或经指针附件绕回同一别名都属于循环；具名结构体通过指针引用自身则仍是有限布局。
编译器仍会验证最终目标的名称、参数个数与类型语法，不用“未知类型”跳过检查。
重复声明和循环别名是错误，应指出涉及的源码声明，不能递归到编译器崩溃：
循环使用 `XE-TYPE-0007` 报告引用链，未知目标和重复名称使用既有名称诊断。

```xe
// 失败示例：没有最终的实际类型。
type First = Second;
type Second = First;
```

## 从旧代码迁移

| 0.8 写法 | 0.9 写法 |
| --- | --- |
| `{i32, i32}` 元组类型 | `tuple[i32, i32]` |
| `{10, 20}` 元组值 | `tuple[10, 20]` |
| `{i32,}` 单元素类型 | `tuple[i32]` |
| `{42,}` 单元素值 | `tuple[42]` |
| 名为 tuple 的普通函数 | 更名为 make_tuple 等非关键字名称 |

旧元组应给出迁移提示，不能静默把它解释为另一种代码。
`{ calculate() }` 仍是块表达式，`Point { .x = 10; }` 仍是结构体字面量，
`Event::Pair[10, 20]` 仍是枚举负载构造；这些花括号和附件无需机械替换。

验收样例位于 `tests/backend/tuples.xe`、`tests/backend/type_aliases.xe`，
已有泛型及指针元组样例也采用 0.9 写法。运行时需要实际验证右侧求值次数、
资源解包/替换/忽略的 Drop 次数，以及类型别名不会改变 Copy 或写权限。
