# 静态 Trait 与条件 Copy/Drop

本章使用已有 `trait`、`impl`、`fn[T: Trait]`、`where T implements Trait` 语法，
不增加新符号。契约检查、具体实例检查和 C 后端直接调用均已实现。

## Trait 是行为契约，不是数据类型

```xe
trait Measure {
    fn measure(self: Self@) -> i32;
    fn doubled(self: Self@) -> i32 { self.measure() * 2 }
}

struct Point { value: i32, }

impl Measure for Point {
    fn measure(self: Self@) -> i32 { self.value }
}

fn[T: Measure] inspect(value: T@) -> i32 { value.doubled() }

fn main() {
    let point << Point { .value = 21; };
    println("{}", inspect(point@)); // 42
}
```

没有正文的方法必须提供；有正文的方法在没有覆盖时采用默认实现。实现中不能添加
契约未声明的方法，普通额外方法放在 `impl Point { ... }` 中。
参数类型、指针写权限、返回类型、`self` 接收器和方法自身的泛型约束必须与声明一致。
仅存在同名普通方法还不够：`T: Measure` 要求真正的 `impl Measure for T`。

在调用处已经知道 `T = Point`，编译器生成直接调用，不创建虚表，不在运行时查找实现。
`Measure` 本身不能作为参数或字段的数据类型；动态 Trait 对象尚未设计。

Trait 自己也可以附带类型参数：

```xe
trait[T] Read { fn read(self: Self@) -> T; }

struct[T] Holder { value: T, }

impl[T] Read[T] for Holder[T] where T implements Copy {
    fn read(self: Self@) -> T { self.value }
}

fn[T: Read[i32]] number(value: T@) -> i32 { value.read() }
```

这里 `Read[i32]` 是行为契约的类型附件，而不是新数据布局。
约束可以引用具体类型或泛型参数，不要求第二通道类型一定为错误类型。

## Copy 的资格按具体类型判断

```xe
struct[T] Holder { value: T, }
impl[T] Copy for Holder[T] where T implements Copy {}
```

这条声明的含义是：满足 `T: Copy` 时，`Holder[T]` 才能复制。
`Holder[i32]` 是 Copy，`Holder[String]` 不是。也可以只承诺一个具体实例：

```xe
impl Copy for Holder[i32];
```

这两种实现不要同时声明，因为它们在 `Holder[i32]` 上重叠。
用户结构体和枚举仍必须显式实现 Copy；基本字段不会自动授予复制资格。
编译器验证每个真实字段/负载的 Copy 能力，无约束的
`impl[T] Copy for Holder[T]` 会报错。泛型指针字段 `T@` 本身 Copy，不要求 `T: Copy`。

`=` 仍然仅复制，`<<` 仍然仅移动不可复制值，`>>` 根据具体类型资格复制或移动。
泛型调用实例的正文重新执行同一套规则，不因模板阶段通过就跳过资源检查。

## 泛型 Drop 也是普通的具体函数

```xe
struct[T] Tracked { value: T, }

impl[T] Drop for Tracked[T] {
    fn drop(self: Self@[mut]) { println("release wrapper"); }
}

fn main() {
    let tracked << Tracked[String] { String::from("owned") >> .value; };
    println("{}", tracked.value@);
} // 先运行 Tracked[String] 的 drop，再清理 value 的 String
```

语义检查器发现拥有的具体类型后，实例化析构函数并检查正文。若正文对 `T = String`
执行不合法操作，编译失败；后端不能偷偷生成一份未经检查的析构代码。
同一具体实例复用缓存。Box/Vec 的元素、枚举活动负载、嵌套结构体沿用同一清理路径。

也可在 `impl` 的 `where` 中限制 Drop 的适用实例。是否禁止移出资源字段取决于该
具体实例是否真的实现 Drop，而不是只看结构体族的名称。
已经实现自定义 Drop 的具体对象不能移出资源字段/枚举载荷，因为 Drop 需要完整对象。
Copy 与 Drop 的实现目标不能重叠；对互不重叠的具体实例可以分别实现。

## 当前明确边界

- 不支持动态 Trait 对象、关联类型、父 Trait 和运行时虚表。
- 不允许重叠实现或特化；不能依赖声明先后顺序挑选实现。
- 普通方法表仍以类型族和方法名组织。同一类型族的多个 impl 若提供同名方法会明确报错，
  包括不同 Trait 的同名方法；当前没有需要用户猜测的隐式消歧规则。
- 完整多态证明不是当前目标：未使用的泛型正文在具体实例实际需要时检查；契约的
  类型、约束名称和方法形状仍在声明收集阶段验证。
- 普通指针不是资源所有者；静态 Trait 不改变 `p#` 的所有权，也不提供内存安全保证。

维护入口是 `compiler/xe_ast/semantic_traits.py`：注册实现、检查约束、验证方法契约、
证明条件 Copy、登记具体 Drop。调用和后端只消费这些已检查结果，不各自再猜一遍规则。

```sh
uv run --frozen --offline python -m unittest compiler.tests.test_static_traits
make run SOURCE=tests/language/trait_dispatch.xe
```
