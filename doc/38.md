# Xe 1.0 候选版：发布契约与收尾

状态：`1.0.0-rc.1`，语法标识 `xe-1.0`，AST JSON schema 1。

这次收尾不新增语法。将已经批准、能够实际生成程序的功能划入应用开发范围，
将未来语法和低层平台目标从当前承诺中分开。完整的范围、兼容约定、安装、
验收、候选包以及转稳定版的步骤统一维护在 [RELEASE.md](../RELEASE.md)，
变更摘要见 [CHANGELOG.md](../CHANGELOG.md)，避免两份发布清单相互漂移。

本轮实际工作包括：

- 统一 CLI、AST、Python 项目和依赖锁中的版本信息；保留 AST schema 1。
- 按用户选择加入 Apache-2.0 许可证与 NOTICE。
- 将旧 unsafe 块、未实现占位内建、格式化能力和错误 self 声明的阶段差异补成
  前端诊断；保留普通指针风险 warning 后仍可编译的约定。
- 为 stage0 生成程序的基础运行时失败增加 Xe 文件/行/列位置；用线程局部存储
  隔离诊断上下文，不宣称完整栈回溯、C 外部错误或任意悬垂地址都可被定位。
- 提供源码候选包、逐文件哈希、包校验、干净临时目录编译运行与统一验收入口；
  CI 只验收，不上传或自动发布。
- 正式候选源码用 --require-clean 逐文件绑定 Git HEAD；开发包明确标记工作树快照。
- 合法用例与早期历史样例分开，忽略生成物/本地凭据，提供结构和贡献说明；
  AGENTS.md 成为独立项目也可阅读的核心实现契约，不擅自固定未审核设计。

运行位置记录由 AST 源码范围生成，不改变用户变量类型，也不改变 AST JSON。
记录在调用潜在失败的运行时助手之前更新，函数内部的操作会更新为自己的位置；
没有映射的独立 C 或自举子集入口仍可能只报告运行时消息。
它不捕获 C 段错误，不提供异常展开，也不改变 `?[panic]` 的资源清理承诺。

候选包可以记录未提交工作树的准确内容，不能冒充对应 Git 提交的稳定发布。
SHA-256 只校验内容是否一致，不提供发布者身份认证。
公开稳定版需要提交经过验收的源码、核对该提交 CI，再明确决定标签与外部发布；
发布工具本身不执行这些外部动作；维护者提交/标签/同步须有用户明确授权。
