# 第一个 Xe 自举编译器：实现与写作经验

这是实际编写、运行后的工程记录，不是新的语言规范。已有规则仍以此前已审核章节为准。
`bootstrap/compiler.xe` 已经完成自编译子集；完整 Xe 0.9 尚未移植。复现命令及逐项范围
见 [bootstrap/README](../bootstrap/README.md)。本章不宣称超越 OCaml/Rust 的整体性能或体验。

## 自举到底完成了什么

Python stage0 编译这份 Xe 源码得到 seed；seed 解析并编译同一份源码生成第一代 C，
第一代 Xe 可执行程序再生成第二代，第二代生成第三代。三代 C 按字节相等，sanitizer
版本自编译也产生相同 C。此后的解析、AST、检查和发射都执行 Xe 编译成的程序，
不是让 Python 偷做一部分前端。

系统 cc 负责 C → 可执行文件，C 运行库负责文件/分配等平台操作。Python 驱动负责启动
工具、比较文件、写报告。证明的是**这个子集编译器能编译自身**，不是完整规范、全部
标准库、全部工具均由 Xe 实现；固定点也不是正确性的充分条件。

测试因此另外比较合法程序与 Python 参考实现的运行结果，比较 seed/三代/sanitizer
编译器的输出与拒绝诊断，并实际执行新编译器编译出的文件工具。递归、短路、实参求值
顺序、指针别名、资源字段移动、循环清理、UTF-8/NUL、算术失败和有限文件描述符都被覆盖。
ASan/UBSan 保留默认泄漏检测，它们是检验手段，不是内存安全证明。

## 为什么这样组织数据

```text
main 拥有原始 String（整个编译期间不修改、不释放）
  └─ Program 拥有 Vec 表
       ├─ Token：源码 str 视图 + 位置
       ├─ Node：种类、子节点 ID、类型 ID
       ├─ edges：变长子节点列表
       ├─ types / fields / parameters：类型和成员
       └─ functions / constants：顶层声明
          ↑
       Generator 通过 Program@[mut] 使用这些表
       自己拥有 output String、symbols、moved_fields
```

树并不一定要写成一堆互相拥有的堆指针。节点统一存在 Vec 中，子节点保存整数 ID；
Vec 扩容会搬动元素，但不会改变先前节点的下标。需要读节点时复制一个显式 Copy 的
小记录，需要改节点时通过表索引写入。绝不长期保存 Vec 元素地址。

Token 的 text 指向不可变的原始源码，不指向输出缓冲区或临时 String。main 的 source
保持存活，因此这些视图有明确的人工可审查来源。warning 没有被关闭；stage0 对跨结构
来源仍有保守 warning，报告保留它们。实际正常执行通过 sanitizer，但不能据此认为
所有未来改动也正确；尤其不能在解析过程中修改 source 导致地址失效。

## 源码导航

| 入口 | 负责什么 | 修改时应保留的不变量 |
| --- | --- | --- |
| lex | 分词，保存位置，处理注释/字符串 | UTF-8 内容不被截断，EOF 可定位，不把字符串当代码 |
| parse_type / parse_expression / parse_block / parse | 类型、表达式、块和顶层 AST | 先按语法建节点，操作符优先级明确，不使用类型猜另一种语法 |
| compound / find_type | 类型表与组合类型复用 | 相同组合复用 ID，Copy 与写权限沿类型保存 |
| infer / require_type / call_type | 类型、名称、函数签名与写权限 | C 编译器不是 Xe 类型错误的兜底检查器 |
| consume / owned_place / writable_place | 所有权与合法存储位置 | 指针访问不授予资源拥有权，Copy 不被当成移动 |
| emit_expression / snapshot / emit_call | 表达式和调用发射 | 临时变量明确规定从左到右求值，不依赖 C 实参顺序 |
| emit_block / emit_if / emit_statement | 分支、作用域与提前退出 | 清理只覆盖退出的作用域，分支状态保守合并 |
| cleanup / finish_temporaries / emit_drop_function | 资源清理 | 已移动值不重复释放，分号结束临时资源，嵌套容器递归清理 |
| define_type / prototype / compile | 布局、声明及最终 C | 先收集用到的类型，再按依赖发射布局，保留函数前向调用 |
| main | 输入输出和 CLI | 完成检查及 C 生成后才打开输出，source 最后仍存活 |

首版采用简单递归下降和优先级解析，没有引入生成器/闭包、复杂优化或机器码算法。
语义检查与发射共用 Generator；这样易跑通，但以后职责扩大时宜拆分类型结果与发射状态，
保持独立检查可测试，而不是让所有新功能继续塞入一个巨大函数。

## 从实际源码归纳的 Xe 写作方式

### 1. 大对象拥有，小描述符复制

```xe
struct Token { kind: i32, text: str, line: usize, column: usize, }
impl Copy for Token;

fn add_node(p: Program@[mut], value: Node) -> usize {
    let id = p.nodes.len();
    p.nodes.push(value);
    id
}
```

Token、Node、Field 等只保存标签、视图、ID；显式 Copy 后用 `=`，不把 `<<` 写成万能赋值。
Program、Vec、String 拥有资源，不实现 Copy；创建/返回它们用移动。记录是否能复制可以
从字段和 impl 两处核对，没有隐式复制缓冲区。

类型和节点标签也统一用 `let`，如 `let N_NAME: i32 = 1;`，不另造常量声明关键字。
这里的模块级绑定在编译期确定，不进行顶层运行时初始化；两个前端都将它记入已有
编译期只读值表。内部的 Constant 名称只是 AST/记录分类，不是源码需要的新语法。
当前子集只接收有类型的 Copy 字面量，模块级可变绑定和资源存储尚不支持。

这些 ID 暂为 usize 而非受保护的新类型，误把类型 ID 当节点 ID 不能被类型系统发现。
这是首版选择的维护弱点，不是所有 ID 都应该一直裸用整数。透明 type 别名能改善名字，
但不会成为名义上的不同类型；后续可用包装结构体区分不同 ID，不需要发明新语法。

### 2. 用参数签名说明改谁

```xe
fn at(p: Program@, text: str) -> bool { peek(p).text == text }
fn put(g: Generator@[mut], text: str) { g.output.push_str(text); }
```

只看签名就知道第一段只读访问，第二段会修改 Generator。`p.field` 越过一层指针是已经
确认的便利约定；它没有把 p 改成 Program，也没有把字段资源授予该指针拥有。
普通指针可复制、可别名，因此连续调用 `put(g, ...)` 无须引入独占借用或“再次借用”模型。
但如果另外保存元素地址，自己必须分析扩容和释放；语法简单并不会消除这项责任。

### 3. 函数返回值组合步骤，局部 let 给读者命名

```xe
let source << read_source(input);
let[mut] program << new_program(input, lex(input, source.as_str()));
parse(program@[mut]);
let generated << compile(program@[mut]);
```

这里所有源内容都由 source 拥有，Program 保留视图，compile 返回自己的输出资源。
没有隐式全局状态、深复制或引用计数。短纯函数可以用尾表达式，大步骤用局部名字解释
中间结果；资源创建与语法分析分开，便于检查异常路径。

不要为了“优雅”把每一步都挤进长管道。本实现用普通函数/块已能自举，管道未来应在
确实降低阅读负担时使用。递归/优先级处理保留参数名字，比仅堆叠符号更好维护。

### 4. 字符串视图与拥有字符串分工

读入文件用 String，Token 保存 str，输出集中 append 到一个 String。扫描 byte_at，
保存边界，确认边界后 slice_bytes。这避免为每个单词独立分配，也能直接处理嵌入 NUL。
编译器仍须区分“字节”“Unicode 字符”“终端显示列”：首版列号是字节，不假装显示列。
不要对任意两个字节先构造 str 再识别注释符，否则可能把 UTF-8 切在字符中间。

### 5. 资源检查与代码发射也采用可解释的实现

C 实参顺序不确定，所以 snapshot 每个 Xe 实参；短路右侧放在条件块中。资源移出后
把其 C 描述符清零，空 String/Vec/File 可安全析构；分号后清理临时资源，退出块按逆序
清理局部变量。这样不用 GC 就可以让读者沿源码追踪正常释放。

“移后清零”只适用于本子集的内建资源及默认成员析构，是后端实现办法，不是用户可以
读取 moved 变量的许可，也不能直接推广到任意用户 Drop。下一阶段自定义 Drop 必须
改用准确的初始化/活性标志；panic 的 Drop 保证仍遵守现有语言边界。

## 实践显示的优势和不足

优势不是对其他语言的空泛排名，而是这次实际能用上的组合：

- 类型/地址/权限同一套后置记号，函数签名就能说明状态操作；容器元素类型不被偷偷变成指针。
- Copy 小记录 + Vec/ID + str 源码视图，构建 AST 不必先实现 GC 或共享指针，也不必写复杂的生命周期类型。
- 显式资源传递与块清理让源码缓冲、表、输出文件各有拥有者；main 的处理链容易讲给初学者。
- 块表达式和类型化函数让递归解析器直接返回 AST ID，无需大量输出参数；具体 C 输出可检视求值与清理。
- 相同源码完成固定点且编译真实文件工具，证明这些约定已能支撑一个不止 hello 的底层编译应用。

不足也很具体：

- 首版 AST 的 kind 用命名整数常量，不是代数数据类型：完整 Xe 已有枚举，但尚未移植到自举前端；
  参考实现对一般枚举相等/通用 Trait 也有限制。补枚举与分支检查，才更接近类型化 AST 的良好体验。
- 输出 C 要大量 put/put_number，线性查找符号/类型也尚未优化；不是 OCaml 式数据处理的性能或简洁度证据。
  可先封装小发射函数、补容器查询，最后依据实际 profiling 决定优化，不先发明宏系统。
  本次长布尔表达式曾暴露 infer 反复检查左子树造成的指数耗时；已去掉这次重复递归并加
  长链回归。没有用全局类型缓存绕过名字的移动状态检查，也没有改短路语义。
- 普通指针与视图必须遵守 owner 存活、Vec 地址不可跨扩容的不变量，学习成本没有消失，只是从
  复杂借用规则移到数据设计。风险 warning 仍需改善，不能用 sanitizer 替代分析。
- 新前端诊断还较粗，type mismatch 缺期望/实际类型展开；只有首错，尚无 JSON AST/check-only/
  多文件加载。首版单文件便于审查固定点，但不宜成为整个工具链的最终结构。
- 保守资源流、数字边界和库支持仍会拒绝某些有效 Xe；自举成功只说明子集闭环，不证明完整规范闭环。

以上主要是实现缺口，不需要立即更改既定语法。当前没有为自举偷偷加入语法或自动改变
变量类型。如果未来需要能力与原规定冲突，应先用小程序展示冲突再商议，不以编译器
实现便利强迫用户接受。

## 下一步按阻塞程度推进

1. 改进诊断类型展示、补 AST 输出和独立检查入口，保持跨代正反例一致。
2. 移植 enum/分支与类型别名，替换弱类型 kind，补完整资源活性和自定义 Drop。
3. 移植模块加载，按 lex/parser/types/ownership/emit/driver 拆分单文件，不改变语义。
4. 逐步覆盖用户泛型/方法、容器与其他 0.9 功能，再决定默认编译器切换。
5. 新编译器全量通过当前回归后才讨论替换 Python；进程启动、FFI、布局等未审核接口另行讨论。

暂不为完成率或“最优”作承诺。每增加能力，都要同时给出源码、失败诊断、可执行程序和
自编译链，才能把一次成功自举逐步变成可维护的完整 Xe 工具链。
