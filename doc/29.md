# Shared、Weak、Mutex 与 Thread

状态：接口和语义已由用户审核确认。沿用 Bootstrap Syntax 0.9 的类型附件、
普通指针、方法、显式捕获和作用域析构，不新增运算符或公开 Send/Sync Trait。
当前 Python/C 后端已实现；stage0 平台为 POSIX，使用 C11 原子和 pthread。

## 三种不同的职责

| 能力 | 接口 | 负责什么 |
| --- | --- | --- |
| 拥有对象 | Box[T] / Shared[T] | 决定 T 何时析构 |
| 判断存活 | Weak[T] | 不延长 T 的生命，尝试取得一个 Shared |
| 同步读写 | Mutex[T] / MutexGuard[T] | 让持锁线程访问受保护的数据 |
| 执行与等待 | Thread[T] | 在线程中执行一次函数，并交付 T |

原子引用计数只保护拥有者计数，不自动保护 T 的数据，也不会把 T 中的
外部地址变安全。Xe 仍不宣称内存安全或静态证明所有数据竞争不存在。

## Shared：显式增加共同拥有者

```xe
fn main() {
    let first << Shared[String]::new(String::from("hello"))?[panic];
    let second << first.share();
    println("{}", second.ptr());
}
```

Shared 始终不可 Copy，`let other = first;` 报错，即使 T 是 i32。
`<<` 移动一个现有句柄，不增加计数；`share()` 增加一个指向同一 T 的拥有者，
不复制 T。最后一个 Shared 结束时，T 恰好析构一次。

接口概要（不是额外的用户声明）：

```text
Shared[T]::new(value: T) -> Shared[T]?[AllocError]
share(self: Self@) -> Shared[T]
weak(self: Self@) -> Weak[T]
ptr(self: Self@) -> T@
```

new 按普通参数规则先复制/移动 T，再尝试分配。数据或控制块分配失败时，
输入的拥有资源在进入调用者的失败分支前恰好 drop 一次，与 Box 的契约一致。
引用计数溢出明确终止，不能环绕成零。share/weak 不另外分配控制块。

`first@ : Shared[T]@` 指向句柄，`first.ptr() : T@` 指向堆对象。
不支持 first#、隐式字段转发、ptr_mut 或隐式深复制。
通过 Shared 修改数据使用下一节的 Mutex，而不是把只读 T@ 升为可写指针。
普通指针不延长生命；共享句柄移动或析构后，风险分析仍可能保守警告，
不能把警告当成运行时一定失效的证明。

## Weak：对象不能复活

```xe
fn main() {
    let observer << {
        let owner << Shared[i32]::new(42)?[panic];
        owner.weak()
    };
    observer.upgrade()?
        1> owner: Shared[i32] -> println("{}", owner.ptr()#)
        2> error: Expired -> println("{}", error);
}
```

```text
share(self: Weak[T]@) -> Weak[T]
upgrade(self: Weak[T]@) -> Shared[T]?[Expired]
```

Weak 也不可 Copy；weak.share() 增加弱句柄，不增加 T 的拥有者数量。
upgrade 成功时原子地取得一个新的 Shared，失败时返回 No[Expired]，不能复活已析构的 T。
Expired 是可复制的无负载标记，格式化显示 `shared object expired`，不是“E 必须是错误”的规定。

Weak 只保留管理信息；T 在最后一个强拥有者结束时立即析构。
最后一个弱句柄结束后管理信息也释放。Weak 不直接提供 ptr()。
强引用环不会自动回收；树的父到子可以用 Shared，子到父用 Weak 打断环。

## Mutex：锁赋予访问受保护内容的权限

```xe
fn main() {
    let counter << Shared[Mutex[i32]]::new(Mutex[i32]::new(0)?[panic])?[panic];
    {
        let[mut] guard << counter.ptr().lock()?[panic];
        let value: i32@[mut] = guard.ptr_mut();
        value# = value# + 1;
    }; // 块表达式语句用 ; 结束；guard 自动解锁。
    let guard << counter.ptr().lock()?[panic];
    println("{}", guard.ptr()#);
}
```

```text
Mutex[T]::new(value: T) -> Mutex[T]?[SyncError]
lock(self: Mutex[T]@) -> MutexGuard[T]?[SyncError]
ptr(self: MutexGuard[T]@) -> T@
ptr_mut(self: MutexGuard[T]@[mut]) -> T@[mut]
```

Mutex 和 MutexGuard 均不可 Copy。Mutex 的内部锁和 T 都放在稳定的堆存储中，
移动描述符不复制系统锁。构造失败按普通资源参数规则清理输入。
SyncError 是不可直接改写内部表示的可复制错误值，当前格式化为系统错误说明。

lock 使用只读 Mutex@，但产生一个新的拥有资源 Guard。这个显式同步接口
提供的是“持锁访问 T”的权限，不是普通指针的隐式可写权限提升。
Guard 的可写绑定才可以 ptr_mut；只读 Guard 只能 ptr。
Guard 保持锁和 T 存活，即使原来的 Mutex 句柄已结束。

Guard 的正常析构自动解锁，return / break / continue / ?[return] 也遵守作用域清理。
Guard 必须在加锁线程释放：直接跨线程捕获、包装进 Box/Shared/结构体后捕获、
或作为线程结果，均报 XE-THREAD-0002。仅仅返回 Guard 的函数值不是 Guard 资源，
可以把这样的工厂函数传入线程，在该线程内部创建和释放它的 Guard。

从 Guard 取出的 T@/T@[mut] 不会保持锁存活；释放 Guard 后继续使用这些地址
不再受同步保护。可识别的逃逸风险仍给 warning，不宣称地址检查完整。
Mutex 不是递归锁；重复锁住同一个对象、持锁等待另一个需要该锁的线程，可能死锁。
锁状态和数据完整性不同：没有 Rust 式 poisoning 或异常展开恢复机制。

## Thread：拥有捕获，执行一次，显式等待

```xe
fn main() {
    let text << String::from("worker");
    let task << Thread[String]::spawn(fn[text]() -> String { text })?[panic];
    let output << task.join()?[panic];
    println("{}", output);
}
```

```text
Thread[T]::spawn(callback) -> Thread[T]?[ThreadError]
join(self: Thread[T]) -> T?[ThreadError]
```

callback 必须是无参数、返回 T 的函数值或拥有闭包。它的具体类型可以推导，
不要求用户给 Thread 附加第二个“闭包类型”参数，也不新增动态闭包类型擦除语法。
Thread 取得闭包所有权，新线程调用一次；该次执行结束后清理未移出的捕获资源。
创建线程或分配环境失败时，在调用者线程清理输入闭包，返回 No[ThreadError]。
ThreadError 同样为可复制的系统错误值，显示系统错误说明。

join 消耗句柄，等待线程执行及捕获清理完成，再取得 T 的拥有权。
未显式 join 的句柄在自动析构时也等待，并 drop 未取出的 T。没有公共 detach 接口。
这意味着裸写 spawn(...)?[panic]; 会在该语句的临时资源结束时等待，
想并行工作应保存 Thread 句柄，稍后 join。
正常 POSIX 拥有句柄的 join 返回 Yes；自等待或外部破坏句柄导致的系统 join 失败，
当前运行库明确终止，而不释放仍在运行的环境或偷偷 detach。不是完整的线程故障恢复协议。

普通指针/非拥有视图的跨线程捕获与返回仍合法，但会保守 warning：
join 建立执行完成的同步关系，不延长栈变量或被析构捕获的生命。
该分析不等同于 Send/Sync Trait，不保证发现所有间接访问或数据竞争。
panic 当前终止整个进程，不是可捕获的子线程异常；不会通过 join 返回 panic 负载。

### 加锁共享计数器

完整程序在 `examples/threads/main.xe`，两个线程各累加 1000 次，输出：

```text
completed=2000 counter=2000
```

运行 `make thread-demo`。构建和审核自动为使用这些接口的生成 C 添加 -pthread；
独立编译 make emit-c 的产物时也应使用 `cc -std=c11 -pthread ...`。
并发 print/println 的整条消息目前不保证原子输出，多个线程的消息可能交错。

## 实现与验收

- `semantic_sync.py`：普通参数规则、线程签名、Guard 线程归属和指针风险；
- `backend_sync.py`：类型化描述符、分配成功/失败、闭包环境和线程结果降低；
- `stdlib/sync/xe_sync.h`：原子计数、弱升级、系统锁、线程创建与等待；
- `test_sync.py`：真实线程、并发升级、资源清理、失败注入及 ASan/UBSan 检测。

Shared/Weak/Mutex/MutexGuard/Thread 和标记类型当前使用简短内建标准名称，
不承诺尚未登记的 std::sync / std::thread 导入路径。
首版不增加 RwLock、条件变量、原子数值 API、Send/Sync Trait、后台线程、用户可选内存序、
异步或多线程静态安全证明。平台层可替换，不把 pthread 实现宣称为所有平台均可用。
