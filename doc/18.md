# 语义检查：当前实现与维护说明

状态：已实现第一版参考检查器，不是完整的自举编译器或安全证明。
不改变第 17 章的冻结语法和 AST JSON v1。解析、语义检查、代码生成是不同阶段。
当前发布承诺见 [发布契约](../RELEASE.md) 与 [第 38 章](38.md)；
后续资源/模式、Trait、C ABI、位操作的细化见 [第 34](34.md)、[35](35.md)、
[36](36.md)、[37](37.md) 章。不要用早期实现计划替代当前能力边界。

当前语法版本为 xe-1.0：元组写 tuple[...]，类型别名写 type Name = Type;；
具名函数写 fn[T: Copy] name(...)；
旧 `fn name[T](...)` 被拒绝并提示迁移。内联约束保存到既有 constraints 列表，
因此语义检查器使用同一套约束检查逻辑，无需区分约束来自附件还是 where。

## 使用

在仓库根目录运行，共用根目录 uv 环境：

```sh
# 只解析：语义错误程序也可能成功输出 AST，这是正常的。
make ast SOURCE=tests/fails/borrow_match_move.xe

# 类型、初始化、所有权、写权限检查；指针风险 warning。
make check SOURCE=tests/fails/borrow_match_move.xe

# 兼容命令，与 make check 检查范围相同。
make check-safety SOURCE=tests/language/pointer_alias.xe
make check-safety SOURCE=tests/language/enum.xe

# 全部 AST、语义与命令行回归测试。
make compiler-test

# 机器可读诊断，不生成 AST。
make check SOURCE=tests/warnings/return_local_pointer.xe CHECK_FLAGS="--diagnostic-format json"
```

成功退出 0，源码错误退出 1，文件读写或编码错误退出 2。
诊断仍使用原始源码的 span；error 阻断编译，warning 不阻断。JSON 语义报告区分严重级别，
包含可推导类型信息，使自动附加的 unsafe 可观察；原始 AST 不伪造用户写过的附件。
语法阶段报告第一个错误；语义阶段每个函数报告第一个主错误，并继续检查其他函数。
顶层声明有错误时停止，避免用损坏的声明制造大量误报。

## 已实现

- 可达模块顶层声明及局部作用域；名称、字段、变体、重复声明和静态可见性检查。
- 显式类型及局部推导；参数个数、普通参数类型、返回类型、条件 bool 检查。
- 基础数值、范围、数组/元组、结构体、枚举、函数类型；整数常量范围检查。
- `T?`、`T?[E]`、返回位置的成功值/None 简写、显式 Yes/No 构造、
  两通道、相同 `No` 负载类型的 `?[return]` 与明确的 `?[panic]`。
- 命名变体、字面量、通配分支；穷尽性、重复/不可达分支和载荷参数检查。
- 共享及可写借用匹配；所有载荷统一为指针，包括 str/Slice 视图描述符。
- Copy 资格、资源移动、移动后使用、部分字段移动；从非拥有指针转送资源始终禁止。
- 分支继续路径的初始化/移动状态合并；已返回路径不污染后续路径；
  保守拒绝循环重复移动外层资源。
- 根据 self 类型的统一方法接收者规则；格式化没有特殊隐式借用。
- 无捕获函数、显式捕获闭包、捕获资源移动与方法式只读/可写/一次性调用。
- next(self: Self@[mut]) -> Step[T] 迭代协议，拥有或可写指针 for，from_fn 回调签名检查。
- 泛型函数显式应用及实参推导、静态 Trait 约束、具体函数体检查与实例缓存；
  泛型结构体/枚举字段与载荷代入、泛型 impl 方法和关联函数。
- T@ / T@[mut] 是 Copy 普通指针，允许别名和重复调用，不要求独占或再次借用。
- T@[mut] 向 T@ 的浅层单向权限转换；初始化、传参、返回都适用，反向拒绝。
- 局部地址/视图逃逸、对象失效、临时来源等可识别风险 warning 并传播 unsafe；
  数组元素地址仍依赖数组存储，不因元素是整数而忽略地址风险。
- tuple[...] 元组与逐元素上下文推导、类型括号分组、无损 as 和整数 try_from 的范围检查规则。
- tuple 解包的声明/赋值、逐成员类型标注和 _；源类型决定复制/移动，右侧只求值一次。
- 顶层透明类型别名、前向引用/链展开、重复/循环/未知目标诊断；别名不授予 Copy 或写权限。
- 已登记的 prelude / std::io::print、println、readline 接口；输入返回 `String??[io::Error]`，
  输出沿用格式字符串与普通参数所有权检查，不插入隐式借用。
- `=` 仅复制、`<<` 仅转移不可复制的值；`>>` 按 Copy 资格复制或移动。
- 用户结构体/枚举必须显式 impl Copy；不再自动实现纯基本值结构体 Copy。
- 捕获环境已接入 C 后端；具体泛型回调、重复状态调用和退出清理有实际执行测试。
- Drop/Copy 互斥及自定义 Drop 类型的资源字段/载荷抽取限制。
- 用户 Trait 方法契约、默认方法与静态分派；泛型 Trait 附件、条件 Copy 和具体 Drop 实例。

标准接口目前是显式类型白名单，集中在 builtin_call / method：
String::from、len、as_str、clone、push_str，范围切片，File::open/size/read_to_string，
结果 expect 和格式化等；标准 IO 的共同接口表位于 `stdlib_io.py`。
上述主要接口已由小型 C 运行库及 stdlib/io 执行，但还不是完整标准库；
Vec[T]、bytes/chars、String 构造及文件写入也已执行；接口和模块加载见第 27 章。
完整命名区域、Map/Set 等仍需扩展；Box 的拥有堆对象与普通指针接口见第 28 章。
扩展接口时必须补签名和正反例，不以 Any 或未知函数吞掉类型错误。

## 检查器怎样工作

`typesys.py` 保存不可变的语义 Type，与源码 AST 分离。
`semantic.py` 中的 Checker 先 collect 收集声明，再逐个 check_function 检查函数。
infer 计算表达式类型；convert 检查上下文类型；consume 记录资源转交；
scope_escape/escape 记录可识别的指针风险；branch/merge 合并所有继续路径。

每个变量有独立 uid，而不是只靠名字追踪所有权。Binding 保存初始化、移动字段、
借用来源和最后使用位置。Value 保存类型、存储位置及来源；因此 p# 即使表面类型是 String，
仍标记为非拥有值，不能传给 consume(String)。输入的外部区域与参数自己的栈存储分开记录。

分支检查复制变量状态，各路径独立检查，最后合并：
初始化必须每条继续路径都成立；移动只要任一路径发生就视为已移动。
这是一版易读的参考算法；后续控制流 IR 可替换内部算法，但必须保留相同回归测试。

增加规则时先写失败测试，再定位 infer/call/branch/consume 等相应入口，
通过 fail 生成统一 Diagnostic。新增 tests/fails 用例须登记准确的错误编号；
语义反例要先通过 parse_source，避免实际测到另一个语法错误。

本地函数会记录“哪些输入参数可能影响返回视图”的摘要，按实际依赖传播直到集合稳定；
不能凭函数数量限制轮数，递归轮换参数可能需要更多轮。失败传播同样检查错误负载来源。
这些摘要改善风险来源精度，不替代完整安全证明；最终报告应保留风险 warning 和 unsafe
传播，不能只做试探阶段，也不能重新用独占借用规则禁止合法指针别名。

结构体/方法/Trait 专项测试位于 compiler/tests/test_data_declarations.py：
struct_create.xe 覆盖字段初始化、嵌套与空结构；
struct_methods.xe 覆盖关联函数、共享/可写/拥有接收者和指针方法调用；
trait_copy_drop.xe 覆盖 Copy 标记与 Drop 方法。
对应 tests/fails/struct_*、method_*、trait_* 断言具体诊断编号。
tests/language/trait_dispatch.xe 验证自定义 Trait 的解析与静态分派；
compiler/tests/test_static_traits.py 检查契约、条件 Copy、泛型 Drop 和实际运行清理。

## 明确边界

普通指针可以发生悬垂、非法地址和别名错误；Xe 不宣称内存安全，也不要求程序提供完整
区域证明。风险分析是可维护的基础参考实现，能够遗漏或保守报告；没有 warning 不等于
没有风险。数组元素地址按来源对象追踪，而不是要求不同索引证明互不重叠。
捕获闭包运行规则见第 15 章；拉取迭代器见第 26 章。动态闭包与 yield 状态机尚未实现。

命名区域的完整语义、注册表依赖/锁文件、动态 Trait 对象、关联类型和重叠特化、
浮点到整数等受控转换尚未完成；
遇到这些使用位置给出 XE-SEM-0001 或相应能力诊断，不静默变成可执行实现。
组合、元组和直接负载过滤的一层模式已实现，元组处理器收到整个元组，
不是解包后的多个成员；递归选择器和守卫仍不支持，见 [第 34 章](34.md)。
未实例化的泛型模板不能作为一等值；明确实例 identity[i32] 可以作为普通函数值。
静态 Trait 与条件泛型 Copy/Drop 的范围见 [第 35 章](35.md)；编译期值参数尚未完成，
不等于完整 Rust 式泛型系统。
历史阶段示例包含旧语法，不作为冻结版本全部通过的承诺。

语义检查本身不插入或执行 drop。新 C 后端已经为其支持的具体结构体、字符串和枚举提供实际
析构、提前返回清理、比较链及普通管道/分支匹配验收；通过系统 C 编译器及链接器生成可执行程序。
完整 HIR/MIR、完整标准库和完整语言自举仍未完成。子集自举固定点已实现，见第 31 章；
实际 stage0 后端范围见第 19 章。

泛型模板在使用时生成独立具体函数体，以具体 Copy/移动规则重新检查；原始 AST 保持不变。
新实例与返回来源摘要一起检查到稳定。同类型递归复用缓存，类型不断增长的实例化有数量限制。
模板内部的类型/所有权错误在使用该实例时报告，未使用的模板不会提前证明适用于所有类型。
这一实现选择和 C 生成过程见第 22 章；不是 Rust 式完整 Trait 体系的承诺。

原计划中的模块、C 后端与子集固定点已落实，不再作为当前缺失项。
后续可以改善风险 warning、分离有类型中间表示并扩展 Xe 子集前端，
但不为了架构重构重新定义已批准的资源、指针和调用语义。
