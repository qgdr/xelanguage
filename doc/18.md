# 单文件语义检查：当前实现与维护说明

状态：已实现第一版参考检查器，不是完整的自举编译器或安全证明。
不改变第 17 章的冻结语法和 AST JSON v1。解析、语义检查、代码生成是不同阶段。

当前语法版本为 xe-bootstrap-0.2：具名函数写 fn[T: Copy] name(...)；
旧 fn name[T](...) 被拒绝并提示迁移。内联约束保存到既有 constraints 列表，
因此语义检查器使用同一套约束检查逻辑，无需区分约束来自附件还是 where。

## 使用

在仓库根目录运行，共用根目录 uv 环境：

```sh
# 只解析：语义错误程序也可能成功输出 AST，这是正常的。
make ast SOURCE=tests/fails/borrow_match_move.xe

# 类型、初始化和资源所有权检查；默认指针类似 C。
make check SOURCE=tests/fails/borrow_match_move.xe

# 在前者基础上检查共享/可写能力、基础别名和生命周期。
make check-borrows SOURCE=tests/fails/borrow_alias.xe
make check-borrows SOURCE=tests/stage999/enum.xe

# 全部 AST、语义与命令行回归测试。
make compiler-test

# 机器可读诊断，不生成 AST。
make check-borrows SOURCE=tests/fails/borrow_alias.xe CHECK_FLAGS="--diagnostic-format json"
```

成功退出 0，源码错误退出 1，文件读写或编码错误退出 2。
JSON 诊断仍使用原始源码的 span；失败写 stderr，成功的空诊断数组写 stdout。
语法阶段报告第一个错误；语义阶段每个函数报告第一个主错误，并继续检查其他函数。
顶层声明有错误时停止，避免用损坏的声明制造大量误报。

## 已实现

- 单文件顶层声明及局部作用域；名称、字段、变体、重复声明检查。
- 显式类型及局部推导；参数个数、普通参数类型、返回类型、条件 bool 检查。
- 基础数值、范围、数组/元组、结构体、枚举、函数类型；整数常量范围检查。
- `T?`、`T?[E]`、返回位置的成功值/None 简写、显式 Yes/No 构造、
  两通道及相同错误类型的 `?[return]`。
- 命名变体、字面量、通配分支；穷尽性、重复/不可达分支和载荷参数检查。
- 共享及可写借用匹配；共享普通载荷为指针，str/Slice 视图按文档规则保留值表示。
- Copy 资格、资源移动、移动后使用、部分字段移动；从非拥有指针转送资源始终禁止。
- 分支继续路径的初始化/移动状态合并；已返回路径不污染后续路径；
  保守拒绝循环重复移动外层资源。
- 根据 self 类型的统一方法接收者规则；格式化没有特殊隐式借用。
- 无捕获函数、显式捕获闭包、捕获资源移动及闭包单次调用的静态检查。
- 直接泛型函数调用从实参推导类型及 Copy 约束；尚未生成实例化代码。
- 可选的基础借用互斥、最后使用、局部地址/视图逃逸及临时资源视图检查。
- Drop/Copy 互斥及自定义 Drop 类型的资源字段/载荷抽取限制。

标准接口目前是显式类型白名单，集中在 builtin_call / method：
String::from、len、as_str、clone、push_str，范围切片，File::open/size/read_to_string，
结果 expect 和格式化等。这只是接口类型模型，不是真正可执行的标准库。
扩展接口时必须补签名和正反例，不以 Any 或未知函数吞掉类型错误。

## 检查器怎样工作

`typesys.py` 保存不可变的语义 Type，与源码 AST 分离。
`semantic.py` 中的 Checker 先 collect 收集声明，再逐个 check_function 检查函数。
infer 计算表达式类型；convert 检查上下文类型；consume 记录资源转交；
scope_escape/escape 检查借用逃逸；branch/merge 合并所有继续路径。

每个变量有独立 uid，而不是只靠名字追踪所有权。Binding 保存初始化、移动字段、
借用来源和最后使用位置。Value 保存类型、存储位置及来源；因此 p# 即使表面类型是 String，
仍标记为非拥有值，不能传给 consume(String)。输入的外部区域与参数自己的栈存储分开记录。

分支检查复制变量状态，各路径独立检查，最后合并：
初始化必须每条继续路径都成立；移动只要任一路径发生就视为已移动。
这是一版易读的参考算法；后续控制流 IR 可替换内部算法，但必须保留相同回归测试。

增加规则时先写失败测试，再定位 infer/call/branch/consume 等相应入口，
通过 fail 生成统一 Diagnostic。新增 tests/fails 用例须登记准确的错误编号；
语义反例要先通过 parse_source，避免实际测到另一个语法错误。

结构体/方法/Trait 专项测试位于 compiler/tests/test_data_declarations.py：
struct_create.xe 覆盖字段初始化、嵌套与空结构；
struct_methods.xe 覆盖关联函数、共享/可写/拥有接收者和指针方法调用；
trait_copy_drop.xe 覆盖 Copy 标记与 Drop 方法。
对应 tests/fails/struct_*、method_*、trait_* 断言具体诊断编号。
tests/unsupported/trait_dispatch.xe 单独验证自定义 Trait 的解析与能力诊断，
不把“尚未实现”误称为语言本身非法。

## 明确边界

借用检查是保守的最后引用位置分析，不是完整 Rust 区域求解器，不能宣称所有接受的程序
已经获得完整内存安全保证。字段/数组位置、复杂循环、多输入返回来源及闭包共同类型
还需控制流 IR 和区域分析完善。闭包类型当前按签名表示，尚未实现捕获环境的独立名义类型。

命名区域、检查模式的多级指针、模块加载、通用 Trait 分派、泛型函数作为一等值、
显式泛型表达式应用、组合/元组/过滤模式、数值 as 转换等尚未完成；
遇到这些使用位置给出 XE-SEM-0001 或相应能力诊断，不静默变成可执行实现。
泛型方法和复杂泛型类型构造仍有边界，基础类型推导不等于完整泛型系统。
历史 stage00..stage904 示例包含旧语法，不作为冻结版本全部通过的承诺。

语义检查本身不插入或执行 drop。新 C 后端已经为其支持的结构体/字符串子集提供实际
析构、提前返回清理和比较链求值验收；通过系统 C 编译器及链接器生成可执行程序。
完整 HIR/MIR、完整标准库和自举产物仍未完成。实际后端范围见第 19 章。

后续顺序：模块和通用类型能力 → 有类型 HIR → 控制流 MIR/析构点 →
更准确的区域与借用检查 → C 后端和小运行库 → Xe 版编译器及自举固定点验收。
