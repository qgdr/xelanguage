# C 外部函数接口

本章落实已规定的 `extern "C" { fn ...; }`，不增加新的语言声明语法。
Python stage0 可以检查外部签名、生成 C 声明，并与显式提供的 C 源码、对象或库链接。
`bootstrap/` 自举子集暂未移植本功能。
仓库中可直接运行的对应示例见 [examples/ffi](../examples/ffi/README.md)。

```xe
extern "C" {
    fn native_add(a: i32, b: i32) -> i32;
    fn native_store(value: i32);
}

fn main() {
    let value = native_add(20, 22);
    native_store(value);
    println("{}", value);
}
```

对应的 C 文件使用相同符号和精确类型：

```c
#include <stdint.h>

static int32_t stored;
int32_t native_add(int32_t a, int32_t b) { return a + b; }
void native_store(int32_t value) { stored = value; }
```

保存为 `native.c` 后，可运行：

以下命令假定从仓库根运行，并先保存上面的 `main.xe`、`native.c`；这两个文件不是现成样例。
对象和库版本须先用系统 C 工具生成，再显式作为链接输入。
无需手写文件的现成示例可直接使用 `./xe run examples/ffi/main.xe --link-input examples/ffi/functions.c`。

```sh
./xe run main.xe --link-input native.c
uv run --project . --frozen --offline python compiler/main.py main.xe --run --link-input native.c
```

`--link-input` 可重复，按给定次序放在生成的 C 文件之后；相对路径以调用者当前目录为准。
工具接受 `.c`、`.o`、`.obj`、`.a`、`.so`、`.dylib` 和 `.lib` 的现有普通文件，具体格式仍须
与选择的 GCC/Clang 兼容工具链及目标平台一致。动态库运行时搜索路径由平台/链接选项管理。
统一入口 build/run/test 支持此选项，旧入口仅 build/run 支持。输入文件不能作为生成 C、
程序或收据的输出目标；链接失败保留已有程序。

外部 C 可以包含额外头文件，库也可以依赖其他库；当前不能登记它们的全部传递输入，
所以带 `--link-input` 的构建保守禁用缓存。收据记录显式链接文件的内容哈希，只清理工具
自己生成的程序/C文件，不把外部输入当产物。已有 `--cflag` 可补充 include、链接等选项。

## 支持的 ABI

| Xe 类型 | 外部 C 类型 |
| --- | --- |
| i8/i16/i32/i64，u8/u16/u32/u64 | 对应的 intN_t / uintN_t |
| isize / usize | intptr_t / size_t |
| f32 / f64 | float / double |
| bool | C bool（_Bool），不是任意整数布尔值 |
| char | uint32_t Unicode 标量，不是 C char |
| 上述类型的 T@ / T@[mut]，及嵌套指针 | 相应 C 指针；访问权限/unsafe 附件不改变 ABI |
| 函数返回 Unit，或省略返回类型 | C void；内部桥接函数交付 Xe Unit |
| fn(A, ...) -> R | 相同 C 函数指针；A/R 必须符合上述 ABI，R不能是Unit/Never |

具名外部函数也可以保存、传参或返回为普通 Xe `fn` 值。C void 返回经内部桥接转换为
Xe Unit；带捕获闭包不是 C 函数指针。由于普通 Xe fn 的 Unit 返回有内部占位值，
当前不接受 Unit/Never 返回的外部 callback，也不接受 Unit 参数。

外部函数符号使用原始 ASCII C 名称，不做 Xe 模块改名；同一符号在不同模块的声明必须
具有相同签名。C关键字、main、下划线开头及 xe_ 开头的保留名称会给出源码诊断，
可以在 C 包装函数中调用这些原接口。外部声明保持所在 Xe 模块的可见性；需要公开 API
时可提供 `pub fn` 包装。

参数/返回按值的 str、String、tuple、Array、Maybe/T?、用户聚合及拥有资源没有自动 C ABI。
指向这些 Xe 特有布局的指针也暂不接收；不能把 C 的 char* 当作 Xe str，或把可选指针
当作 C 的裸指针。需要通过标量、字节指针、长度及明确的 C/Xe 包装函数转换。
不支持可变参数、C结构体布局承诺、其他ABI、泛型外部函数或C导出库。

签名不支持使用 `XE-FFI-0001`，跨模块符号签名冲突使用 `XE-FFI-0002`，check与build
采用相同验证。外部实现是否遵守声明、指针有效性、同步及释放契约由包装层负责；
普通指针参数不转移拥有资源，也不延长对象生命期。外部返回地址沿用现有风险传播，
编译成功不能证明外部 C 不会发生内存错误。

从仓库根验收：`uv run --project . --frozen --offline python -m unittest compiler.tests.test_ffi -v`，包含真实 C 源码/对象链接、void
桥接、函数值、双向callback、指针、跨模块符号、非法ABI、输出保护及失败保留。
