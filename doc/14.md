# 词法与语法摘要

本章给出实现解析器所需的规范摘要。章节示例比这里的 EBNF 更容易阅读；两者冲突时应当先
修正文档，使二者保持一致。

## 词法

```text
identifier  = (letter | "_") (letter | digit | "_")* ;
integer     = decimal | "0x" hex+ | "0o" octal+ | "0b" binary+ ;
float       = decimal "." decimal (exponent)? ;
string      = '"' (escaped-character | non-quote-character)* '"' ;
character   = "'" (escaped-character | unicode-scalar) "'" ;
byte          = "b" character ;
line-comment  = "//" ... newline ;
block-comment = "/*" ... "*/" ;
doc-comment   = "///" ... newline | "//!" ... newline ;
```

块注释允许嵌套。源码必须是 UTF-8。换行不是语句结束符。

字节字面量复用字符字面量外形，但内容必须是 ASCII 字节或取值不超过 255 的转义。

核心关键字：

```text
let var const fn return if else while for in break continue
struct enum trait impl for where implements match
pub use as crate self super region extern unsafe
true false unit
```

## 名称、路径与字面量

```text
path-root = "crate" | "self" | "super" | identifier ;
path      = path-root ("::" identifier)* ;
literal   = integer | float | string | character | byte
          | "true" | "false" | "unit" ;
```

`crate`、`self`、`super` 只能出现在路径首段。普通名称和类型名称都使用同一条 `path` 规则。

## 模块项目

```text
module      = item* ;
item        = use-item
            | const-item
            | function-item
            | struct-item
            | enum-item
            | trait-item
            | impl-item
            | extern-item ;
visibility  = "pub"? ;
use-item    = "use" path ("as" identifier)? ";"
            | "use" path "::" "{" use-name ("," use-name)* ","? "}" ";" ;
use-name    = identifier ("as" identifier)? ;
extern-item = "extern" string "{" extern-function* "}" ;
extern-function = "fn" identifier "(" parameters? ")" ("->" type)? ";" ;
```

普通语句不能直接出现在模块顶层。

## 声明与函数

```text
binding     = ("let" | "var") identifier (":" type)?
              (("=" | "<<") expression)? ";" ;
const-item  = visibility "const" identifier ":" type "=" expression ";" ;
function-item = visibility "fn" identifier generic-params?
                "(" parameters? ")" ("->" type)? where-clause? block ;
parameters  = parameter ("," parameter)* ","? ;
parameter   = "var"? identifier ":" type ;
generic-params = "[" generic-param ("," generic-param)* ","? "]" ;
generic-param  = identifier | "region" identifier ;
where-clause   = "where" constraint ("," constraint)* ","? ;
constraint     = type "implements" path ;
```

## 类型

```text
type          = primary-type type-postfix* ;
primary-type  = path type-arguments?
              | "(" type ("," type)+ ")" ;
type-arguments = "[" generic-argument ("," generic-argument)* ","? "]" ;
generic-argument = type ;
type-postfix  = "@" borrow-modifier?
              | "?" ("[" type "]")? ;
borrow-modifier = "[" ("mut" ("," identifier)? | identifier) "]" ;
```

示例：`i32@`、`i32@[mut]`、`T@[r]`、`T@[mut, r]`、`T?[E]`、`Slice[T, r]`。

泛型实参中的裸名称先按普通类型路径解析，再根据声明的参数种类判定它代表类型还是区域；
因此语法分析器不需要为 `r` 增加上下文相关词法规则。

## 复合类型

枚举声明、构造和模式中的负载都使用 `[]`；无负载变体直接写名称，不加 `[]`。

```text
struct-item = visibility "struct" identifier generic-params?
              (";" | "{" field-decl* "}") ;
field-decl  = visibility identifier ":" type "," ;
enum-item   = visibility "enum" identifier generic-params?
              "{" variant-decl* "}" ;
variant-decl = identifier ("[" type-list "]")? "," ;
trait-item  = visibility "trait" identifier generic-params?
              "{" trait-member* "}" ;
impl-item   = "impl" generic-params?
              (type | path "for" type) where-clause?
              (";" | "{" impl-member* "}") ;
type-list    = type ("," type)* ","? ;
trait-member = visibility "fn" identifier generic-params?
               "(" parameters? ")" ("->" type)? where-clause?
               (";" | block) ;
impl-member  = function-item ;
```

## 语句与表达式

```text
block       = "{" statement* tail-expression? "}" ;
tail-expression = expression ;
statement   = binding
            | "return" expression? ";"
            | "break" ";"
            | "continue" ";"
            | assignment ";"
            | expression ";" ;
assignment  = place ("=" | "<<") expression
            | expression ">>" place ;
if-expression    = "if" expression block ("else" (if-expression | block))? ;
while-expression = "while" expression block ;
for-expression   = "for" pattern (":" type)? "in" expression block ;
match-expression = "match" expression "{" match-arm* "}" ;
match-arm        = pattern "->" expression "," ;
unsafe-expression = "unsafe" block ;
```

表达式按优先级包含：字面量、名称、元组、数组、结构体字面量、块、`if`、`match`、循环、
一元运算、二元运算、调用、字段、索引、借用、解引用、转换、管道和结果处理。

```text
struct-literal = path "{" field-init* "}" ;
field-init     = "." identifier ("=" | "<<") expression ";" ;
result-arm     = ("1>" | "2>")
                 (path | "->" expression
                 | pattern (":" type)? "->" expression) ;
```

普通表达式按照以下层级结合；越靠下绑定越紧：

```text
expression       = control-expression | pipe-expression ;
control-expression = if-expression | while-expression | for-expression
                   | match-expression | unsafe-expression ;
pipe-expression  = range-expression ("|>" pipe-target)* ;
range-expression = logical-or ( (".." | "..=") logical-or? )?
                 | (".." | "..=") logical-or? ;
logical-or       = logical-and ("or" logical-and)* ;
logical-and      = comparison ("and" comparison)* ;
comparison       = additive (("<" | "<=" | ">" | ">=" | "==" | "!=") additive)* ;
additive         = multiplicative (("+" | "-") multiplicative)* ;
multiplicative   = cast (("*" | "/" | "%") cast)* ;
cast             = unary ("as" ("[" ("checked" | "wrap") "]")? type)* ;
unary            = ("not" | "+" | "-") unary | postfix ;
postfix          = primary postfix-operation* ;
postfix-operation = arguments
                  | bracket-arguments
                  | "." identifier arguments?
                  | "@" borrow-modifier?
                  | "#"
                  | "?[return]"
                  | "?" result-arm result-arm ;
arguments        = "(" argument-list? ")" ;
bracket-arguments = "[" expression ("," expression)* ","? "]" ;
argument-list    = expression ("," expression)* ","? ;
pipe-target      = path | path "(" pipe-argument-list? ")" ;
pipe-argument-list = pipe-argument ("," pipe-argument)* ","? ;
pipe-argument    = expression | "_" ;
tuple            = "(" expression "," (expression ("," expression)* ","?)? ")" ;
array            = "[" (expression ("," expression)* ","?)? "]" ;
place            = path (("." identifier) | ("[" expression "]") | "#")* ;
primary          = literal | path | tuple | array | struct-literal | block
                 | "(" expression ")" ;
```

赋值不嵌入普通表达式，只能出现在语句位置；因此 `a = b = c` 不合法。范围最多含一个
`..`/`..=`。比较链可以混用 `<`、`<=`、`>`、`>=`、`==`、`!=`：`a == b == c` 检查
`a == b` 和 `b == c`。操作数从左到右求值且最多求值一次；某一对为假后不计算后续
操作数。`a != b != c` 只比较相邻两对。结果分流和 `?[return]` 是后置操作。

赋值左侧和 `@` 的操作数必须是 `place`，也就是能够稳定指向存储位置的名称、字段、索引或
解引用；需要借用复杂临时表达式时，先把它绑定到局部名称。

管道目标不带括号时，左值成为唯一参数；带括号时必须恰好出现一个 `_` 占位符。这个约束
由语义检查完成。

结果分流必须同时包含一个 `1>` 和一个 `2>`，顺序可以交换，不能重复。
`T?[E]` 的两个通道都带负载；`T?` 或 `T?[None]` 的 `2>` 没有负载，只能写
`2> -> expression` 或指向零参数函数。`None` 是 `?[None]` 内的无负载标记，不能用作普通
错误类型。通道是否允许绑定由被分流表达式的类型决定。

## 模式

```text
pattern        = simple-pattern ("|" simple-pattern)* ;
simple-pattern = "_"
               | literal
               | "(" pattern-list ")"
               | path ("[" pattern-list "]")? ;
pattern-list   = pattern ("," pattern)* ","? ;
```

## 解析与诊断要求

- 词法分析采用最长匹配，因此 `::`、`<<`、`>>`、`..=`、`?[`、`1>`、`2>` 等必须先于
  短符号识别；
- 解析器必须保留每个节点和标点的源码范围；
- 未闭合括号、缺少分号、错误字段初始化和遗漏结果通道应提供针对性诊断；
- `[]` 在类型位置表示类型参数或运算符修饰；在值位置，`Type::Variant[value]` 表示枚举
  负载，`object[index]` 表示索引。词法分析只识别方括号，名称解析后根据左侧符号判定用途；
  枚举变体后写 `()` 时应提示改用 `[]`；
- 语法恢复应尽量同步到 `;`、`,` 或配对的 `}`，继续报告后续独立错误。
