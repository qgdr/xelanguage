# 浅层指针降级与具体泛型实例

本章记录第 21 章迁移规则的可执行实现。编译器仍采用单文件语义检查与 C 后端，
没有引入完整模块系统、通用 Trait 分派或内存安全承诺。

## 可写指针可以降为只读

`T@[mut]` 可以在初始化、赋值、普通传参和返回时隐式转换为 `T@`。
转换复制地址、放弃当前值的写权限；原来的可写指针仍可写，指向同一对象的别名仍然合法。

```xe
fn read(pointer: i32@) -> i32 { pointer# }
fn readonly(pointer: i32@[mut]) -> i32@ { pointer }

fn main() {
    let[mut] value = 42;
    let writable = value@[mut];
    let pointer: i32@ = writable;
    let[mut] assigned: i32@ = pointer;
    assigned = writable;
    println("{} {}", read(writable), readonly(writable)#);
}
```

反向转换始终非法：`T@` 不能隐式获得 `mut`。把降级后的指针解引用，再取可写地址，
同样不能恢复写权限。`unsafe` 仅表示地址风险，不授予写权限或资源所有权。

降级只改变最外层指针，所指类型必须保持一致。组合类型的参数也保持一致：

| 来源 | 目标 | 结果 |
| --- | --- | --- |
| `i32@[mut]` | `i32@` | 允许 |
| `i32@` | `i32@[mut]` | 拒绝 |
| `i32@[mut]@[mut]` | `i32@[mut]@` | 允许，仅外层降级 |
| `i32@[mut]@` | `i32@@` | 拒绝，内层指针不同 |
| `Array[i32@[mut], 1]` | `Array[i32@, 1]` | 拒绝 |
| `i32@[mut]?` | `i32@?` | 拒绝 |
| `fn() -> i32@[mut]` | `fn() -> i32@` | 拒绝 |

Slice、元组、用户泛型类型与函数参数签名遵守相同规则。允许通过逐个读取元素，
为新组合值显式构造只读地址；不能把已有组合值整体视为另一种元素类型。
这是写权限检查的一部分，避免二级指针或容器中的地址槽位造成权限混淆。
例如 `i32@@[mut]` 可以替换外层指针所指的只读地址槽位，但 `pointer##` 仍只读。

`if` 两个继续分支分别返回 `T@[mut]` 与 `T@` 时，共同类型为 `T@`，不受分支顺序影响。
分支和上下文转换都合并 `unsafe`，不会因只读类型注解洗掉风险；局部地址逃逸仍报告 warning。

## 泛型声明与调用

未知量附在声明关键字后，具体参数附在使用名称后：

```xe
struct[T] Holder { value: T, }

fn[T] identity(value: T) -> T { value }
fn[T] wrap(value: T) -> Holder[T] {
    Holder[T] { value >> .value; }
}

fn main() {
    let number << wrap[i32](identity(42));
    let text << wrap[String](String::from("hello"));
    println("{} {}", number.value, text.value@);
}
```

直接函数调用可以从实参推导类型，也可以使用 `identity[i32](42)` 显式代入。
显式类型参数可以是指针、结果类型、函数类型或嵌套的具体用户类型。
`identity[i32@](value@[mut])` 的参数是具体的 `i32@`，因而适用上述浅层降级规则。
没有足够实参信息时需要显式代入，不从预期返回类型猜测任意实例。
已明确代入的 `identity[i32]` 可以作为 `fn(i32) -> i32` 值，也可以作为普通管道和
分支目标；未代入的函数模板不能作为普通函数值保存。

泛型实现使用 `impl[T] Holder[T]`，关联函数和方法按具体拥有者选择实例：

```xe
impl[T] Holder[T] {
    fn new(value: T) -> Self { Self { value >> .value; } }
    fn pointer(self: Self@) -> T@ { self.value@ }
}
```

`Holder[i32]::new(42)` 与 `Holder[String]::new(String::from("hello"))` 分别代入
拥有者类型。方法也可以声明自己的类型参数，使用 `object.method[Type](value)` 显式代入，
或从普通实参推导。普通管道和分支目标中的裸泛型函数从传入载荷推导实例。

`Holder[i32]` 与 `Holder[String]` 是不同的具体类型，有各自的字段布局。
泛型枚举同样按具体类型生成载荷布局，支持构造、单层匹配和资源清理。
省略构造名称上的类型附件时，必须已有完整上下文，例如
`let event: Event[i32] << Event::Value[42];`；没有上下文时写 `Event[i32]::Value[42]`。
结构体构造遵守相同规则，不从载荷/字段反向猜出任意泛型类型。
字段转送 `value >> .value;` 在具体实例中按 Copy 资格决定复制还是移动。
用户类型没有显式 Copy 承诺就不能复制，`Holder[i32]` 不因字段为整数自动变成 Copy。

目前支持 `Copy` 泛型约束，如 `fn[T: Copy] duplicate(value: T) -> tuple[T, T]`。
对不满足约束的资源实参给出所有权错误。泛型类型的条件 Copy 实现和自定义泛型 Drop
尚未支持，报告 `XE-SEM-0001` 能力诊断；泛型实例中的资源字段和枚举载荷仍会正常自动析构。

## 实例化与后端

语义检查器保存模板，并为实际使用的具体参数组合建立实例缓存。
每个实例拥有单独复制、代入后的函数体，再执行普通类型、写权限和所有权检查。
原始 AST 保留用户源码结构，隐藏实例和调用目标保存在语义侧表中。
因此 `T = i32` 的合法操作不能替代 `T = String` 的重新检查。
未使用模板的函数体延迟到具体实例使用时检查，不会提前证明它适用于所有类型。
实例正文错误仍指向原始源码，提示中补充具体代入类型和首次使用位置。

缓存键使用模板及具体类型，`unsafe` 不参与实例身份。地址风险由每次调用的数据流传播，
不能由第一次危险地址调用污染后续安全调用，也不能因复用实例丢失当前调用的风险。
普通递归复用既有实例；不断增加类型层数的递归受实例数量限制，默认最多 256 个，
类型参数嵌套深度最多 64 层；超出任一限制时给出 `XE-GENERIC-0002`，提示检查递归代入。

C 后端使用已检查的具体调用目标，只生成实际实例，不输出未代入的模板函数。
具体结构体、枚举和相关组合类型按完整类型缓存布局，资源清理沿用普通后端路径。
方法与关联调用也必须绑定具体拥有者和代入参数，不能按类型族名称误用其他实例的方法。
指针指向的递归实例只需 C 前置声明，不强行展开无限布局；按值递归仍给出明确源码错误。

当前仍未完成：模块加载、通用 Trait 约束与分派、命名区域求解、动态闭包/公共 Call Trait、
泛型类型的条件 Copy 与自定义 Drop。解析某个声明成功不代表上述能力已可执行。

## 验收与维护

```sh
make run SOURCE=tests/stage999/generic_holder.xe
make run SOURCE=tests/backend/generic_instances.xe
uv run --frozen --offline python -m unittest compiler.tests.test_pointer_weakening
make compiler-test
```

`test_pointer_weakening.py` 覆盖单向降级、两种分支顺序、嵌套不变性、二级只读权限、
unsafe 与局部地址 warning，并通过 C 编译器和 ASan/UBSan 执行正常地址例。
`test_generic_parser.py` 覆盖类型附件与普通索引边界；泛型后端和跨阶段测试分别检查
具体实例运行、布局与资源清理，以及类型附件、所有权、缓存和风险传播之间的关系。
风险示例只检查或编译，不执行已知悬垂地址。

修改泛型规则时，应同时验证 Copy 和资源代入；修改指针规则时，应同时验证最外层
转换成功与嵌套转换失败。任何新能力都需经过语义、C 生成、系统编译及实际行为验收，
不能只以输出了 C 文本作为完成依据。
