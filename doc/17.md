# Bootstrap Syntax 0.2：冻结范围

状态：**冻结（FROZEN）**。标识：`xe-bootstrap-0.2`。
本章是第一版新编译器的契约；冻结的是语法形状及其 AST 含义，不代表类型检查或后端已实现。
变更冻结项必须更新版本、文档、成功/失败测试及迁移说明，不静默改变旧代码含义。

## 0.2 迁移与泛型附件（FROZEN）

具名函数和具名方法统一写 `fn[T: Measure] inspect(value: T@) -> i32 { ... }`。
无约束写 `fn[T] identity(value: T) -> T { value }`。泛型附件属于 fn，
不再属于函数名；0.1 的 `fn identity[T](...)` 报迁移提示，不自动兼容。
复杂约束保留 `where T implements Trait`，可与内联约束组合。
每个参数内联一个 Trait 约束；多个约束可使用 where 的多个条目。

具名声明的 fn[...] 是泛型，匿名表达式的 fn[...] 只表示捕获：
`fn[base](x: i32) -> i32 { base + x }`。首版不支持闭包声明独立泛型，
但闭包可以使用外层已经声明的类型参数；后者不意味着同一个闭包能接受任意类型。
函数类型仍写 `fn(i32) -> i32`，不接受泛型/捕获附件。
struct/enum/trait 的泛型仍跟在类型名后，impl 的泛型仍跟在 impl 后。

泛型附件内 `T: Trait` 是类型参数能力约束；参数/变量/字段处 `value: Type`
是值的类型标注。上下文确定含义，不靠名字大小写或类型推导猜测。
AST 中内联约束归一保存为已有 TraitConstraint；JSON schema_version 保持 1，
syntax_version 更新到 xe-bootstrap-0.2。通用 Trait 语义仍不因语法冻结而自动实现。

## 已冻结的前端规则

| 范围 | 状态 | 固定规则 |
| --- | --- | --- |
| 名称、字面量、注释 | FROZEN | UTF-8；:: 路径；整数/浮点/字符串/字符/字节；嵌套块注释 |
| 绑定与值传递 | FROZEN | let / var；名称: 类型；= / <<；独立源 >> 目标语句 |
| 函数与复合声明 | FROZEN | fn / struct / enum / trait / impl / extern；参数类型、泛型附件、where |
| 类型语法 | FROZEN | 后置 @ / ?；[] 泛型/修饰；元组和 fn 参数类型；数组长度可为整数常量 |
| 表达式优先级 | FROZEN | 第 02 章表；比较链单独建节点；普通 ? 低于管道，?[return] 为后置 |
| 块与控制流 | FROZEN | 普通语句用 ;；块尾返回值；块控制语句可省略尾分号；if / while / for |
| 普通管道 | FROZEN | |> 后只能是函数目标、参数绑定、fn 或括号包裹的函数值表达式 |
| 分支管道 | FROZEN | 数字 1> / 2>；模式 :>；参数绑定不产生函数值，不使用负载占位符 |
| 模式选择器 | FROZEN | 选择不绑定；字面量/变体/元组/_/组合；变量只在处理参数位置声明 |
| 共享匹配 | FROZEN | ?[@]；普通负载为指针，包括标量；类型注解不改变输入表示 |
| 匿名函数外形 | FROZEN | fn[captures](parameters) -> Type { body }；捕获附件是可选的 |
| 导入语法 | FROZEN | use 路径 / 分组导入 / as 别名；无 * 导入 |
| AST JSON | FROZEN v1 | schema_version、syntax_version、source、ast；节点 kind 及半开源码 span |

名称解析前，表达式中的 [] 统一保留为 BracketApply，随后判断枚举负载、索引或泛型应用；
不能用大写字母猜测类型。AST 不插入隐式借用、成功包装或 Drop；后续有类型阶段执行这些规则。

## 语法保留、语义暂缓（RESERVED）

- @[mut] / 区域、?[@[mut]]：前端保留结构；借用区域算法与视图负载的可写限制后续实现。
- fn[...] 捕获闭包：前端区分捕获与参数绑定；拥有捕获的单次消费协议仍为 PROVISIONAL。
  无捕获匿名函数的语法已冻结；闭包存储布局、多次调用、共同类型不冻结。
- str / Slice 的复制视图例外、资源 Drop 抽取限制：保持当前方向，交由类型/所有权阶段验收。
- T? / T?[E] 结果布局及返回简写：类型语法已冻结，转换与布局不是 AST 解析职责。
- 按路径加载包、xe.toml、构建图检查模式：接口方向保留，第一步只解析单文件，不递归加载依赖。

线程、异步、动态闭包、结构体深层绑定和模式守卫属于 DEFERRED，不加入冻结核心。
旧 match、=>、模式 >、1> foo(_) 和直接的 2> 0 不属于冻结语法，应给清晰诊断。

## 阶段边界

make ast 只回答“源码结构是否符合冻结语法”，不回答“名字存在吗、类型正确吗、资源是否移动”。
tests/fails 中的语义错误程序可能正常生成 AST，这是正确现象，不能称其语义检查通过。
新解析测试单独维护，固定 AST 形状、优先级、位置、诊断、CLI 和目标样例覆盖。

单文件语义检查现已通过 make check / make check-borrows 提供；实际支持范围及保守边界见
[第 18 章](18.md)。RESERVED 表示尚未完全固定或实现的契约，不代表其中每条都没有任何检查。
