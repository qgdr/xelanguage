# Xe 1.0：冻结语法范围

状态：**冻结（FROZEN）**。当前标识：`xe-1.0`；编译器候选版：`1.0.0-rc.1`。
本章是第一版新编译器的契约；冻结的是语法形状及其 AST 含义，不代表类型检查或后端已实现。
变更冻结项必须更新版本、文档、成功/失败测试及迁移说明，不静默改变旧代码含义。

本次从历史标识 `xe-bootstrap-0.9` 归档到 `xe-1.0`，不重新解释已经批准的符号。
JSON 信封仍是 schema 1；消费者须识别新的 syntax_version。以下 0.x 小节保留迁移历史。
**1.0 的可执行支持范围以 [发布契约](../RELEASE.md) 为准**；冻结 AST 外形不等于
所有目标语法已经能够生成程序。运行期 `unsafe {...}` 不是普通指针的权限门禁，
旧块目前在检查阶段明确拒绝；风险附件仍写在 `T@[unsafe]` 上。

## 0.9 迁移：tuple 与透明类型别名（FROZEN）

- 元组类型统一写 `tuple[A, B]`，元组值写 `tuple[a, b]`；单元素写 `tuple[T]` / `tuple[value]`。
  旧花括号元组被拒绝并给出迁移提示；代码块、结构体字面量、枚举和分支正文继续使用花括号。
- `let tuple[a, b] = expression;` 创建新的解包绑定；不可复制源使用 `<<`。
  支持 `let[mut] tuple[a: A, b: B] ...`，声明附件不改变成员类型或复制能力。
- `tuple[a, b] = expression;` / `tuple[a, b] << expression;` 写入已有变量。
  `expression >> tuple[a, b];` 保留通用转送；右侧只求值一次，成员按位置转交。
- 解包中的 `_` 不创建变量，忽略的拥有资源仍会自动 drop；不增加递归绑定模式或空元组。
  `tuple[]` 不属于本轮冻结语法，没有内容的值仍使用 `unit: Unit`。
- 顶层 `type Name = Type;` 声明透明类型别名，可指向函数类型、元组或具体用户类型。
  支持前向引用与别名链；循环别名、未知目标和重复名称应给出定位诊断。
  不增加泛型别名语法、局部别名或新的名义类型身份，别名不会增加 Copy 或写权限。
- `tuple` 与 `type` 是关键字；过去名为 tuple 的函数等普通声明需要更名。

语义和运行边界见 [第 23 章](23.md)；`=` / `<<` / `>>` 的既有含义保持不变。

## 0.8 迁移：普通指针、显式 Copy 与泛型声明（FROZEN）

- T@ 是只读普通指针，T@[mut] 是可写普通指针；两者都 Copy，允许别名和重复传参。
  可写不意味着独占，不再要求再次借用，不再宣称内存安全。
- unsafe 是跟着地址传播的风险注记，不是语句块门禁。能够识别的悬垂、失效等风险给
  warning 并标注推导类型，但仍可编译；类型、写权限和资源所有权错误仍拒绝。
- 用户结构体和枚举必须显式 impl Copy；不再自动实现基本值结构体 Copy。
- 具名声明统一写 struct[T] Holder、enum[T] Event、trait[T] Convert、fn[T] wrap。
  使用仍写 `Holder[i32]`、`wrap[i32](10)`：前者声明未知量，后者代入具体值，理由见第 21 章。
- 结构体字段允许 value >> .field;，按类型复制或移动，适用于未知泛型 T。
- 每个 ? 只消解当前一层枚举；不支持递归变体选择器，需要显式再写一次 ?。
- 有捕获闭包已按第 15 章重新审核并实现；采用普通指针和方法式接收者，不冻结动态闭包协议。

## 沿用 0.7：转换与复制/移动边界（FROZEN）

- `=` 只复制，`<<` 只转移不可复制的值，Copy 值使用 << 会得到迁移提示。
- `>>` 按用户约定保留通用值传递，Copy 值复制、资源移动；不是 << 的严格反向操作。
- `as T` 仅无损转换。撤回未获确认的 as[checked]/as[wrap] 草案，使用整数 `T::try_from(value)`。
- `?[panic]` 是明确的失败终止操作；成功返回负载，失败不承诺执行 Drop。
- `None` 只在结果类型/结果值上下文中使用，不是可以独立声明的普通类型或值。

## 沿用 0.6 的类型组合（FROZEN）

- () 允许类型分组；当前元组值/类型遵循上面的 0.9 tuple[...] 迁移。
  空 {} 保留为空块。
- RawPtr 删除，指针统一为 T@；unsafe 不改变 ABI、写权限或资源所有权。
- str@ 合法，借用匹配的视图负载统一成为 T@ / T@[mut]，删除旧视图复制例外。
- 可变性和所有权检查始终开启，旧检查旗标只为兼容；指针风险单独 warning。
- str 复制地址和长度；用户结构体 Copy 规则采用上面的 0.8 迁移。
- 捕获闭包的具体布局、读/写/一次性调用与资源清理已接入 C 后端，规则见第 15 章。

## 沿用的参数规则（FROZEN）

公开局部声明统一为 let / let[mut]；函数参数只写 name: Type。
参数绑定只读；局部重新赋值在函数体使用 let[mut] name = name;，
资源转交使用 <<。修改调用者对象仍使用 name: T@[mut]，不改变参数绑定。
0.3 的 let[mut] 参数前缀、0.4 的 name[mut] 附件以及参数前缀 var 均被拒绝并提示迁移。
匿名函数及内联处理参数遵守相同规则；处理参数允许省略类型或使用 _。
var 保留为 let[mut] 的隐藏别名。声明附件只允许单个 mut。
--check-safety / --check-borrows 为兼容旗标，当前无关闭检查的入口。
类型、初始化、Copy/移动、析构和可变性始终验证；未知附件仍拒绝。风险注记不代替这些检查。
JSON schema_version 仍为 1；当前 syntax_version 为 xe-1.0。
Parameter.mutable 字段保留但固定为 false，避免破坏 AST JSON 结构。

## 沿用 0.2 的泛型附件（FROZEN）

具名函数和具名方法统一写 `fn[T: Measure] inspect(value: T@) -> i32 { ... }`。
无约束写 `fn[T] identity(value: T) -> T { value }`。泛型附件属于 fn，
不再属于函数名；0.1 的 `fn identity[T](...)` 报迁移提示，不自动兼容。
复杂约束保留 `where T implements Trait`，可与内联约束组合。
每个参数内联一个 Trait 约束；多个约束可使用 where 的多个条目。

具名声明的 fn[...] 是泛型，匿名表达式的 fn[...] 只表示捕获：
`fn[base](x: i32) -> i32 { base + x }`。首版不支持闭包声明独立泛型，
但闭包可以使用外层已经声明的类型参数；后者不意味着同一个闭包能接受任意类型。
函数类型仍写 `fn(i32) -> i32`，不接受泛型/捕获附件。
struct/enum/trait 的泛型统一跟在关键字后，impl 的泛型仍跟在 impl 后。
具体类型和函数的应用附件跟在名称后，不使用 <>。

泛型附件内 `T: Trait` 是类型参数能力约束；参数/变量/字段处 `value: Type`
是值的类型标注。上下文确定含义，不靠名字大小写或类型推导猜测。
AST 中内联约束归一保存为已有 TraitConstraint；JSON schema_version 保持 1，
当前 syntax_version 为 xe-1.0。静态 Trait 的实际范围见第 35 章；
动态 Trait 等目标能力仍不因语法冻结而自动实现。

## 已冻结的前端规则

| 范围 | 状态 | 固定规则 |
| --- | --- | --- |
| 名称、字面量、注释 | FROZEN | UTF-8；:: 路径；整数/浮点/字符串/字符/字节；嵌套块注释 |
| 绑定与值传递 | FROZEN | let / let[mut]；名称: 类型；tuple 解包声明/赋值；= / <<；源 >> 目标，也可用于字段初始化 |
| 函数与复合声明 | FROZEN | fn / struct / enum / trait / impl / extern / type；参数类型、泛型附件、where；透明类型别名 |
| 类型语法 | FROZEN | 后置 @ / ?；[] 泛型/修饰；tuple[...] 与 fn 参数类型；当前数组长度为非负整数字面量 |
| 表达式优先级 | FROZEN | 第 02 章表；比较链单独建节点；普通 ? 低于管道，?[return]/?[panic] 为后置 |
| 块与控制流 | FROZEN | 普通语句用 ;；块尾返回值；块控制语句可省略尾分号；if / while / for |
| 普通管道 | FROZEN | |> 后只能是函数目标、参数绑定、fn 或括号包裹的函数值表达式 |
| 分支管道 | FROZEN | 数字 1> / 2>；模式 :>；参数绑定不产生函数值，不使用负载占位符 |
| 模式选择器 | FROZEN | 选择不绑定；字面量/单层变体/元组/_/组合；不递归展开；变量只在处理参数位置声明 |
| 共享匹配 | FROZEN | ?[@]；普通负载为指针，包括标量；类型注解不改变输入表示 |
| 匿名函数外形 | FROZEN | `fn[captures](parameters) -> Type { body }`；捕获附件是可选的 |
| 导入语法 | FROZEN | use 路径 / 分组导入 / as 别名；无 * 导入 |
| AST JSON | FROZEN v1 | schema_version、syntax_version、source、ast；节点 kind 及半开源码 span |

名称解析前，表达式中的 [] 统一保留为 BracketApply，随后判断枚举负载、索引或泛型应用；
不能用大写字母猜测类型。AST 不插入隐式借用、成功包装或 Drop；后续有类型阶段执行这些规则。

## 尚未实现的预留能力（RESERVED）

- 命名区域附件为历史/预留能力，不作为普通指针的强制安全条件；可写权限仍验证。
- 注册表/锁文件/模块级增量构建仍保留为后续接口，不把清单中的示例当成已支持。

## 已实现语义与库接口的边界

以下是已批准规则的实现状态，不归入 RESERVED；它们仍只承诺所引用章节列出的具体范围。

- fn[...] 显式捕获、默认 f() 方法式接收者和具体环境布局已实现，见第 15 章。
  读/写调用保留环境，移出捕获资源才消耗环境；动态共同类型仍暂缓。
- 资源 Drop 抽取限制保持当前方向，交由类型/所有权阶段验收；视图不再有借用复制例外。
- T? / T?[E] 结果布局及返回简写：类型语法已冻结，转换与布局不是 AST 解析职责。
- 按路径加载本地模块和 xe.toml 的 path 依赖已实现，见第 27 章；
  AST 阶段仍只解析单文件，模块加载发生在检查和后端阶段。

异步、yield 暂停恢复、动态闭包、结构体深层绑定和模式守卫属于 DEFERRED，不加入冻结核心。
next(self: Self@[mut]) -> Step[T] 迭代协议及 std::iter::from_fn 是已实现库/语义接口，
不改变 0.9 AST 语法版本，详细边界见第 26 章。
用户已确认第 09 章的 pub 可见性规则及第 28 章 Box 拥有堆对象接口。
pub 写在声明、字段、方法或 use 前；不新增可见性范围附件。
Array/Vec 下标访问的类型为 T，只有显式 @ 才变成 T@；不是隐式借用转换。
Box 始终不可 Copy，不自动解引用，new 返回可处理的分配结果，into_value 消耗拥有者。
这些接口沿用已冻结语法，不改变 AST 版本。
模块级 let / let[mut] 的只读/可写静态存储现已按用户要求实现，沿用声明/指针修饰，不增加关键字；
当前要求显式类型与静态 Copy 初值，原版支持 Copy 聚合、函数值及全局地址，自举子集
仅支持 Copy 字面量。Python stage0 还支持静态标量运算；只读模块 let 可取址，
不可取得可写指针。Constant 仅为兼容 AST 名称。全局资源、动态初始化/退出清理
暂未规定。完整边界见第 01 章。

已确认并实现单词位运算 `bitand` / `bitor` / `bitxor` / `bitnot` / `bitshl` / `bitshr`，
仅用于整数，位宽不变。移位检查次数和左移溢出，不静默截断或对次数取模。
优先级见第 02 章；不复用所有权 `<<` / `>>` 作移位，也没有增加传统符号位运算。
Shared/Weak、Mutex/MutexGuard 和 Thread 的库契约已另行确认并实现，见第 29 章；
明确 share 增加拥有者，弱升级返回 Expired，Guard 不跨线程，Thread 析构自动等待。
不新增公开 Send/Sync Trait 或独占借用规则，也不宣称数据竞争静态证明。
旧 match、=>、模式 >、1> foo(_) 和直接的 2> 0 不属于冻结语法，应给清晰诊断。

## 阶段边界

make ast 只回答“源码结构是否符合冻结语法”，不回答“名字存在吗、类型正确吗、资源是否移动”。
tests/fails 中的语义错误程序可能正常生成 AST，这是正确现象，不能称其语义检查通过。
新解析测试单独维护，固定 AST 形状、优先级、位置、诊断、CLI 和目标样例覆盖。

语义检查现已通过 make check / make check-safety 提供，并递归加载可达模块；实际支持范围及保守边界见
[第 18 章](18.md)。RESERVED 表示尚未完全固定或实现的契约，不代表其中每条都没有任何检查。
