# 单词位运算

状态：已确认并实现。作用对象是整数，不是布尔值、指针或资源。

| 表达式 | 含义 | 结果类型 |
| --- | --- | --- |
| `left bitand right` | 对应位均为 1 时结果位为 1 | 两侧相同整数类型 |
| `left bitor right` | 对应位至少一个为 1 时结果位为 1 | 两侧相同整数类型 |
| `left bitxor right` | 对应位不同时结果位为 1 | 两侧相同整数类型 |
| `bitnot value` | 在该整数位宽内逐位翻转 | value 的整数类型 |
| `value bitshl count` | 向左移动，检查结果溢出 | value 的整数类型 |
| `value bitshr count` | 向右移动，无符号补 0，有符号补符号位 | value 的整数类型 |

```xe
let READ: u8 = 0b0000_0001;
let WRITE: u8 = 0b0000_0010;

fn main() {
    let[mut] flags: u8 = READ;
    flags = flags bitor WRITE;          // 0000_0011：打开 WRITE 位
    println("{}", flags bitand WRITE != 0); // true：检测 WRITE 位
    flags = flags bitand bitnot WRITE;  // 0000_0001：关闭 WRITE 位
    println("{}", flags);              // 1
}
```

位运算不自动扩宽或把整数转换为布尔值。例如 `let all: u8 = bitnot 0;` 为 255，
`let all: i8 = bitnot 0;` 为 -1。字面量按上下文确定类型；没有上下文时默认为 i32。
`bitnot 256` 不能作为 u8：先检查输入能否表示，不能借取反偷偷截断。
当前支持平台的有符号整数使用二进制补码，`bitnot` 不属于算术溢出。

优先级从高到低为：后置调用/索引/地址等、前缀 `bitnot`、转换、乘除余、加减、
移位、`bitand`、`bitxor`、`bitor`、比较、`and`、`or`。所以 `flags bitand mask != 0` 等价于
`(flags bitand mask) != 0`。二元操作从左到右求值，各操作数只计算一次；位运算不短路。
完整排序见 [第 02 章](02.md)。

只读/可写模块绑定的静态初值都可以使用这些运算。Python stage0 检查、生成 C 并运行；
Xe 自举子集也支持函数内的这些运算，但其模块初值仍只接受 Copy 字面量。

移位次数可以是任意整数类型，不隐式改动其类型；要求 `0 <= count < value 的位宽`。
已知的非法次数或左移结果报编译错误，运行时才知道的情况会 panic。
左移不截断高位：`let byte: u8 = 128 bitshl 1;` 是错误，而不是得到 0。
允许范围内的负数左移，例如 `let min: i8 = -1 bitshl 7;` 为 -128。
有符号右移保留符号位，因此 `-3 bitshr 1` 为 -2，而不是整数除法 `-3 / 2` 的 -1。
后端显式实现这个规则，不依赖 C 负数移位的实现定义行为或有符号左移未定义行为。

不提供 `&` / `|` / `^` / `~` 作为位运算表达式。`|` 仍只用于已有组合模式，`<<` / `>>`
仍只用于所有权传递。volatile、布局/对齐和裸机接口尚未冻结，不能据此
宣称目前已覆盖嵌入式平台。可执行示例见 [word_bits.xe](../tests/language/word_bits.xe)。
