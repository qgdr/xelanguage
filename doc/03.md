# 所有权、普通指针与风险提示

`T@` 是普通指针，不是 Rust 式引用。Xe 允许地址别名和底层操作，不宣称内存安全。
指针模型与资源所有权模型分开：复制地址不会复制或取得地址处资源的所有权。

## Copy 与移动类型

`=` 只复制 `Copy` 值；`<<` 只转移不可复制值；`>>` 根据 Copy 资格复制或移动。
基础标量与指针可复制。用户定义的结构体、枚举不自动 Copy，必须显式声明
`impl Copy for Type;`，并满足第 08 章列出的条件。

```xe
let first: String << String::from("hello");
let second: String << first;
println("{}", first); // 错误：first 已移动，不是指针风险 warning。
```

需要两个独立资源时显式克隆：

```xe
let first: String << String::from("hello");
let second: String << first.clone();
```

## 取地址、读写与复制指针

基本对应关系可以直接推导：`a: T` 则 `a@: T@`；`p: T@` 则 `p#: T`；
`p@: T@@` 是指针变量自身的地址，不是所指对象的地址。

`T@` 是只读指针；`T@[mut]` 是可写指针。两者都 Copy，都可以存在别名。
`mut` 表示写权限，不表示独占，也不表示延长对象存活时间。

```xe
fn increase(pointer: i32@[mut]) { pointer# = pointer# + 1; }

fn main() {
    let[mut] count: i32 = 0;
    let read: i32@ = count@;
    let write: i32@[mut] = count@[mut];
    increase(write);
    increase(write); // 合法：每次复制地址，不移动指针，不要求“再次借用”。
    println("{}", read#); // 2；read 与 write 可以指向同一个对象。
}
```

只有可写的存储位置才能产生 `@[mut]`。`let` 绑定不可重绑，`let[mut]` 可重绑；
参数绑定不可重绑，但 `pointer: T@[mut]` 仍可修改所指对象。只读指针不能写所指对象，
也不隐式转换为可写指针。可写性、类型和所有权错误仍是编译错误，不降级为 warning。

## unsafe 跟着指针走

显式标注危险来源或使用约定：

```xe
let pointer: u8@[unsafe] = view.data();
let writable: i32@[mut, unsafe] = count@[mut, unsafe];
```

`unsafe` 是指针的风险注记。它不改变布局和调用 ABI，不增加写权限、不取得所有权，
也不自动插入运行时保护。修饰项顺序不影响含义；未知或重复项仍报错。
危险指针经赋值、函数返回和复合值传播时，风险不能因目标省略 `[unsafe]` 而被抹去。
“类型相容”与“风险信息相同”是两件事。

编译器对能够识别的风险自动附加 `unsafe`，给出 warning，但仍允许生成可执行文件：

- `XE-PTR-0001`：局部对象的地址或视图逃逸，返回时对象可能已经结束生命周期；
- `XE-PTR-0002`：对象移动、析构或缓冲区失效后，已有指针可能失效；
- `XE-PTR-0003`：临时对象或其他不能证明有效性的来源。

```xe
fn dangling() -> i32@ {
    let local: i32 = 42;
    local@ // warning：返回局部地址；推导结果附带 unsafe，仍可编译。
}
```

这个例子不能作为正常运行测试：解引用结果可能产生未定义行为。
warning 表示需要程序员审查，不意味着“程序会崩溃”，也不意味着编译器发现了所有风险。
没有 warning 不是内存安全证明。外部地址、间接释放、别名写入、复杂控制流和并发尤其
需要调用者遵守契约；自动风险分析允许保守和不完整，不能伪装成完整证明。

Xe 不以 `unsafe { ... }` 作为解除检查的语句门禁。外部 ABI、地址整数构造指针、
分配和释放接口仍需要独立实现；风险注记不代表这些接口已完成。
不再定义 RawPtr；普通指针统一写 `T@`。

## 解引用、方法与格式化

`pointer#` 访问所指对象。对 `pointer: T@`，`pointer.field` 和 `pointer[index]`
允许在字段/索引位置自动越过最外层指针；它们仍访问原对象，不取得对象的所有权。
这不意味着任意表达式、普通函数参数或按值方法接收者都能自动解引用。

方法调用按声明的 `self` 类型决定如何传递接收者：值可以为 `self: Self@` / `Self@[mut]`
自动取地址；已有指针可以直接传给权限相容的指针接收者。若 `self: Self`
要求取得所指非 Copy 资源的所有权，则 `pointer.method()` 必须报错；
普通指针不能把自己不拥有的资源交给方法。Copy 值的按值方法只复制值，
不构成资源所有权转移；具体接收者写法见第 07 章。

```xe
pointer.method(); // 指针接收者方法可调用；消耗所指非 Copy 资源的方法不可调用。
```

普通函数参数不会偷偷取地址；格式化也不例外：

```xe
println("value = {}", value@);      // 显式传递地址，保留拥有值。
println("address = {:p}", value@); // 选择指针地址格式。
// let address: usize = pointer.addr(); // 地址 API 预留，当前语义检查和后端均未支持。
```

`str@` 指向“地址 + 长度”的视图描述符，`.data()` 返回底层字节指针。
两者分别满足 `text@: str@`、`text.data(): u8@`，不能混为一谈。

## 非拥有指针不能转送资源所有权

`a_ptr: T@` 或 `T@[mut]` 不拥有 `T`。即使可写或带 unsafe，也不能把非 Copy 的
`a_ptr#` 或其资源字段移给函数、返回值、管道、枚举负载或变量：

```xe
fn consume(text: String) { println("{}", text); }

fn inspect(a_ptr: String@) {
    consume(a_ptr#);     // 错误：指针没有 String 的所有权。
    println("{}", a_ptr); // 正确：传递地址，不取走 String。
    consume(a_ptr.clone()); // 正确：创建新的拥有值。
}
```

可以复制所指的 Copy 值：`fn read(p: i32@) -> i32 { p# }`。
可写指针可以原位修改、用新资源替换并析构旧资源；当前未设计返回旧资源的通用 take 接口。
资源变量仍在作用域退出时自动 drop；指针既不释放所指对象，也不延长它的生命周期。

## 当前工具边界

`make ast` 只解析语法。`make check` 检查类型、初始化、Copy、移动、写权限，并报告
可识别的指针风险。原始 AST JSON 保留源码语法，不修改用户写出的类型；推导的 unsafe
属于语义阶段信息。`--check-safety` / `--check-borrows` 仅保留兼容名字，不启用独占借用模型。

命名区域不再是普通指针的强制安全条件。已有区域附件属于历史/预留能力，不把未完成的
区域求解器作为普通指针必须通过的安全门禁。长期关系仍推荐 NodeId、TypeId 和 Arena，
因为这通常比依赖悬垂风险更容易维护，而不是因为语言禁止指针。
