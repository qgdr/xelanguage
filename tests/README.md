# 测试目录

- `stage01` 至 `stage04` 保存早期宿主编译器的历史阶段样例；旁边的 `.ast.json`、`.ll` 和
  `.out` 是旧实验生成物，不是目标规范。
- `stage903`、`stage904` 保存块表达式、可变绑定、借用和控制流设计样例。
- `stage999` 保存完整目标语法样例，新的编译器按功能逐步让这些样例通过。
- `fails` 中的程序必须编译失败；测试工具还要校验错误代码、源码范围和关键提示文字。
- `warnings` 中的风险程序应 warning 但仍可编译；不能统一执行可能悬垂的指针程序。
- `backend` 保存实际 C 执行的现代示例，tuples.xe/type_aliases.xe 展示 0.9 元组解包与透明类型别名。

实现一个功能时，应同时增加：

1. 正常成功样例；
2. 边界样例；
3. 至少一个失败样例；
4. 面向使用者的诊断快照。

## 指针模式与目标语法测试

公开示例使用 let / let[mut]；var 只保留为编译器内部兼容别名。
当前元组类型/值统一为 tuple[...]；旧花括号元组要收到迁移提示，不能误当成合法代码块。
let tuple[...] 创建变量，无 let 的目标写入已有变量；Copy 与资源仍使用不同的 = / <<。
两种可变写法的 AST、语义与执行等价性由 compiler/tests/test_binding_modifiers.py 验证。

当前所有语义及后端动作均检查类型、所有权和写权限；旧旗标为兼容别名。
stage999/pointer_unchecked.xe 保留历史文件名，内容已迁移为明确的可写普通指针。
资源盗取和只读写入必须失败；指针别名合法，悬垂风险 warning 但仍可编译。
当前编译器通过 make check / make check-safety 验证这些语义；make ast 只验证语法。
不可把解析失败当作正确的所有权诊断。旧编译器已删除，历史阶段样例仍保留用于参考，
不要求它们符合当前冻结语法。
